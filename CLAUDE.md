# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What is CaveWhere

CaveWhere is a Qt 6 / C++ desktop application for cave mapping and 3D visualization. It features 2D-to-3D survey morphing, loop closure detection, Git-based project sync, and LiDAR note processing.

## Build Commands

From a fresh checkout:
```bash
git submodule update --init --recursive
conan profile detect --force
conan install . --build=missing -of conan_deps
cmake --preset conan-release -DCMAKE_TOOLCHAIN_FILE=conan_deps/conan_toolchain.cmake
cmake --build build/<preset> --target all
```

Requires **Qt 6.11+**.

The build directory name (`build/<preset>`) is generated by CMake from the Qt version and platform, e.g. `build/Qt_6_11_0_for_macOS-Debug`. Use `ls build/` to find the correct name.

Run the application: `./build/<preset>/CaveWhere`

Build and run tests:
```bash
cmake --build build/<preset> --target cavewhere-test cavewhere-qml-test
./build/<preset>/cavewhere-test -d yes 2>&1 | tee /tmp/cavewhere-test-$$.log
./build/<preset>/cavewhere-qml-test --platform offscreen 2>&1 | tee /tmp/cavewhere-qml-test-$$.log
```

Always redirect test output to a log file so failures can be inspected without re-running. Keep `$$` (the shell PID) in the log name: sibling checkouts and the nightly runner write to `/tmp` too, and a fixed path lets one run silently clobber another's log — producing a mixed-up log whose failures belong to a different working tree. Run a single C++ test with Catch2 tags (`cavewhere-test "[TagName]"`); run a single QML test with `cavewhere-qml-test --platform offscreen -input test-qml/tst_YourTest.qml`. Always run both suites before pushing.

### Flaky tests

Run the suites through `scripts/flaky/flaky.py`. It keeps one ledger, `~/.cavewhere/flaky.sqlite`, shared by every checkout, every session, and the nightly runner:

```bash
scripts/flaky/flaky.py run --build build/<preset>                                  # both suites
scripts/flaky/flaky.py run cpp --build build/<preset> -- "[TagName]"
scripts/flaky/flaky.py run qml --build build/<preset> -- -input test-qml/tst_YourTest.qml
```

It reruns each failing test alone five times and labels it **FLAKY** (a rerun passed), **BROKEN** (every rerun failed), or **UNVERIFIED** (it could not be rerun alone). A test the suite timeout cut off is **INTERRUPTED** and is left out of flake counts. It exits 0 only when every test ran and every failure was flaky. Treat BROKEN, UNVERIFIED, and an INCOMPLETE suite (a crash or timeout left tests unrun) as real failures. A FLAKY result marked as the test's first flake on a tree with uncommitted changes may come from your change, so check before setting it aside. A full run plus reruns can outlast the 10-minute Bash limit; run it in the background.

Let the script do the reruns. If you already reran a failure by hand, log it: `flaky.py record --suite cpp --test "<name>" --reruns N --rerun-failures M`. Before fixing a failing test, `flaky.py show "<name>"` lists its history (seed, load, ASAN, other suites running, kept logs). `flaky.py report` ranks flakes by frequency. `flaky.py promote "<name>"` drafts a GitHub issue labeled `flaky-test`; `--post` sends it, and only the owner runs that or approves it.

## Architecture Overview

`main.cpp` exposes `cwRootData` as a QML singleton — the hub owning every major subsystem, and the place to start when looking for one.

Data model: `cwCavingRegion` → `cwSurveyNode` tree (`cwCave` is a thin node subclass; nested nodes live under `sub/`) → `cwTrip` → `cwSurveyChunk` → `cwShot` (+ splays) and `cwNote` (2D scan) → `cwScrap` (digitized outlines). Walk with `rootNode()->allNodes()` / `allTrips()`; `region->caves()` is only the root's children and `cave->trips()` only a node's direct trips. Post-solve station naming is `cwScopeLabels::resolve` + `cwTrip::scopePrefix` only.

**Persistence (`cwProject`)**: three formats — legacy `.cw` (JSON + SQLite, auto-converted on load), bundled `.cw` (zip, the default for single-file saves), and `.cwproj` directory (Git-backed, for collaboration). Serialization is Protocol Buffers (`cavewhere.proto`). Save/load is queued through `cwSaveLoad` so it never blocks the UI thread.

**Rendering**: Qt RHI, never OpenGL directly (`cwRhiScene`, `cwRhiItemRenderer`); 3D math lives in the `QMath3d` submodule.

**Import/export**: Compass, Survex, and Walls parsing goes through the `dewalls` submodule. Compass station names are exported uppercase — Compass is case-sensitive, CaveWhere is not. `cwSurveyNetwork` performs loop closure detection.

**Solve and georeferencing**: `cwSurvexExporter` writes Survex from `cwTripData` snapshots, with splays, each fix in its own CS via `cwSurvexCS`, `*declination auto` once per located node, and a fallback `*fix` on an unfixed block only when no written tie joins it to an anchored one. Pipelines are `cwUpdatable`s driven by `cwUpdateCoordinator`: mark one as needing an update, then run it (there is no `rerunSurvex`). `cwGeoReference` + `cwLocalProjectionManager` hold the project's local frame, which is stored and read back on load as is; `cwFixStationValidator` checks fixes against it, and per-fix diagnostics live on `cwSurveyNode::fixStationDiagnostics`.

**UI**: `cwPageSelectionModel` routes pages; `cwKeywordItemModel` / `cwKeywordFilterPipelineModel` drive hierarchical keyword search.

## Coding Conventions

- **Comment sparingly.** Let clear names and structure carry the code. Comment only to explain non-obvious behavior (a subtle invariant, a workaround, a "why" not visible from the code), and keep it brief.

### C++
- 4-space indentation, opening braces on the next line
- `UpperCamelCase` for classes, `m_` prefix for members, `lowerCamelCase` for functions, `k` prefix for file-scope/`constexpr` constants (e.g. `kMaxGridPointsPerAxis`)
- Full `const` correctness; use Qt signal/slot patterns with `Q_OBJECT`
- Use function-pointer syntax for `connect`/`disconnect` (`connect(obj, &Class::signal, this, &Class::slot)`), never the `SIGNAL()`/`SLOT()` string macros
- Address Sanitizer is enabled in macOS Debug builds
- **No magic numbers.** Extract numeric/color literals (z-values, radii, offsets, font sizes, RGB tuples) to named `constexpr`/`const` constants, typically in an anonymous namespace at the top of the `.cpp`. Fix adjacent raw literals too rather than matching a bad sibling.
- **Main-thread budget: one frame (16 ms) per event-loop turn.** Any work that scales with project size (nodes, trips, stations, fixes, keyword items) must fit it, in this order of preference:
  1. **Cut.** Coalesce per-item observer work into one queued pass: set a dirty flag and schedule the pass once with `QMetaObject::invokeMethod(this, &Class::slot, Qt::QueuedConnection)` (a `QTimer` allocates a `QObject` for the same job). Insert ranges, never one row at a time: `beginInsertRows` over the range, `addNodes`/`addItems`, not N calls to `addNode`/`addItem`. A whole-tree walk connected to a per-item signal is quadratic.
  2. **Move.** Run it on a worker and bring the result back with `AsyncFuture::observe(future).context(this, ...)`.
  3. **Interleave.** Install a large result in bounded batches, one batch per event-loop turn, under a `cwFutureManagerToken` job so the task list shows progress.

  Tests pin growth, not milliseconds: a 4x larger synthetic fixture may cost at most about 4x (measure the longest event-loop gap, or count `dataChanged`/`rowsInserted` with `QSignalSpy`). Absolute timing is for the owner in the app.
- **`AsyncFuture::waitForFinished` is test-only.** It spins a nested `QEventLoop`, causing re-entrancy bugs (use-after-free, iterator invalidation). In production use `AsyncFuture::observe(future).context(this, callback)` (auto-disconnects on `this` destruction; destructors just call `future.cancel()`). Existing `waitForFinish()`/`waitToFinish()` helpers on managers exist solely for tests.
- **Use `.at(i)` or a `const` reference for read-only access to `QList`/`QVector`, never non-const `operator[]`.** `operator[]` calls `detach()`, which reallocates when refcount > 1 — a data race from worker threads. This includes access through smart pointers: write `ptr->at(i)`, not `(*ptr)[i]`.
- **Do not wrap `QList`/`QVector` in `std::shared_ptr`.** They are already implicitly-shared value types. To snapshot for a worker thread, `auto snap = m_container;` and capture by value; workers must stick to const access.
- **Do not use Qt bindable properties** (`Q_OBJECT_BINDABLE_PROPERTY*`, `QBindable`, `QProperty`, `setBinding`) in new code. Use plain members with explicit setters following `if (m_x == x) return; m_x = x; emit xChanged(); /* side effects */` and declare `Q_PROPERTY` with `NOTIFY` (no `BINDABLE`). Some older classes still use the macros; don't add more or refactor unless touching the file anyway.
- **Use `QStringLiteral(...)` for compile-time `QString` constants.** It bakes the UTF-16 payload in at compile time; `QString::fromLatin1(...)` and `QString(const char*)` heap-allocate on every call — fine for one-shot init, wasteful in per-frame hot paths (e.g. `buildPipelineKey`, which runs once per frame per RHI object). Don't wrap a `constexpr const char*` in `QString::fromLatin1` for DRY's sake; repeat the `QStringLiteral` instead — it's free at runtime and compilers fold duplicate instances.
- **Keep production public API free of test scaffolding.** No `*ForTesting` methods/members or `friend class FooTestAccess` on production classes. Do not add member data that exists only for tests to observe — e.g. call counters, "times invoked" tallies, or last-value caches. Tests verify through the real surface: disk-state checks (file existence, byte content, mtime), existing public signals (`objectPathReady`, `saveFlushCompleted`, `discardCompleted`), and standard wait helpers (`waitSaveToFinish`, `waitLoadToFinish`, `waitForDiscardToFinish`). Use `SignalSpy`/`SignalSpyChecker` to count emissions instead of a member counter. `cwSaveLoad::waitForFinished()` and `cwProject::waitSaveToFinish()` are pre-existing exceptions; don't add new ones.
- **Never use `goto`** — no exceptions; the codebase has zero usage. To escape nested loops, use a `[&]()` lambda (capturing by reference) that uses `return` to exit. Name the lambda when the body is more than ~10 lines or you'd otherwise comment its intent; an inline IIFE is fine for short, self-documenting bodies. Both inline to the same machine code as `goto` and read top-down. Avoid the `bool flag; if (flag) break;` pattern.
  ```cpp
  const auto seedConnected = [&]() {
      for (cwTrip* trip : cave->trips())
          for (cwSurveyChunk* chunk : trip->chunks())
              for (int i = 0; i < chunk->stationCount(); ++i)
                  if (isValid(chunk->station(i))) {
                      insertChunkToConnected(chunk, connected, edges);
                      return;                  // escapes all three loops
                  }
  };
  seedConnected();
  ```

### Threading and the task pool
- **One pool, one entry point.** All CPU work runs on `cwTask::threadPool()` through `cwConcurrent::run`, `cwConcurrent::map`, or `cwConcurrent::mapped`. Never call `QThreadPool::start`/`tryStart`, subclass `QRunnable` or `QThread`, use `std::thread`, or call `QtConcurrent::run` directly. The only other executors are the two serial lanes (`cw::ktx2::encodeLane()`, `cwSaveLoadPrivate::m_saveThreadPool`) and the render thread's `scheduleRenderJob`; do not add a pool.
- **The future is the completion signal.** Every `QFuture` is stored, observed with `AsyncFuture::observe(f).context(this, ...)`, combined, or joined. Never discard one. Never hand-roll completion with `QSemaphore`, `QWaitCondition`, `std::condition_variable`, an atomic counter, `isFinished()` polling, or `msleep`. The two documented exceptions are the encode lane hand-off (`runOnLane`) and `EncodeClaim` in `cwKtx2Codec.cpp`; a new one needs a comment saying why a future cannot carry it.
- **Fan-out is bounded.** The pool is a single FIFO shared with interactive work, so a loop that enqueues N runs up front makes every later job wait for the drain. Data-parallel items go through `cwConcurrent::map`/`mapped` (pull model, queue depth = pool width). Weighted or memory-budgeted admission goes through `cwMemoryBudget::limitedOnPool` / `AsyncFuture::limited`; a long-lived queue through `AsyncFuture::Limiter`.
- **Cancel reaches the worker.** Work that can be superseded or takes more than a few milliseconds uses the `QPromise&` form of `cwConcurrent::run` and polls `promise.isCanceled()` between stages. Managers keep the current run (`Limited` or `Restarter`) and cancel it on restart and in the destructor. No side-channel cancel flags (`shared_ptr<atomic<bool>>`).
- **Waiting inside a pool worker.** Prefer calling the dependent work inline on the current thread. If a worker must block on other pool work, it releases its slot around the wait (`cwGeometryItersecter::waitOnPool` is the model) so a small pool cannot deadlock. A plain `QFuture::waitForFinished` is fine from a thread outside the pool and the event loop (a lane, a teardown join); `AsyncFuture::waitForFinished` and any `QEventLoop` spin stay test-only.
- **Destructors cancel, never wait.** No `waitToFinish`, `processEvents`, or `QEventLoop` in a destructor.
- **Review trigger.** A diff that adds `QSemaphore`, `QWaitCondition`, `QRunnable`, `QThread`, `std::thread`, `QtConcurrent::`, `globalInstance()`, `releaseThread`, `msleep`, or a `cwConcurrent::run` whose result is unused gets a threading review before it merges.

### QML
- Strict typed properties (no `property var`); lowerCamelCase property names; Capitalized component filenames
- Use `Theme.qml` for all colors and font tokens — never hardcode hex values or font sizes
- Prefer `id` selectors over `objectName`; keep bindings simple; avoid deep nesting
- Register modules via `qt_add_qml_module` in CMakeLists.txt
- Use `Loader` for deferred/conditional loading; avoid expensive operations in bindings
- Use `QCanvasPainterItem` (C++) for custom painting; do not use QML `Canvas` or `Shapes`
- Prefer `TapHandler` over `MouseArea` in new components (existing `MouseArea` is legacy — don't refactor unless touching the file)
- Import `QtQuick` as `QQ` (never `Q`), so it's easy to search for
- **Item body ordering** (blank line between groups): `id`, `objectName`, property declarations, property assignments/aliases, signal declarations, functions, property bindings, signal handlers (`on*`), child objects, `states`/`transitions` (last)

#### Private data
- Fixtures, tests, plans and commit messages hold only fake or public (OpenStreetMap, Grottocenter) data: no real fixes, cave or survey names, owner paths, or exact project counts. Reproduce a private-data bug with a fake fixture of the same shape. The `private-dataset` skill has the rules; its pre-commit and commit-msg hooks block findings (`.claude/skills/private-dataset/scripts/install-hooks.sh`).

#### C++ testing
- Tests must be safe to run as **multiple concurrent processes** (nightly CI runs several in parallel). Never use hardcoded temp paths — include `QCoreApplication::applicationPid()` in the name or use `QTemporaryFile`/`QTemporaryDir`.
- **Wait on a condition, never pump.** When a test needs a queued pass or a worker result to land, name the state it produces and wait for that: `REQUIRE(waitUntil([&] { return <state>; }))` from `testcases/TestHelper.h`, or `QSignalSpy::wait()`. A bare `QCoreApplication::processEvents()` asserts timing (one turn happened to be enough) where the test means to assert behavior; it is the C++ form of a fixed `wait()`.

#### QML testing
- Prefer `tryVerify()`/`tryCompare()` over fixed `wait()`. `QQ.Transition` with `QQ.ScriptAction` fires next frame, so `tryVerify` the side-effect rather than assuming the state change is enough.
- Collapse note overlays (`setNoteOverlaysCollapsed(true)`) before clicking the note image in tests — the NoteTransformEditor overlay (z=2) can intercept clicks.

#### Text and fonts
- Use **`QC.Label`** (`import QtQuick.Controls as QC`) for all text — it inherits `font.family` and tracks the palette for dark mode. Never use bare `Text {}` / `QQ.Text {}` (they render black in dark mode).
- Use **`BodyText`** for paragraph/body copy (wraps `QC.Label` with `Theme.fontFamilyBody`).
- Prefer `Theme.qml` font tokens over hardcoded sizes: `fontSizeCaption` (11), `fontSizeSmall` (12), `fontSizeBody` (14), `fontSizeUI` (16), `fontSizeMedium` (18), `fontSizeTitle` (20), `fontSizeLarge` (24), `fontSizeXLarge` (30).

### Commits
- Short, capitalized, imperative subjects ("Fix", "Add", "Implement")
- Body: what changed, why, build/test commands run
- Attach screenshots for QML UI changes; link related issues; note submodule/dependency changes explicitly
- Do not mention Claude or add Co-Authored-By lines
