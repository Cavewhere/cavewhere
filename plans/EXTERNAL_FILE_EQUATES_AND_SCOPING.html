External File Integration — Equates & Station Scoping

Part of the External File Integration plan. Read the master plan and Phase 2 first. This file owns a foundational feature that is bigger than Phase 2 and underpins Phase 3: a persistent, user-editable equate (station tie-in) concept, the unified station-scope model it rides on, and opt-in native station prefixing. It was spun out of Phase 2 §15 because the equate work is a new model concept, not a Phase-2 bug fix.

Cross-cutting test rules (per-process safety, cavern serialisation, narrow tag filters, "existing tests always green") live in master §10.1 and apply to every commit here without restating.

0. Why this exists (and how it relates to Phase 2 & 3)

The user asked a deceptively simple question: how does a native survey tie into an attached external centerline? The answer, after tracing the code, is it can't — and the reason exposes a missing primitive that three separate features all need. This plan builds that primitive once.

  • Phase 2 is not gated by this work. Its only remaining blockers are §16 B2 / B3 / B6. But the note-station entry UI and the trip-page layout Phase 2 is finishing will be reshaped by the scope model here — so settling this design before hardening that UI avoids building it twice.
  • Phase 3 (cave-level attach) is already specified in terms of a stationPrefix on "Scope trips" (Phase 2 §11 stub, master §7.2 / §8.5.1 / §8.7). That is identical to the "native prefixing" designed here (§7 Path B). This plan makes the shared foundation explicit so Phase 3 consumes it rather than reinventing it (§6).
  • Phase 2 §15 F1 (external note-name / native-station collision) is a symptom of the same missing scope model and is folded into the scope lens (§4 commit 7) here.

1.2 There is no equate concept in the model at all

  • Nothing persists an equate. cavewhere.proto stores stations only by name — no equate/tie/alias/ connection field on Cave (:82), Trip (:107), Shot/StationShot (:217/:244), or ExternalCenterline (:76). FixStation (:65) is a georeferencing position, not a station-to-station tie. No runtime cwEquate/cwConnection class exists.
  • Import flattens equates. A Survex *equate A.1 B.1 is consumed at import: cwSurvexGlobalData::populateEquateMap (cwSurvexGlobalData.cpp:278–311) picks a canonical name and fixStationNames (:148–250) renames the stations to share it, then discards the map. The relationship becomes an implicit shared-name tie. (It also can't handle 3+-way equates — FIXME at cwSurvexGlobalData.cpp:292–296.)
  • Export synthesizes equates. The only *equate lines the exporter writes are for LRUD carrier stations, generated fresh from geometry each export (cwSurvexExporterTripTask.cpp:346–350, cwSurvexExporterRule.cpp:428–432) — not a round-trip of stored data.

Conclusion: a user-editable equate is a brand-new persistent model concept. The only reusable prior art is the mechanical *equate emission pattern and the import-side name-merge machinery.

1.3 Feasibility: decode is ready, emission has one real blocker

Decode round-trips an equate for free. Cavern emits both equated names at the same coordinate; the reader keeps both (cwSurvex3DFileReader.cpp:89–105); and splitLookupByCave keys the per-cave lookup by regex capture 2 (cwLinePlotTask.cpp:455–456, cwCavernNaming.cpp:65–67), producing two distinct cave-local keys sharing one position with no collision. An equate is literally "two aliased names, one point," and the pipeline already represents it that way.

Emission is a bare *equate line — SPIKED & RESOLVED 2026-07-22 (commit 1, testcases/test_cwEquateSpike.cpp). The feared export barrier does not apply to our driver. Cavern's error 26 ("Station not exported") fires only when a station was *export-ed but not to a deep enough level: the check at readval.c:329 runs only when min_export is neither 0 nor USHRT_MAX, and a never-exported station keeps min_export == 0, making the check a no-op. The survex corpus shows exactly this asymmetry: survex/tests/export.svx passes because inner.1 is *export-ed at both nesting levels; survex/tests/exporterr1b.svx fails because it is exported at the inner level only — an incomplete chain, not a missing one. Since our driver emits no *export at all (cwSurvexExporterCaveTask.cpp:104–125), a bare qualified *equate just resolves. No *export and no *infer exports are needed. The spike drove real cavern solves and confirmed coincident positions at cave scope, region scope, and for an N-way (3-operand) equate. This materially simplifies commits 4 and 5: emission is one *equate line at the tie's scope.

Two lesser wrinkles to design around, not blockers:

  • Topology stays "two nodes at one point." The .3d line-endpoint index is first-label-wins (cwSurvex3DFileReader.cpp:98–104), so the alias name gets a position but may carry no adjacency edges; updateCaveNetworks (cwLinePlotTask.cpp:576–620) does not merge the two cave-local keys. Positions are perfect; consumers must treat the aliased keys as position-aliases, not assume one merged node.

2. Decisions locked (2026-07-22)

#DecisionRationale
D1Alias, never merge. A 3D station location may carry multiple names; both stations keep their identity. Mandatory for external (can't rename a foreign file's stations) and matches the decode's natural representation (§1.3). The import's rename-and-drop is the wrong model for a persistent tie.
D2Both cave-scoped and cross-cave / region-level equates ship in this plan. Cross-cave is a second storage home + a second emission path (§5), not a new model — the handle (D6) is shared. Two caves that physically connect (a dig breaks through) is a first-class case, not a someday one; the self-contained handle makes it cheap to include now.
D3Spike first — DONE 2026-07-22 (GREEN). Commit 1 proved cross-scope *equate solves at both cave and region scope with a bare line: no *export, no *infer exports. The export barrier was a false alarm (see §1). Emission in commits 4/5 is one *equate line. Small, decisive, and the whole model is worthless if cross-scope *equate can't solve. It can.
D4N-way equates. An equate is a set (≥2) of station handles; fix the import's 2-way limit while here. A junction where three surveys meet is one physical point, not two pairwise ties.
D5Additive / opt-in. native→native keeps working implicitly by shared name (backward compat). Equates are added for the three external directions and for prefixed-native trips. No migration forced on existing flat projects.
D6Self-contained station handle (scope, containerId, tail) with containerId always populated (option A): caveId for a NativeCave station, tripId for a Trip-scoped (external / Scope-trip) station. Location-independent identity — the same handle works on a cave or the region, so cross-cave needs no schema change. A tripId (not a denormalized caveId) for scoped stations keeps a re-parented trip correct.

3. Foundation: one unified station scope

Three things scope a trip's stations, and they are the same shape. The whole plan hinges on collapsing them into one accessor so equates, the scope lens, native prefixing, and Phase 3 all speak it.

Trip kindScope prefixSource
Native (flat) (empty)—
External (trip attach)<tripLabel>. the trip's name, pooled for uniqueness against its cave's other trips; externalCenterline only selects that this rule applies
Scope trip (Phase 3 cave attach) / native prefixed <stationPrefix>. stationPrefix

Updated 2026-07-26 (Fork A). The sketch below was written when a label was trip_<hex> — a pure function of an immutable QUuid. It is now derived from the trip's name and de-duplicated against its siblings, which changes the shape of the accessor: it needs the sibling set, and isScoped() deliberately no longer routes through it. 

// As shipped. The pooled-label overload is where the policy actually lives;
// the other two entry points feed it a label and share the branch.
QString cwTrip::scopePrefix(const cwTripData& data, const QHash<QUuid, QString>& tripLabels) {
    if (!data.externalCenterline.isEmpty()) {
        const QString label = tripLabels.value(data.id);      // cwCavernNaming::scopeLabels
        return label.isEmpty() ? QString() : label + '.';     // "topo_1." / "topo_1_2."
    }
    if (!data.stationPrefix.isEmpty()) return data.stationPrefix + '.';  // "A."
    return QString();                                                     // flat native
}

// NOT !scopePrefix().isEmpty(): scopePrefix() has to walk the cave's trips to
// pool the labels, and this is read from QML bindings. Same two fields decide it.
bool cwTrip::isScoped() const { return !m_externalCenterline.isEmpty() || !m_stationPrefix.isEmpty(); }

Consequence for every future commit here: a label is only unique within a cave, and producing one costs the whole sibling set. Anything asking per trip inside a loop over a cave's trips is quadratic — pool once with cwCavernNaming::scopeLabels and pass the map (cwSurvexExporterCaveTask::writeCave and cwLinePlotGeometry both do). And because the label depends on a mutable name, deriving it in two places is no longer safe by construction — see "Label ownership" under Fork A.

The three cwTrip accessors (solvedStationPositions/solvedNetwork/ solvedStations, cwTrip.cpp:406–503) originally branched on m_externalCenterline.isEmpty() and stripped tripScopePrefix(id()). They now branch on isScoped() and strip scopePrefix() — the strip logic was already there, just generalised. This subsumes Phase 2 §15 R2 ("shared externallyBacked predicate") and A1 ("uniform external-station accessor"): both C++ (cwLinePlotGeometry.cpp, cwLinePlotLabelView.cpp) and the QML NoteStation / NoteLiDARStationItem validator bindings that hand-roll externalCenterline.entryFile.length > 0 collapse onto isScoped. Exception: TripPage.isExternal stays on externalCenterline — it drives the pane swap ("is this an external attach?"), not the station-name grammar, and a Scope trip has native chunks that must keep the survey editor. (See Commit 2's "deliberate deviations".)

The failure mode to avoid: building equate emission (or any new scope logic) around the external-only trip_<hex> prefix. That works for trip-attach but silently breaks for Phase-3 Scope trips. Everything must go through scopePrefix().

An equate is an N-way set of self-contained station handles (D6): 

struct cwStationHandle {
    enum Scope { NativeCave, Trip };
    Scope   scope;
    QUuid   containerId;   // caveId when NativeCave, tripId when Trip
    QString tail;
};

containerId is always populated — auto-filled from the owning cave for a within-cave native tie, so the UI never asks for it. Because the handle is location-independent, one type serves two homes:

  • cwCave equate list — within-cave ties. Validation: every Trip handle's parentCave and every NativeCave handle's containerId must equal the owner cave. Travels with the cave.
  • cwCavingRegion equate list — cross-cave ties (two caves that connect). Handles may span caves; no owner-cave constraint.

Commit 6 — Tie-in UX (the pain-point payoff)

Design settled 2026-07-22 across three interactive HTML prototype iterations; the editor-centric direction below was chosen. It supersedes the original "pick two stations in a global Ties panel" sketch — a global pick-two panel tested as confusing. A tie is not an object you curate in a list; it is how a station joins the cave (same qualified name ⇒ same point, the D5 implicit tie). So creation moves into the editor, where the survey data is, and the global list survives only as a read-only audit.

Two mechanisms, chosen automatically by whether the tails match:

  • Same tail → re-scope (no equate object). The trip has a1 and the cave already has a1: escape the trip's prefix on that one station so its qualified name becomes the cave's a1 and the two coincide (D5 shared-name tie, taken cross-scope). Non-destructive — the tail is unchanged, only its scope. This is the .-absolute override (below), and it is the primary path.

The payoff is the floating-survey suggester, not a pretty table. Three surfaces, one shared banner→suggester spine:

  • Native — the SurveyDataEditor station cell. Cells are small, so a tied station shows only its tail plus a tie badge (a1 ↳ tied), never the full whitmore.a1; the target opens in a click popover (change / remove).   • External centerline — the TripPage panel. No editable shot cells exist (stations come from the .svx), so ties live in their own Connections list on the panel.   • Global — a read-only Health / Ties page. Never creates a tie: every join in one place with its misclosure, which trips are still floating, and an exported-survex peek (readable vs hex) — the "reviewable, not a text file" win, and where the naming spike's payoff is visible.

Floating means no coordinates — so the first tie cannot be distance-ranked. A disconnected survey has no position in the cave's frame, so proximity ranking and the misclosure/gap read-out are unavailable until at least one station is tied and the network re-solves. The suggester therefore ranks the first connection by name only (tail + letter-prefix, no gap number); once one tie lands and the solve pulls the survey into frame, subsequent connections gain distance ranking and gap numbers. This is precisely why the external-centerline panel must allow multiple connections and iterate: tie one by name → re-solve → refine the rest with distance (extra ties past the first also yield the loop misclosure that validates the join).

Label ownership and invalidation (from the 2026-07-26 pre-commit review)

The deeper version of that coupling, and the thing to design before Commit 6 and Commit 8 add consumers. Under hex a label was a pure function of an immutable QUuid, so "derive it wherever you need it" was correct by construction, and six sites adopted that habit: cwSurvexExporterRegion.cpp, cwSurvexExporterCaveTask.cpp (×2), cwLinePlotTask.cpp, cwLinePlotGeometry.cpp, cwTrip.cpp, cwExternalCenterlineManager.cpp. Fork A makes a label a function of (mutable display name × mutable sibling set × iteration order). The habit is no longer safe.

Three consequences were found; the first two were fixed inside Fork A, the third in the A1 commit that followed it:

  • Fixed. ExternalCenterlineTripPanel.qml bound scopePrefixForTrip(trip) with trip as its only declared dependency, so a rename left it filtering the re-solved network on a dead prefix and the station list silently emptied. It named the network instead — every rename re-solves, so that is the pulse that says the prefix may have moved. (Superseded: the panel now passes only trip and the model subscribes to the re-solve itself — see The model owns its own pulse.) Any future binding on a scope label needs the same care; a Q_INVOKABLE returning a name-derived value has no NOTIFY of its own.
  • Fixed. The trip label had four independent derivations where the cave label had one. cwTrip::scopePrefix(data, tripLabels) is now the single policy, and writeCave, the cave and region equate operands, and the geometry pass all pass it a pool computed once per cave (this also removed an O(trips²) per solve and an O(equates × handles × trips) per export).
  • Fixed (A1 commit A, 2026-07-26). scopeChanged fired for a trip's own rename but could not fire when a sibling was renamed, added, or removed — which is exactly what moves this trip's collision suffix. Closed by putting each cache where its uniqueness rule already lives; see below.

What shipped (A1 commit A). The sibling set that can move a label is owned by the parent, but only the child had a change signal — so the fix was to give each parent the cache and the pulse for exactly the set it defines:

  • cwCave::tripScopeLabels() caches its trips' labels and tripScopeLabelsChanged() fires on insert, remove, or a held trip's rename. The wiring lives in cwCave::connectTrip/disconnectTrip, called from InsertRemoveTrip::insertTrips/removeTrips — the one funnel every mutation (including setData's load path) already goes through. cwCavingRegion::connectCave/disconnectCave mirror it one level up. Keeping the wiring in named methods rather than inline in the undo commands is what made the missing teardown visible: writing disconnectCave is what surfaced that the pre-existing grid-convergence connect had never had one.
  • Invalidate before the first emit, pulse after the last. Both funnels mark the cache stale immediately after mutating the list, then emit the model signals, then pulse *ScopeLabelsChanged last. A handler woken by insertedTrips can reach cwTrip::scopePrefix() (cwLinePlotLabelView does, through solvedStations), and a cache still marked fresh would answer it from the list as it stood before the insert.
  • cwCavingRegion::caveScopeLabels() does the same for cave labels, and scopeLabelsChanged() aggregates its own cave insert/remove/rename plus every cave's tripScopeLabelsChanged — the single region-wide pulse a consumer showing labels across more than one cave needs (Commit 6's ties audit and suggester).
  • cwTrip::scopeChanged chains off its cave's signal, so the Q_PROPERTY stops lying, and scopePrefix() is now an O(1) lookup instead of walking every sibling on each read.
  • The two cave-less cases are not the same case (settled in review, 2026-07-27). A trip with no cave at all — being built, or imported before it is parented — has no sibling set, so its own sanitized name is unique by construction and stays its label. A trip its cave still parents but no longer lists (removed; InsertRemoveTrip leaves the parent set so undo can restore it) now reports no scope. A self-derived label there is precisely the label a live sibling may already hold, and the solved* accessors would strip by it and hand back that sibling's stations as this trip's. The earlier "keeps the self-only fallback" wording collapsed both cases and was wrong for the second.
  • cwExternalCenterlineManager::scopePrefixForTrip — the sixth derivation site — now reads the region cache, which orphaned cwCavernNaming::scopePrefix(id, siblings); it was reshaped into scopePrefix(label), the one place the . separator is spelled (three sites had it inline).

The one thing Commit 6 must still be careful about. cwTrip::scopeChanged deliberately means "this trip's own prefix may have moved" — it does not fire when the cave is renamed, because that moves the qualified name (scopePrefixForTrip = cave label + trip prefix) while leaving scopePrefix() itself untouched. Anything binding a qualified name must use cwCavingRegion::scopeLabelsChanged, which covers both halves. ExternalCenterlineTripPanel.qml is correct today only because its station list refreshes on the re-solve and a cave rename re-solves; a consumer that does not re-solve has no such luck.

cwSiblingLabelCache — the live half, extracted

Added in review (2026-07-27). cwCave and cwCavingRegion had each grown the same pair of members (mutable QHash<QUuid, QString> plus a mutable bool …Stale) and the same rebuild loop. Who owns the qualified name — RESOLVED 2026-07-27

Follow-ups 3 and 4 above were taken together, before commit 6 starts, and the answer turned out to be nobody, on the live side. Three facts, in the order they landed:

  • There was never duplication to consolidate. cwExternalCenterlineManager.cpp:726–732 is the only live site that joins a cave prefix to a trip prefix; the QML panel and the tests all call it. The problem was placement and shape, not repetition.
  • Its shape does not fit commit 6. scopePrefixForTrip(cwTrip*) answers "what prefix do this trip's stations carry". Commit 6 holds a cwStationHandle, whose NativeCave case has no trip at all. The badge popover, the Ties page and the suggester all want handle → qualified name, which no live API answers.
  • The snapshot side already answers it. cwSurvexExporterRegion.cpp:56–69 composes exactly that, parameterised by cwScopeLabels. It is exporter-private and snapshot-only, and it blanks a malformed handle — right for emission, wrong for a UI whose job is to show you the broken tie.

Decision: the live side stops composing qualified names entirely. cwScopeStationListModel's second mode (scopePrefix + network) is deleted, the panel drives the model by trip, and scopePrefixForTrip goes with them — it has no other caller. What remains of "who owns the qualified name" is only handle → display name for commit 6's Ties page, which is the exporter-side renderer, reached once rather than reimplemented.

The load-bearing rule: identity never round-trips through a string. cwStationHandle already says it — a station is named "by the scope it lives in plus the tail, never by a fully-qualified flat string" (cwStationHandle.h:21–24). Parsing fisher_ridge.topo_1.a1 back into a handle would reintroduce exactly that, and it does not even work: a native-prefixed trip's prefix is stationPrefix, arbitrary user text that can contain dots and collide with a cave label. So the picker carries (containerId, tail) and commit 6 reads them directly. This is why no inverse map is needed, and it is what retires follow-up 3 rather than fixing it: rows sourced from solvedStations() carry no baked qualified prefix to go stale.

Rejected: a region-owned live cwScopeLabels. Building the pool from the two live caches and invalidating on scopeLabelsChanged would give both sides one read interface, but costs an O(total trips) rebuild per pulse — a rename emits one per keystroke — and makes a third copy of every label. Its one real draw was materialising the inverse (label → id) that a string-parsing picker would need; the rule above removes that need. Note the inverse already exists in another form: StationTripScrapLookup (cwLinePlotTask.cpp:63–113) materialises station-name → tripId per cave — that is follow-up 1's problem, not something commit 6 should reach into.

Cost correction. Resolving a handle's owning container live is O(total trips), not O(caves × trips) — owningCave's inner loop is bounded by that cave's trips, so the visits sum to the region's trip count. A Ties page rendering M ties is M × O(T): milliseconds at realistic sizes. A trip → cave index is a profile-driven addition, not a design requirement.

Per-window editor host — DONE

A spike settled first whether this was needed at all, since issue #494 (“Support Multiple windows” — right-click the sidebar to open View/Data/Map in its own window) would depend on it. It was: tst_ShadowEditorMultiWindow.qml built two windows, each claiming the host the way MainContent.qml did. There is one QQmlApplicationEngine for the application, so a singleton host is shared by every window, and an Item has one parent — the second window took the host away from the first, and window A's fields then opened an editor in window B. Silently: no warning, no crash. The Data page is wall-to-wall ClickTextInput, so #494 would have hit this immediately.

GlobalShadowTextInput is gone. In its place: ShadowEditorHost (the same component, no pragma Singleton), held by a new AppOverlay that each window declares once, and a C++ attached type cwWindowOverlay that resolves an item's window to that window's overlay — the same shape as Qt's own Overlay.overlay. A field writes (WindowOverlay.overlay as AppOverlay)?.shadowEditor. An attached type was chosen over a hand-rolled QML registry keyed by window because it re-resolves on windowChanged by construction: #494 moves items between windows, which a resolve-once registry gets wrong, and gets wrong silently.

RootPopupItem rode along and is deleted: it was the identical hack on the identical two lines, and its two consumers (ErrorListQuoteBox, RemoveAskBox) now reparent into the same per-window overlay. Also gone: both X.parent = overlay reparent pairs, the anchors-with-no-parent startup state, and the reset boilerplate that had been copied into five test files — now one MainWindowTest.closeAnyOpenEditor().

One trap worth keeping. DataBox's MiddleTyping state used to install its Tab/Space/Enter handling with QQ.PropertyChanges reaching through _shadowEditor with grouped-property syntax. That needs the host's type fully resolved while DataBox.qml is still compiling, and now that the two types name each other it is order-dependent: MainContent failed to load with “Invalid grouped property access … neither a value nor an object type” in 3 runs out of 5. The handlers are now a QQ.Connections gated on enabled: state === "MiddleTyping", whose target is an ordinary binding — which also retires DataBox's exposure to the PropertyChanges-resolves-once landmine. Note the QML suite could not catch this: test-qml is a separate module that loads cavewherelib already built, so only the C++ test_CavewhereMainWindow saw it, and only intermittently.

Still single-window, and not this commit's work. The editor host was one instance of the pattern, not the last. RootData.pageView (cwRootData.h, written from both MainContent.qml and sketch/qml/Main.qml) is the same app-global slot for a per-window visual object, and prepareForProjectSwitch() clears only the one registered page view's cache. cwPageSelectionModel fuses an app-wide page registry with per-window selection and history — the larger #494 blocker. SelectableValueGroup holds an app-global Item, so focusing a field in one window deselects another's. All three can now use this mechanism; none is scheduled here.

Host owns the editing contract — DONE

The per-field editor commit made GlobalShadowTextInput.textInput and .errorHelpBox transient — bindings over editorLoader.item, rebuilt whenever a field asks for a different editor — but left five call sites still reaching through them. That relay was only half the repair: any one of those reaches could have grown into the same silent QQ.PropertyChanges failure, and the nullable bindings were dereferenced unguarded. Both properties are now gone from the host's public surface, replaced by verbs the host performs: editorText(), setEditorText(), clearSelection(), focusEditor(), editorHasFocus(), showError(), clearError(), hasError(), defaultKeyHandling(). Each null-guards in one place, so the "don't hold the editor" rule is enforced by there being nothing to hold. pressKeyPressed now carries the key event, so DataBox's MiddleTyping handler no longer has to go find it on an object it isn't allowed to keep. currentEditor stays public: a caller that legitimately needs to know which editor opened has to look, and looking was never the mistake — storing it was.

Two behaviour fixes fell out of it. commitChanges()'s branches disagreed on ordering — the validator branch emitted finishedEditting before closeEditor(), the other closed first — so a handler that moved focus and rewrote the model (which DataBox's does) saw the editor still open and the focus leaving it, and committed a second time. Both branches now capture, close, then emit. And the error path's textInput.focus = true could not put the cursor back at all: under the Loader's focus scope focus is still true after a blur, so the assignment changed nothing. focusEditor() calls forceActiveFocus().

Tests: tst_ShadowEditorHostContract.qml (new) covers a rejected value leaving the editor open, focused and explaining itself, and finishedEditting arriving with the editor already closed on both branches. Existing tests moved onto the host API rather than the editor. Status: COMMITTED 58bb43e9 on externalFiles, green (QML suite 829/0), not pushed.

Commit 9 — Native prefixing, Path B (declared stationPrefix)

The ergonomic + structural layer, shared with Phase 3: a trip carries a declared stationPrefix (from commit 2); chunks store bare tails; the qualified identity is prefix.tail, applied at the same layer external trips are wrapped (cwSurvexExporterCaveTask.cpp:104–125 generalised from trip_<hex> to any scope label). Case-policy landmine (from Commit 2 review): Commit 2 made the three cwTrip solved-* accessors strip the scope prefix case-insensitively (the cave lookup keys canonically via cwStation::canonicalKey, so an authored mixed-case prefix must match case-folded), but the worker-thread geometry strip in emitNetworkScopeGeometry (cwLinePlotGeometry.cpp:82, station.startsWith(scopePrefix)) is still case-sensitive. New collision class this commit creates (review 2026-07-26). cwCavernNaming::scopeLabels pools an external trip's name-derived label against its siblings' names, but a native-prefixed trip's stationPrefix goes through cwTrip::scopePrefix verbatim and never enters that pool. 5. Cave-owned vs region-owned equates

Both ship in this plan (D2). They differ only in storage home and emission scope; the self-contained handle (D6) is identical, so cross-cave adds no new field — a region-owned equate is simply one whose handles resolve to more than one cave.

6. Phase 3 compatibility

Phase 3's cave-level attach auto-creates Scope trips under a cave, each carrying a stationPrefix (the file's survey designation) rather than a per-trip externalCenterline (Phase 2 §11 stub: trip.stationPrefix "Phase 3 adds it"; isScope/scopeHeaderComp; master §7.2 / §8.5.1 / §8.7).
