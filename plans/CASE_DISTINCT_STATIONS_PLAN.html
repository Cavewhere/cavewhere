Case-Distinct Stations

CaveWhere branch externalFiles, based on 3f7be010 "Keep foreign neighbors out of scoped survey networks" · 2026-10-26

Goal. When an attached file has two stations whose names differ only in case, CaveWhere draws them as two stations, the way cavern solved them. Compass and Walls names are case-sensitive, and cavern keeps P2 and p2 apart. CaveWhere folds both to p2 when it reads the .3d, so the pair gets one position and every leg of either station is drawn to it. In a private Compass project with 412 such pairs, 284 pairs sit more than 1 km apart, and the plot fills with long false legs.

The bug

Survex reads a Compass .DAT with case folding off (survex/src/datain.c, about line 753: pcsNew->Case = OFF). Walls files and Survex files that set *case preserve behave the same way. Cavern then writes P2 and p2 as separate labels at separate coordinates in the .3d, and that output is correct.

cwSurvex3DFileReader::readNetworkAndLookup passes every label to cwStationPositionLookup::setPosition, cwSurveyNetwork::setPosition and cwSurveyNetwork::addShot. All three key by cwStation::canonicalKey, which lowercases. The reader also lowercases the splay anchors, the fixed stations and both ends of each legKey. So:

  • the pair keeps only the position of whichever label came last;
  • the network gives p2 the neighbors of both stations, and cwLinePlotGeometry draws every one of those legs to that single position;
  • splays and loop-closure errors from both stations land on that one station.
A case pair merges at readback. The legs of P2 are drawn to p2's position. In real data the two stations can be kilometers apart.

CaveWhere's own trips are safe. The driver keeps cavern's default *case tolower, so a native name reaches the .3d already lowercase and never forms a case pair. plans/EXTERNAL_FILE_PREFIXING_RESEARCH.md §5.3 named these mixed case regimes, but the readback side kept lowercasing.

Decisions

  • Cavern decides what counts as one station. Two labels are one station exactly when cavern wrote one label. The reader keeps every station cavern kept.
  • Keys stay lowercase unless they form a case pair. A solved station's key is canonicalKey(label), as it is today. It keeps cavern's spelling only when another label in the same .3d lowercases to the same key. The survey levels of such a key are still lowercased; only the last level, the station name, keeps its case. So a project without case pairs gets byte-for-byte the keys it has today, and the existing tests that expect "k1" keep passing.
  • Lookups by name keep ignoring case. A by-name lookup first tries the name exactly, then canonicalKey(name). position("K1") still finds k1. With a pair P2/p2, position("P2") and position("p2") each find their own station. A spelling that matches neither exactly, such as "bB2" for a pair BB2/Bb2, finds the all-lowercase member if there is one and otherwise nothing. A fix or tie typed that way gets the usual unknown-station warning.
  • By-name inserts keep folding; by-key inserts don't. setPosition(name), addShot(name, name) and addNeighbor(name, name) keep lowercasing: test helpers on origin insert "A.s1" to overwrite a.s1, and cwTripLinePlotTask renames native stations through them. New by-key methods store the key exactly as given. The reader and every view built by copying another view's keys use the by-key methods.
  • Labels at one coordinate are one station. An equate between spellings (a native P2, which cavern lowercases, tied to a file's P2) makes cavern write two labels at one point. Those are one station, so they share the lowercase key, as today. Only case variants at different coordinates form a case pair. A coincidence without an equate merges the same way; it draws identically.
  • The harvest reports spellings, not keys. A harvest runs cavern on the attached file alone, so it can't see a native station that shares the attachment's scope. With a cave-level file holding a lone P2 and a native P2 in the same cave, the file alone says p2 but the region solve has a pair (cave.p2 native, cave.P2 file). So Stations::names and fixedNames become each station's spelling: survey levels lowercased, the station name as cavern wrote it (K1, P2, p2). Everything that needs a solved key resolves scope + spelling against the region lookup with key(): exact for a pair member, lowercase for everything else. The harvest cache is in memory only (cwExternalCenterlineManager m_harvestCache), so the change needs no migration.
  • A fix on an attached file's station is written in the file's spelling. Today cwSurvexExporterUtils::writeFixStations writes *fix <typed name> under cavern's default *case tolower. A fix typed K1 or k1 for a Compass station K1 anchors a new station cave.k1, which cavern reports as an unused control point, and leaves K1 unfixed. This happens without any case pair; it was confirmed by running cavern on compass_excluded_lrud.dat plus *fix K1. The writer resolves the typed name to the file's spelling and wraps a fix whose spelling isn't all lowercase in *begin / *case preserve / *end, as cwSurvexExporterCaveTask's equate writer already does (about lines 543–556).
  • Duplicates are judged by resolved station. Two fixes, ties or list rows are duplicates when they resolve to the same station, not when their names lowercase to the same text. A fix on P2 and one on p2 of a pair are two fixes. A fix on native A1 and one on a1 are still one station and still a duplicate.
  • Scope of the fix. Stations whose names differ only in case. Out of scope, and recorded as follow-ups: labels that differ only in the case of a survey level (a Survex *begin Foo beside *begin foo under *case preserve); a dotted Compass name in a run whose separator is '.', where the reader can't tell the station part from the survey part (see "Separator ambiguity" in plans/EXTERNAL_FILE_PHASE3.html); and an "ambiguous station" warning for a name that matches a pair only by case.

C.8A trip under a source root refuses a survey file, and an existing one says its file is unsolved

  • Why. Found in the C.7 investigation. A source root (a .mak, .wpj or .svx attached as a node) can hold native trips. On an empty one, the survey editor's "Add from survey file…" (SurveyEditor.qml about line 448) attaches a file to that trip, and cwExternalCenterlineAttach::attach(cwTrip*) (about lines 596–621) accepts it. The driver never writes it: DriverTree::indexSourcedSubtree (cwSurvexExporterCaveTask.cpp about line 134) and the source-root branch of writeNodeBlock (about line 356) write only native trips, and cwScopeLabels' sourcedTripLabels (about line 36) labels only native trips. So the file draws nothing, and sourcedTripOperand's second branch (about lines 165–167) returns an empty operand, so writeEquateLine drops any tie to it without a word.
  • Owner decision (2026-10-27): refuse it. A trip under a source root takes no survey file, matching the node page's rule (NodePage.qml about line 616 hides "Add trip from survey file…" on a sourced node). To add such a file, the user puts it in the .mak, or attaches it to a node outside the source root and ties it with an equate. Supporting it (writing the trip's *include inside the source root's block under its own label) is a separate feature and out of scope.
  • Code. Hide "Add from survey file…" for a trip under a sourced subtree. Make attach(cwTrip*) refuse there with a reason. A trip that already holds such an attachment (from a project saved before this item) shows a warning on the trip and on the project's error list that its file is not solved and how to move it; nothing is removed or migrated.
  • New tests. attach(cwTrip*) on a native trip under a .mak source root returns the refusal and leaves the trip unchanged. A project built with such an attachment already in place loads, solves, and carries the warning; the source root's own stations still solve. A QML test checks the menu item is hidden on a trip under a source root and shown on a trip in a plain cave.

C.9A Survex source root keeps its settings to itself, and a file that uses *export still takes CaveWhere's ties and fixes

  • Why, settings. Found in C.7 and measured with cavern 1.4.22 (scratchpad experiments, one included file per setting, then a native trip with a 10 m leg due east). A setting at a Survex file's top level stays in force past its *include, and the source-root branch of writeNodeBlock (cwSurvexExporterCaveTask.cpp about lines 350–372) writes the native trips right after it in the same block. The trip writer (cwSurvexExporter.cpp about lines 56–100) always writes *data, *title, *date and *team, but writes a calibration only when it is nonzero and *units tape only for feet or yards, so a meters trip with no calibration takes the file's values. Measured leaks: *units tape feet (b at 3.05 m), *units tape 2 metres (20 m), *units compass grads, *units clino percent/grads, *calibrate tape/compass/clino, *declination 10 degrees, *flags surface (stations marked SURFACE), *flags duplicate/splay (leg flagged), *truncate 1 (native stations renamed, trip comes loose), *set decimal , (cavern fails on 10.5). C.7's B1 reset covers *case only.
  • Fix, settings. Write an anonymous *begin before writeIncludeSystem and *end after writeExternalInclude in the source-root branch, and remove B1's *case tolower line (about line 365). Measured: the wrapper closes every leak above, and leaves the file's own result unchanged (same stations, positions, flags, exports and *title in the 3D output; a node fix written before the wrapper still lands; a file with an extra or missing *end still gets cavern's "in this file" error, so it can't close the wrapper). Walls and Compass files reset their own settings at end of file; .mak output is already wrapped by the translator, and trip-level attachments by *begin <tripLabel>, so the source-root branch is the only place to change.
  • Why, exports. Found in the same investigation, and independent of case. Once any file uses *export, cavern checks exports across the whole solve. Then CaveWhere's own lines fail: a tie *equate sub.s1 native.a fails with "Station root.native.a not exported from survey root.native" (CaveWhere never writes *export), and a node fix on a file station the file doesn't export fails the same way. Worse, a second Survex attachment that never uses *export and solves alone (a cross-level *equate x.b y.c) fails too, as soon as the first one is in the project. The comment above writeEquates (about line 509) says no *export is needed, which holds only while no file uses it. The one fixture with *export (survex_root_and_block.svx) is used only by scanner tests.
  • Owner decision (2026-10-27): *infer exports on. Write it once at the top of the driver. Measured: it clears CaveWhere's ties and fixes and the second file's failure. Accepted cost: a file's own missing *export no longer errors in CaveWhere, though cavern still rejects that file when run on it alone. Writing *export lines was rejected: it covers only the blocks CaveWhere writes, so it can't reach a station the file keeps private, nor the second file's own equates. Update the comment above writeEquates to say why the line is there.
  • New tests. A Survex source root whose file sets, at its top level, each leaking setting above, with a meters native trip and no calibration: the native trip's stations land where its own shots put them, and stay underground and unflagged. A *case toupper root keeps B1's test passing after its reset line is gone. For exports: a Survex root that uses *export, with a native trip tied to one of its stations and a node fix on a station it doesn't export, solves; a second Survex root with an unexported cross-level equate solves beside it. Tests that check the exact driver text are updated for the wrapper.
  • Gate: cavewhere-test "[SurvexExport],[LinePlotManager],[SourcedFixtures],[Attach]".
