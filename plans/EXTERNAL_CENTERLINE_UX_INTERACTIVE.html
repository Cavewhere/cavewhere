What the Phase 2 lane reflects (all shipped)

  • Attach entry points: CavePage Add Trip split button (primary = native, menu = "Add trip from survey file…") and SurveyEditor's Add Survey Data equivalent on an empty trip. Cancel deletes the up-front-created trip.
  • Attach dialog: two-box Attach (Recommended) vs Import a copy choice — buttons, not radios. Import is Survex-only. Failure keeps the dialog open with the error in the picker; the in-project-source refusal (G2) reads exactly as shipped.
  • Trip panel order: missing-copy banner → file-error banner → floating banner → attached header → solve status → metadata → stations. Panel width 500, error log capped at 120 px, station list at 12 rows.
  • Provenance line's three states and both context menus (file: Show in Finder / Open; source: Reload / Show in Finder / Open — Reload enabled only when canReloadFromSource).
  • App-scope source-change banner (AppOverlay strip): Update all / Show / ✕ (dismiss is per-revision, session-only). Row Update disabled for "Source missing".
  • Replace dialog: explainer paragraph is the confirmation; overwrites edits (Q2 behavior change).
  • CavernOutputPage: status line, attached-centerlines rows, per-owner error (the only surface a cave-level owner has — F3), Input / Output / Loop Closure switcher over the mono pane.
  • Detach has no UI in Phase 2 — the C++ verb exists, no menu exposes it. Phase 3 adds the first Detach button (cave-level); trip-level detach should ship with the same pattern.

    • Phase 3 proposals encoded in the second lane

  • Naming. "Add cave from survey file…" under the Add Cave chevron — same verb family as Phase 2's shipped menu item, replacing the old prototype's "External cave…".
  • No Import box at cave level. The dialog carries a single Attach verb; whole-file native import is the existing Import Survex feature, not this dialog's job.
  • Scope-trip preview in the dialog. The scanner already resolves the block tree, so the dialog shows exactly which trips will be auto-created before the user commits. Silent auto-creation (old prototype resolution) stays — the preview is disclosure, not a picker.
  • Multi-cave root-file heuristic. When the entry resolves to several top-level blocks forming ≥2 disconnected networks, warn that the file is a project, list the included sub-files as one-click alternate targets, and still allow the attach. Signals available at scan time: top-level block count, connected-component count, include fan-out. This is the answer to "user points at the region master" — guidance, not refusal, since Phase 6 owns the real multi-cave mapping.
  • Cave-level detach cascade. RemoveAskBox-style inline confirm naming the auto-created trip count and the copied-file deletion, per the resolved question in the old prototype.
  • Declination column. Scope trips show an em-dash — cavern owns the math for the whole file; per-trip declination only exists where CaveWhere feeds the driver (trip-level attach without file declination).

    • Open questions this prototype should help settle

  • Heuristic thresholds: is "≥2 disconnected networks" the right trigger, or top-level block count, or both? False positives (one cave surveyed as two unconnected fragments) are real caves mid-exploration.
  • Should the sub-file suggestions in the heuristic be limited to direct includes of the entry, or any file in the closure whose subtree is a single network?
  • Does the Scope-trip preview need a station threshold display (blocks with 0 stations are skipped) or is silence fine?
  • Where does the cave-level attach live when the region master case truly is wanted as one cave (small two-entrance systems)? Current answer: the warning is dismissible by just clicking Attach.
