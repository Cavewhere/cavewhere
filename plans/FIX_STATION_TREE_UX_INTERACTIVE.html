Trade-offs

Grouped list

  • Each header carries its full relative path, so a scrolled-to row always shows where it lives.
  • Everything is visible at once; the jump strip reaches any node in one click.
  • One flat header style keeps owner controls readable at full width.

TreeView

  • Indentation shows the hierarchy at a glance and matches the Data page tree.
  • Collapsing a branch shortens a large project page to the parts in focus.
  • Short names leave more room for chips and badges on each node row.
Design notes
  • A fix shows on the node whose file holds it: entrances.svx's fixes sit under entrances.svx, never on the owner.
  • A node's page shows that node and its whole subtree, in depth-first order; the project root's page shows every fix in the project.
  • Nodes with no fixes still appear, labeled "No fixed stations", so the subtree shape matches the Data page.
  • The attachment owner (the root of an attached file tree) holds one choice: the system used to read fixes whose file names none. It applies to every bare fix in the attachment.
  • Child headers inside an attachment show the owner's choice read-only, with ↑ to the owner's page. Native folders and the project root carry no such control.
  • Cavern rejects a bare fix under an output projection until a system is named, so an unset owner shows "→ unset" in the danger color and a "⚠ N without coordinate system" badge on every header above it.
  • A fix whose file names its own system shows that system as plain text; the owner's choice leaves it alone.
  • Native rows are editable in place (coordinates, system, delete). Attached rows are locked and show the file's raw coordinate text; the 🔒 tooltip names the file to edit.
