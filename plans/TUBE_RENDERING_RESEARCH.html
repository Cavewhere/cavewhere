Passage Tube Rendering

Research for drawing cave passages as a continuous 3D tube that follows the survey centerline: what CaveWhere already has, how other cave tools and the graphics literature solve each sub-problem, and a recommended design with phases. Companion to plans/TUBE_RENDERING_RESEARCH.md; line references are from the tube_render branch, October 2026.

Create a continuous tube rendering that follows centerline data. It should generate cross-sections, then cross-sections are joined at passage junctions. Investigate whether the cross-sections should be z-aligned, or have pitch (a vertical pit would be an x-y plane). The cross-section is modified by scrap geometry to get the extent: plan scraps add to the width, profile scraps define the height. Splays should also change the cross-section geometry. If no scraps or splays exist, use LRUD data.

0. Summary

Inputs already existLRUD per station occurrence, splays per station occurrence, solved positions from cavern, and every scrap's outline, note stations, transform and view matrix are all in the snapshot the line-plot worker receives. Missing: the builder, a lit mesh render object, and a home for splay tips.
Frame: hybrid, blendedWalking passage uses a section plane perpendicular to the bisected shot direction with world-up as its in-plane up reference. As inclination steepens the reference blends into a rotation-minimizing frame, so a pit gets a horizontal ring with no singularity. Every shipping tool uses a hard threshold here.
One radial-sample modelLRUD, splays, plan scraps and profile scraps all become radial samples in the section plane; one star-shaped ring is fitted per cross-section. Plan scraps fill horizontal directions, profile scraps fill vertical ones, and a plan scrap over a pit yields the full footprint automatically.
Chains first, hulls laterChain the network into traverses (Loch), place rings in bisector planes, subdivide sharp bends, and end side arms with a dome cap pushed into the through tube. Manifold junction patches or an SDF watertight mode come later and only matter for translucency and cutaways.

3. Cross-section frame: z-aligned or pitched?

Both, blended by inclination. LRUD, plan-scrap widths and profile-scrap heights are all measured in a vertical section through the station, so for passage under about 45° a section plane perpendicular to the path with world-up as its in-plane up vector reproduces the measurement. In a vertical pit that section is meaningless; the useful one is horizontal, and the useful data are the plan footprint. A hard threshold leaves a visible kink where a passage steepens past it; a rotation-minimizing frame transported along the chain has no singularity at vertical, and blending toward it only when steep keeps the horizontal case exact.

t_in  = n(P_i − P_{i−1}),  t_out = n(P_{i+1} − P_i)        // one of them at chain ends
t_i   = n(t_in + t_out)                                     // bisector tangent; ring lies in the plane ⟂ t_i
incl  = asin(|t_i.z|)

up_h   = n(Z − (Z·t_i) t_i)                                 // world up projected into the section plane
up_rmf = doubleReflection(up_{i−1}, t_{i−1}, P_{i−1}, P_i, t_i)   // Wang et al. 2008
w      = smoothstep(θ_lo, θ_hi, incl)                       // e.g. 45° → 75°
up_i   = rotateAbout(t_i, up_h, w · signedAngle(up_h → up_rmf))   // pure RMF above θ_hi
right_i = t_i × up_i                                        // east for a northbound horizontal leg

Double-reflection step (r = up reference, t = tangent), exact for straight polyline segments:

v1 = P_i − P_{i−1};  c1 = v1·v1
rL = r_{i−1} − (2/c1)(v1·r_{i−1}) v1;   tL = t_{i−1} − (2/c1)(v1·t_{i−1}) v1
v2 = t_i − tL;       c2 = v2·v2
r_i = rL − (2/c2)(v2·rL) v2
  • Seed the chain's RMF from up_h at the first station with incl < θ_hi; if the chain starts vertical, seed at the first non-vertical station and transport backwards. A fully vertical chain seeds from world +Y (Loch's convention).
  • Sample angles are always measured in the local (right, up) basis: L at 180°, R at 0°, U at 90°, D at 270°. For horizontal passage that is the measured meaning. In a pit, LRUD gives no ring samples (decision in §7): L/R have no usable direction on a vertical shot and U/D are distances along the pit axis, so the ring comes from splays, a plan scrap, or the fallback chain (§4.4). U/D are still used at a pit dead end: the cap is placed D below the bottom station (or U above a top station) instead of flush with it. LRUD samples fade out with the same weight w that rolls the frame, so there is no second threshold.
  • Raw u/d are used as in-plane distances even on inclined passage, as every tool does; projecting by cos(incl) is only ~13% different at 30°.
  • Zero-length legs and unresolved stations break a chain; skip them rather than inventing a frame.

4. Cross-section sources: one radial-sample model

Every source contributes radial samples (angle θ, radius ρ, weight) in the section plane at a sample point S with frame (t, right, up). One star-shaped ring is then fitted from the samples. This is what makes "plan adds width, profile defines height, splays modify, LRUD fallback" a single mechanism.

4.1 LRUD → quadrant ellipse

For bin angle θ: a = cosθ ≥ 0 ? r : l, b = sinθ ≥ 0 ? u : d, ρ(θ) = a·b / |(b cosθ, a sinθ)| (the polar radius of the quadrant ellipse at angle θ; the parameter form |(a cosθ, b sinθ)| is the distance to the point at parameter θ, which lies at a different angle and bulges the diagonal bins when a ≠ b). Eight points of this are CaveView's oval and Loch's octagon; evaluating it at every bin works for any ring resolution. A missing dimension produces no sample for that quadrant pair rather than aven's fabs(-1) = 1. Use the LRUD occurrence from the chunk that owns the leg being skinned; a junction station has one per arm. The ellipse samples carry weight 1 − w (§3), so they vanish in a pit where L/R are meaningless and U/D run along the axis.

Facing (added after Phake Cave 3000). A station occurrence's left and right were measured facing one way: along its chunk, as aven draws a *data passage block, perpendicular to the horizontal chord between the station's chunk neighbors (the single shot at a chunk end; a vertical shot borrows the nearest facing in the chunk, else north). The record's right direction R is that facing turned clockwise, and a ring takes each wall's component across itself: with c = R · right of the ring frame, the ring's right axis reading is r·c and its left l·c, swapping when c < 0. A leg walked backwards needs no left/right swap, and a leg leaving a junction at an angle to the chunk sees the wall foreshortened instead of drawn full-size across itself (at a6, chunk 1's 5 m left wall was a 5 m fin on the arm a4→a6 and a second 5 m fin, 75° away, on the through chain a7→a6).

Shaft readings (added after Phake Cave 3000). Surveyors record a pit's depth as the down, or an aven's height as the up, of the stations next to it — including a dead end with no leg into the pit (a12: L 0, R 2, U 8, D 35) and the station one leg before the pit (a4: D 23). An up/down reading more than kShaftRatio = 3 times the larger of the station's width (l + r) and the median of the same reading at its neighboring stations is a shaft, not a wall: the ring uses the neighbor median (or half the width), the raw value still places a steep dead-end cap, and a ShaftReading warning names the station. An up/down reading that runs along a leg leaving the station (the lip and bottom of a surveyed pit) is dropped from the ring for the same reason and, on a gentle leg, refilled from the leg's other end.

4.2 Splays → projected tips

v = T − S;  along = v·t;  q = v − along·t
keep if |along| ≤ max(½ · min(adjacent leg lengths), kMinAlongTolerance)
     and |q| > kSplayParallelFactor · |along|       // drop splays shot down the passage (TopoDroid rule)
θ = atan2(q·up, q·right);  ρ = |q|;  weight = 1

Tips come from LinePlotCaveData::splayTips(); the manager must start keeping them. Mid-shot samples take tips from both end stations whose along lands near the sample.

4.3 Scraps → page-space ray casts

For each scrap whose note stations include the sample's station (both stations of the shot for mid-shot samples), work in page space: the paper-meter frame in which the outline is a plain 2D polygon and the morph is locally linear.

pageOf(noteNormalized) = metersPerDot · pixels(noteNormalized)         // paper meters
toCave  = noteTransform.matrix(scale, northUp)                         // paper m → cave m
V       = scrap view matrix (Plan: I; ProjectedProfile: fixed; RunningProfile: Data(from,to))
S_page  = pageOf(noteStation(S))                                        // or lerp of two note stations at s

for each ring direction d_k (world unit vector in the section plane):
    d_view = (V · d_k).xy                                               // how much of d_k the page can see
    c = |d_view|;  skip if c < kMinPageComponent (≈ 0.5, within 60° of the page)
    d_page = n(toCave⁻¹ rotation · d_view)
    hit    = nearest intersection of ray (S_page, d_page) with the outline polygon
    if hit:  ρ_k = distance(S_page, hit) · scaleToCave / c;  weight = c
  • Mid-shot samples: S_page = lerp(page(A), page(B), s) with S_world = lerp(P_A, P_B, s) matches how morphPoints densifies shots. Sampling every kSampleSpacing (the 1 m default setting) is what makes the tube follow curved drawn walls. Only sample where both stations are in the scrap and S_page lies inside the outline.
  • Several scraps over one station: keep every sample; the fit takes the max per bin. A plan scrap and its profile fill different bins, so they never compete.
  • Projected profiles read the ceiling and floor at the station's projected location, which is exact where the passage runs along the profile plane and approximate as it turns. Running profiles have no such issue.

4.4 Priority and fallback

Build the sample set from everything available, then fit. If fewer than about four bins are filled after scrap and splay samples, add the LRUD ellipse. If still too sparse (no LRUD, or a pit where LRUD contributes nothing): borrow the nearest ring along the chain that had real samples (Compass "Expand Passages"), then kDefaultRadius, flagged so the UI can show "no passage data" differently. This is the requested "if no scraps or splays exist, use LRUD" with one more rung so chains never tear. A LRUD-only pit therefore renders at its lip ring's width, which is the honest answer to "nobody measured it."

4.5 Ring fit

  • N bins (16 default; 8 suffices for LRUD-only, 24–32 for dense splays), centers θ_k = 2πk/N in (right, up).
  • Per bin ρ_k = max(ρ), optionally a trimmed max when three or more splays share a bin.
  • Empty bins interpolate angularly from the nearest filled bins. Optional concavity clamp against single-splay spikes; its outward mirror, kOpeningRatio, catches scrap openings (§5.6).
  • Emit N vertices S + ρ_k (cosθ_k right + sinθ_k up). Same N and θ_0 everywhere → fixed zipping topology.

4.6 Units and conventions

LRUD → cwUnits::convert(toDouble(), trip.calibrations.distanceUnit(), Meters). Splay tips and positions are already meters. Scrap distances are paper meters × note-transform scale. L/R follow chunk order; when a chain traverses a chunk backwards, swap them for that leg.

5. Joining rings into a tube

5.1 Chains

Build an edge list from every chunk's shots (from, to, chunk id, shot index; positions from the cave's lookup). Then chain like Loch:

  1. Compute degree per station. Seed chains from odd-degree stations first (dead ends, then 3-way junctions), then even-degree.
  2. From the current edge end, continue along the unused edge with the largest dot product with the current direction. Stop at a dead end (Flat end) or when the node has no unused edges but other edges exist (Round end at a junction). Remaining edges at a junction seed new chains starting there.
  3. Loops: a chain whose last node is its first closes on itself.

5.2 Along a chain

  • Rings at stations use the bisector frame, which is the miter: the ring lies in the bisecting plane of the two legs, so side quads between consecutive rings meet with no gap and no fold.
  • A ring in the bisecting plane is stretched by 1/cos(φ/2) for turn angle φ. Above about 60°, use Compass corner rounding instead: truncate both legs ε before the corner, insert one or two interpolated sample points with lerped rings, frame them by RMF. This also removes Loch's fold-back failure.
  • Mid-shot samples are just extra rings with t = leg direction and transported up.
  • Side quads → two triangles each, outward winding. Phase 0 shades flat from screen-space derivatives in the fragment shader, so the vertex layout is position only and every generated quad is visible as built (decision in §7). A Normal attribute with averaged vertex normals is a later "smooth" option; the builder owns the geometry, so computing them is a small addition.

5.3 Junctions: the clean merge

Phase 0 and 1 closed each arm with a dome inside the through tube and let the depth test hide the overlap. That fails translucent and cut-away rendering (the interior faces show) and fly-throughs (the dome is a bump on the wall), and on Phake Cave 3000 the dome itself read wrong: an arm whose last ring is borrowed from a neighbor pushed a deep box across the through passage. The junction is now a separate stitch pass between ring fitting and meshing. It works on ring columns only, so LRUD, splay and scrap rings go through the same code; it was reviewed in 2D on 18 cases in plans/TUBE_JUNCTION_GALLERY.html (local file).

  1. Fill. The arm's section is carried from the through's near wall to its far wall: fill = armTube ∩ extrude(through, n), with n = t_through × t_arm. The arm tube is the arm's own rings read as a solid, its last ring continued past the junction; the extrusion sweeps each through ring's polygon along ±n. For a side passage n is vertical, so the fill is the arm's section limited to the through's plan width; for a pit dropping into a passage n is horizontal across the passage, so the fill is the pit's section between ceiling and floor; for a passage entering a shaft it is the passage's section between the shaft's near and far walls.
  2. Grow. Every through ring near the junction extends each column as far as its ray stays inside a fill. A trench floor dips across the full width to the far wall; a tall arm makes a chamber across the junction; an arm smaller than the through changes nothing. Growth tapers with the arm's outline, so there is no blend constant.
  3. Trim. Each arm column is cut where it first enters the union of the through tube and the fills. The cut points form the mouth loop, which lies on the through surface by construction.
  4. Cut and zip. The through quads inside the mouth loop (in ring × column parameter space) are removed and the window's boundary is zipped to the mouth loop. The result is one closed, consistently wound surface with no faces inside either tube.

Known limits: two arms whose windows share through quads fall back to a fan-capped overlap with a warning; a shaft's far wall is flattened across an entering passage's width; grazing joins give a long mouth. A fillet at the mouth crease is cosmetic and can come later. Figure 8 shows the geometry before this pass: the dashed pit extension is what the trim now removes, and the passage ceiling inside the pit's footprint is what the window cuts out.

5.4 Junctions, phase 2 options

  • Hull patch (B-Mesh / Blender Skin / SQM): at each junction take the nearest ring of every incident chain, compute the 3D convex hull of their vertices, delete faces inside an incident ring's disc, stitch the openings to the tubes. Manifold, and literally "cross-sections joined at junctions". Needs a QuickHull (~300 lines, no new dependency) and concave-junction cleanup.
  • SDF union + marching cubes / dual contouring: per leg a distance to the swept ring, min across legs, optional smooth-min at nodes, on a sparse voxel grid; isosurface and decimate. Watertight and degree-agnostic; dense output, loses ring correspondence. The ring pipeline is reused as the shape definition, so this is an additive mode.

5.6 Concave outlines and un-surveyed side passages

Every real scrap outline is concave: walls wiggle, passages neck down, and sketchers draw alcoves, side leads and whole side passages that have no survey station in them. The question is what the ring model does at those concavities, and especially at a split: a lobe of the outline that is really a passage with no centerline.

What the scrap pipeline does today

  • The outline is one QPolygonF (cwScrapData::outlinePoints) and cwScrap enforces no convexity or simplicity on it. Concave is the normal case; self-intersecting outlines are accepted too.
  • The mesh handles concavity completely. cwTriangulateTask::createQuads classifies grid quads with containsPoint(Qt::OddEvenFill) at the four corners (full quads) or an outline-edge crossing (partial quads). Partial quads go through QPolygonF::intersected, addPointsOnOverlapingEdges, createSimplePolygons and cwTriangulate::Process, an ear-clipping triangulator that takes any simple polygon. A failed clip is ignored (Q_UNUSED(couldTrianglate)), and a self-intersecting outline fills odd-even. cwTriangulateTask.cpp:387-574, 1379
  • The morph treats a lobe as texture, not as a passage. Each grid point is positioned by an inverse-square-distance blend (morphPoint) of the ten nearest pseudo-stations (maxClosestStations), with every shot densified every 0.5 m (buildStationsWithInterpolatedShots). The outline-visibility test stationsVisibleToPoint exists but its call is commented out, so a lobe with no station inside is pulled by whichever main-passage pseudo-stations are nearest: a side passage in a plan scrap renders as a flat sheet hanging off the main passage at its neighbors' interpolated Z (then smoothZ, 2 m radius); in a running profile a lobe lies in the bracketing shot's profile plane. Nothing knows the lobe is a passage. cwTriangulateTask.cpp:928-963, 1230-1262 · cwTriangulateWarpingData.h:15

So concave scraps are a solved problem for the sheet and an unsolved one for the tube: the tube has to decide where the passage is, which the sheet never had to.

What the ray-cast ring does at a concavity

The ring is star-shaped around the sample (nearest hit per direction, §4.3), so:

  1. Neck or pinch: the nearest hit reads the neck. Correct.
  2. Pillar drawn by looping the outline inward: rays hit the pillar wall, the ring narrows on that side. Acceptable.
  3. Sample outside the outline (the sketched wall misses the station): containsPoint is false, the scrap is silent there and splays/LRUD take over. Keep it, plus a warning so the user can see which scraps miss their own stations.
  4. Opening: a lobe, alcove or side passage whose mouth faces the sample. The ray through the mouth hits the lobe's far wall instead of the main wall. In a plan scrap every ring direction with a right component projects onto that same page ray (§4.3: d_page is the page-side direction for L, both shoulders and everything between, each scaled by 1/c), so the whole side of the ring is pushed out together and the angular neighbors cannot catch it. Sweeping the mid-shot samples past the mouth gives a run of such rings: a slab-shaped fin where the side passage should be (Figure 9a). This is the failure case of the model.
  5. Profile lobes are vertical openings, a dome in the ceiling or a pit in the floor drawn as a lobe. Same spike, in the up or down bins.

Options

A. Clamp the opening (phase 2, day one). A scrap contributes at most two page rays per sample (plan: ±right; profile: ±up), so compare each ray's hit distance with the median of the same ray over the ±kOpeningWindow (3) neighboring samples along the shot. A hit above kOpeningRatio (≈1.8) times that median "sees through an opening": replace it by the interpolation between the nearest unflagged samples on either side, and let the ring bins that share the ray follow. This is the along-the-chain mirror of the angular concavity clamp in §4.5. The lobe vanishes from the tube and still shows in the scrap layer. Record each clamp as Warning{ScrapOpening, scrapId, station, s, direction}; those warnings are the detector for option B.

B. Walk the lobe: a synthetic chain (recommended, phase 2.5). Treat an opening as a junction whose third arm is a chain with no survey shots, and let the ring machinery sample it.

  • Detect. Along each shot, for each page-space side direction (plan: ±right; profile: ±up), look at ρ(s) over the mid-shot samples. A mouth is an interval [s₀, s₁] where ρ jumps by at least kOpeningRatio and comes back, whose page width is at least kMinMouthWidth (≈ max(2 × sample spacing, 0.75 m)) and whose depth through the mouth is at least kMinLobeDepth × mouthWidth (1.0; a bay shallower than its mouth is a wide spot and keeps the clamp). The mouth center M_page is the midpoint on the wall line; the start direction is the side direction.
  • Walk. From M_page step kSampleSpacing. At each step cast the two rays perpendicular to the current direction, move the center to the midpoint of the hits (the local medial point), turn toward that drift with the turn clamped to kMaxTurnPerStep (≈30°), and record (center_page, halfwidth_page). Stop when the forward ray hits within one step (dead end → cap), when the center leaves the outline, when the walk comes within kRejoinDistance of a surveyed shot of the same scrap (a bypass loop: finish at that second mouth and join there too), when the width exceeds kMaxLobeWidthRatio × the mouth (a chamber: stop and cap), or after kMaxLobeSteps. Openings seen while walking recurse once.
  • This is the medial axis of the outline computed on demand along one branch, with the ray caster the design already has. A general medial axis or straight skeleton (CGAL, Boost.Polygon Voronoi) would give the same branches plus a pruning problem, and none of those libraries are in conanfile.py. A raster distance transform via the existing cwSketchScrapRasterizer is the fallback if the walk ever proves insufficient.
  • Place in world. Map page points through the same morph the scrap uses (cwTriangulateTask::morphPoint with buildStationsWithInterpolatedShots), so the synthetic centerline lands exactly where the scrap texture lands. Width comes from the two page hits. A plan lobe has no height, so inherit the junction sample's up/down bins (profile, splays or LRUD) and hold them constant along the lobe, optionally tapering toward a dead end. Profile lobes mirror this: height from the hits, width inherited from the mouth ring. Where a plan lobe and a projected-profile lobe describe the same side passage, match them by s along the shot within kMouthMatchTolerance and combine width with height.
  • Join. The synthetic chain is an ordinary junction arm in §5.3 terms: first ring at the mouth, pushed ½ρ into the through tube and dome-capped inside it; the phase-4 hull or SDF applies unchanged. Output is the same cwPassageTubeMesh, with the vertex range tagged synthetic = true so the shader can tint it and the UI can toggle it, since its height is inherited rather than measured.
  • Splays that point into the lobe already land in the spiking bin; inside the mouth sector they become samples for the synthetic chain's first rings, otherwise they stay ring samples at their station.
  • Tests. Rectangular outline with a rectangular side bay → one synthetic chain with the expected ring count and inherited height; bay shallower than its mouth → clamp only, one warning; U-shaped bypass → chain ends at the second mouth; self-intersecting outline → no crash, warnings only.

C. Implicit footprint extrusion (phase 4 alternative). The plan footprint times the height profile is a 2.5D solid: rasterize the outline's signed distance in page space, extrude between floor and ceiling heights taken from the rings, union with the tube SDF, marching cubes. Lobes come for free with no detection and no synthetic centerline, at the cost of ring correspondence and a dense mesh. It gives the phase-4 SDF option a second justification but is heavier than B for the common case.

Decided (§7): A in phase 2 (one guard in the ring fit plus a warning), B as phase 2.5 behind a followScrapLobes tube setting, C stays optional.

6. Architecture

6.1 Builder and manager

  • cwPassageTubeBuilder: static build(const cwCavingRegionData&, const QHash<QUuid, cwStationPositionLookup>&, const QHash<QUuid, cwSplayTipsByStation>&, const Options&) → cwPassageTubeMesh. Edge list → chains → frames → samples → rings → mesh, every step a free function over value types. Follows the worker rules (.at(), value snapshots, no shared_ptr<QList>).
  • cwPassageTubeManager (cwUpdatable), registered with UpdateCoordinator->add(PassageTubeManager, {LinePlotManager}) cwRootData.cpp:202-207. Runs the builder through an AsyncFuture::Restarter under cwConcurrent::run, delivers via observe(...).context(this, …). Triggers: stationPositionInCavesChanged and the scrap signals cwScrapManager already listens to cwScrapManager.cpp:618-645, debounced, so an outline drag updates the tube without re-running cavern.
  • Splay tips: add cwCave::setSplayTips / splayTips() next to the position lookup and populate it in cwLinePlotManager::updateLinePlot.

A separate manager rather than building inside cwLinePlotTask: the line-plot worker has every input, but it only runs on survey edits, and re-running cavern on every scrap outline drag would be wasteful. The scrap manager has the same relationship to the line plot and is the model to copy.

6.2 Render object

  • cwRenderPassageTube: setMesh into cwTracked<GeometryState>; color/opacity in cwTracked<RenderState>; setRangeVisible over index ranges with a published mask (copy cwRenderLinePlot::setRangeVisible); no registerPickable. Created in cwRegionSceneManager after the line plot.
  • cwRHIPassageTube: Position + Normal layout, immutable vertex/index buffers, small std140 uniform block (color, opacity, light), mask gated on entryVersion, cwLedgeredBytes under a new category, Opaque pass, pipeline keyed on context.renderData, globalCameraBinding = 0, worldBounds() = mesh AABB.
  • PassageTube.vert/.frag: GlobalBlock at binding 0 copied from LinePlot.vert, tube block at binding 1, view-space headlight with an ambient floor (aven uses 0.7 + 0.3·dot). Phase 0 computes the normal in the fragment shader as normalize(cross(dFdx(viewPos), dFdy(viewPos))) (flat shading, needs the "150,300es" shader block), flipped by gl_FrontFacing so the inside of the tube lights correctly, and the pipeline sets CullMode::None because the camera is routinely inside the cave (§5.7); a Normal attribute path is added with the smooth option. For inspecting the generated mesh, a second pipeline with QRhiGraphicsPipeline::PolygonMode::Line gives a wireframe overlay on the desktop backends (gate on QRhi::isFeatureSupported(QRhi::NonFillPolygonMode); GLES lacks it).

6.3 Visibility and settings

  • Per-trip keyword item Type="Passage", created the way "Splays" is cwLinePlotManager.cpp:378-397, cwTrip.cpp:540-548, with a cwVisibilityProxy subclass calling setRangeVisible. Tubes then filter by cave/trip/date alongside the line plot, and this is how tubes and scraps coexist: independent layers the user toggles (decision in §7), with no special-casing in the builder.
  • A whole-object "Passage Tubes" toggle in the View menu next to "Scraps Visible" qml/FileMenu.qml:157-165.
  • Tube settings (decision in §7): a persisted settings object under cwSettings cwSettings.h:27-33, either new properties on cwRenderingSettings or a sibling cwPassageTubeSettings with the same kDefault* + QSettings pattern cwRenderingSettings.cpp:22-30, exposed on qml/RenderingSettingsItem.qml. Properties: sample spacing along shots (meters), ring resolution (bins), and later the blend angles, default radius and subdivide-bend angle. A change triggers a tube rebuild only, never a cavern run.
  • Export (decision in §7): the tube is an ordinary keyword layer, so map export shows exactly what the keyword visibility shows. The user hides the tube from an export by hiding it in the layering, the same as any trip or scrap; captureHiddenObjectIds() stays untouched.

6.4 Tests

  • test_cwPassageTubeBuilder.cpp: straight leg with LRUD → ring at P ± r·right ± u·up; 90° bend → bisector frame and subdivision; vertical shot between horizontal legs → continuous up, horizontal pit ring, no NaN; chain assignment at 3-way and 4-way junctions; L/R swap on reversed chunk traversal; plan-scrap ray cast on a rectangle returns the drawn half-widths; profile-scrap ray cast returns the drawn height; splay binning with an outlier; missing LRUD falls back to neighbor ring then default radius. From the artifact checklist (§5.7): a pit entered and left on different bearings keeps right_i · right_{i−1} > 0 at every sample (no twist); a tight bend with a wide ring produces no vertex behind the previous ring's plane (no fold); hiding one trip of a two-trip chain leaves a capped end; 0 0 0 0 LRUD falls back and a single zero gives kMinRadius; a 0.3 m shot with 1 m spacing emits two distinct rings; a scrap that closes across the passage gives no pinched ring at its end; a scrap ending mid-chain produces a cross-faded transition and a SourceChange warning.
  • test_cwPassageTubeManager.cpp: load a small region, wait for line plot and tube; edit a scrap outline point → tube rebuilds without a new cavern run; keyword visibility hides a trip's index range.
  • Front-end render tests like test_cwRenderPointCloud.cpp, registry sync through CwRhiSceneTestAccess, a manual screenshot once the look is settled.

7. Decisions and open questions

Decided (October 2026)

  1. Pit LRUD: U/D only. On a near-vertical shot L/R have no usable direction and U/D are distances along the pit axis. LRUD therefore gives no ring samples in the pit regime (weight 1 − w); the ring comes from splays, a plan scrap, or the fallback chain, and U/D set the cap offset at a pit dead end (§3, §4.1, §4.4).
  2. Opaque. CaveWhere draws nothing translucent, and the tube keeps to that. Translucency is dropped from phase 4; junction hulls remain only as a cutaway/export quality option.
  3. Scraps and tubes are independent layers. A plan scrap is a sheet at station height inside the passage, so an opaque tube hides it from outside. Rather than skipping tubes where scraps exist (Therion's walls auto), both are keyword-filtered layers the user toggles (§6.3). Skipping can be added later as an option.
  4. Faceted first. Phase 0 flat-shades from derivatives with a position-only vertex layout so the generated geometry is visible as built; a wireframe overlay is the debugging aid; smooth normals come later as an option (§5.2, §6.2).
  5. Sampling is a setting. Sample spacing along shots and ring resolution live in persisted CaveWhere settings on the rendering settings page; a change rebuilds the tube without a solve (§6.3). Defaults: kDefaultSampleSpacing = 1.0 m and kDefaultRingResolution = 16.
  6. Map export follows the keywords. Tubes carry keywords (per-trip Type="Passage" items, §6.3) and are shown or hidden through the layering like everything else; export renders whatever the keyword visibility shows, with no tube-specific entry in captureHiddenObjectIds().
  7. Scrap lobes: clamp, then walk. Option A (clamp + ScrapOpening warning) lands with scraps in phase 2; option B (walk each opening into a synthetic chain joined at a synthetic junction) follows in phase 2.5 (§5.6).

Open

  • Synthetic chain appearance. Whether a walked lobe's inherited height is tinted or drawn like measured passage, and the kMinMouthWidth / kMinLobeDepth thresholds that separate "side passage" from "wide spot". Pick in phase 2.5 and tune by eye.

8. Phases

  • Phase 0

    LRUD tubes, aven-parity and better. Builder (edges, chains, blended frames, LRUD ellipse rings, bisector joins, bend subdivision, dome caps at arms, fan caps at dead ends with U/D offsets in pits and at trip boundaries, angle unwrap and twist distribution, per-vertex fold-back fix, ring merge below kMinRingSpacing, 0 0 0 0 LRUD as absent with kMinRadius/kMaxRadius guards, shorter-diagonal quad split), manager, render pair, flat-shaded two-sided shader without culling, wireframe overlay, View-menu toggle, tube settings with sample spacing and ring resolution, builder unit tests. Visible on every project with LRUD.

  • Phase 1

    Splays. Keep splay tips on cwCave; projected-tip samples; binning and outlier guard; synthetic-splay tests.

  • Phase 2

    Scraps. Page-space ray casts for plan, running-profile and projected-profile scraps; mid-shot sampling; opening clamp with ScrapOpening warnings (§5.6); closing-edge rejection and source cross-fade (§5.7); rebuild on scrap edits without a cavern run; rectangle-outline tests.

  • Phase 2.5

    Scrap lobes. Walk detected openings into synthetic chains (§5.6) behind a followScrapLobes setting; inherited height, tinted as synthetic; bay / bypass / self-intersection tests.

  • Phase 3

    Integration polish. Per-trip "Passage" keyword visibility, memory ledger category, culling bounds, export check (keyword-hidden tubes stay out of exports), warnings surfaced, manual screenshot.

  • Phase 4

    Junction geometry (optional). Convex-hull junction patches or SDF + marching cubes watertight mode, for cutaways and solid export; smooth normals as a shading option.

  • Later

    Read img_XSECT from the .3d so externally included .svx passage data renders too; splay-based scrap morphing can reuse the same per-station samples.
