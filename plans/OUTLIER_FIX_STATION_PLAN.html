Detect Outlier Fix-Station Coordinates

Find fix stations whose coordinate is a data-entry error (wrong CS, wrong UTM zone, transposed digits) — the class of mistake that silently blows up the whole 3D render — and surface it where the user can act on it. Grows out of #596 (removing the confusing "Recenter world origin" button).

Origin of this work. #596 asked "what does Recenter world origin do, and should we remove it?" It manually recentered the world origin — an internal float-precision offset — with no visible effect, so it was removed (done menu item deleted from DataMainPage.qml, test renamed). That button was a manual knob for a problem the app should detect on its own: a coordinate so wrong it breaks rendering. This plan builds that detection.

2. Problem & precision math

CaveWhere subtracts a world origin from every coordinate before it reaches the GPU, so that survey data (UTM coordinates in the millions) fits inside float (32-bit) precision in the shaders. The origin is auto-computed on the first line-plot solve as the centroid of all fix stations (cwLinePlotManager.cpp:691 → cwCavingRegion::recomputeWorldOrigin()).

A float has a 23-bit mantissa → relative precision 2⁻²³ ≈ 1.19e-7. Absolute error at coordinate magnitude d is d × 1.19e-7. Choosing a 1 cm budget:

d_max = 0.01 m / 1.19e-7 ≈ 84,000 m  ≈ 84 km

So any rendered vertex more than ~84 km from the origin has >1 cm of jitter. A single typo'd fix — wrong UTM zone or a transposed digit — lands hundreds of km out. Because the origin is the mean, that one point drags the origin off the real data and inflates the scene bounding box, so the auto-framed 3D view shows the real cave as a sub-pixel dot. The user sees an empty or garbage render with no explanation.

Not a generic "your survey is too big" warning. A region that legitimately spans >84 km can't be helped by recentering, and warning about it on every solve is unactionable noise. We detect only the isolated outlier — a fix far from the cluster of every other fix — which is almost always a typo and is fixable. The relative test (§4) naturally ignores legitimately spread-out surveys.

3. Altitude: a dedicated validator, owned by the region

"Outlier" is defined relative to the whole survey, so detection needs every cave's fixes at once — a region-scoped computation. But cwCavingRegion is already the app's busy root model, and this work is a distinct responsibility (gather + reproject, median math, per-cave cwError lifecycle, a summary property, signal wiring). So it lives in a new class, cwFixStationValidator, owned by the region rather than baked into it.

The region keeps only what is genuinely its own state — writing the world origin to geoReference — and delegates everything else. The validator gathers each cave's fixes, reprojects into the region's global CS (the reprojection logic that recomputeWorldOrigin() does today moves here), classifies, and attributes any flag back down to the owning cave's existing errorModel().

The per-cave cwError lifecycle copies the proven pattern from cwTripCalibration.cpp:329-360 (the declination warning): keep the current cwError per flagged cave, append() it, setData(MessageRole) for in-place text updates, and remove() when the coordinate is corrected — with a stable errorTypeId so it is identifiable and user-suppressible. Severity is Warning (survex still runs; warnings are suppressible — the escape hatch for a genuinely remote fix).

4. Detection algorithm

Working in the region's global CS, on the reprojected candidate points:

  1. Robust center c = component-wise median of all candidates.
  2. Robust scale s = median of the distances |pᵢ − c| (a typo-proof cluster radius).
  3. Flag candidate i when |pᵢ − c| > max(kOutlierFloorMeters, kMadMultiplier × s).
  4. Run only when there are ≥ kMinFixesForDetection fixes (need a cluster to be an outlier from).
Why the max() of two thresholds. A flagged point must exceed both:
  • the precision floor (~84 km) — below it, rendering is fine, so nothing to flag; and
  • k × cluster-radius — in a legitimately spread survey the radius s is large, the threshold rises, and nothing is flagged. Only a point far from an otherwise tight cluster trips it.
This is precisely the discriminator that separates "typo" from "big survey."
The outlier trips both thresholds; the good cluster trips neither. Two legitimate caves 100 km apart would form two clusters — a large s, nothing flagged.

This math is the pure static cwFixStationValidator::classifyCandidates() from §3 — no region, no side effects, so the threshold logic is unit-testable with hand-built candidates. currentClassification() wraps it with the gather/reproject step. Both recomputeWorldOrigin() (via robustWorldOrigin()) and the per-cave attribution run the same classification logic. Note they do not share a single gather: each call to currentClassification() re-runs gatherCandidates(), so a solve that recomputes the origin and then revalidates (Commit 3) gathers twice. That is acceptable at solve-time (not per-frame); if Commit 3 wants one gather per solve, cache currentClassification()'s result and invalidate it on the same triggers that drive revalidate().

5. Robust world origin behavior change

Today recomputeWorldOrigin() sets the origin to the mean of all fixes. The mean is not robust — one outlier drags it, so the good geometry ends up far from the origin and the whole scene jitters / frames wrong. Fix: compute the centroid from inliers only (equivalently, the median). Then the origin sits in the real cluster, the good geometry renders crisp and centered, and only the bad station flies off — which is the behavior we want for diagnosis, and what makes the render-view banner meaningful.

Touches tested behavior. test_cwCavingRegion_worldOrigin.cpp has "averages multiple fixes" asserting the mean. For clusters with no outlier the inlier-centroid equals the old centroid, so that test is expected to still pass; a new test asserts an outlier no longer drags the origin. Isolated as its own commit so it can be dropped if you'd rather keep mean semantics — at the cost of the render-view banner being far less useful (scene stays garbage rather than showing one station flown off).

12. Commit 6 — Detecting the few-caves case post-Commit-5 follow-up

Implemented (dev_3, uncommitted; C++ + QML gates green). Resolutions of the open decisions below:
  • Domain bound → decision (a). New cwCoordinateTransform::isWithinDomain(cs, point) queries proj_get_area_of_use() for the CRS's lon/lat bbox, inverse-projects the fix to geographic, and flags it when the result is non-finite or lands more than a 5° margin outside the bbox. PROJ stays encapsulated in cwCoordinateTransform; the validator never includes <proj.h>. Un-checkable CS (empty / unparseable / unknown area of use) returns within — it never cries wolf, deferring to the cluster rule.
  • Distinct errorTypeId. Domain warnings use kDomainErrorTypeId = 597 (cluster keeps 596), so the two kinds coexist on one cave and are suppressed independently. setCaveWarning() is now keyed by id; a small updateWarningTracking() keeps m_cavesWithWarning correct while a cave carries either.
  • Part B. kMinFixesForDetection lowered 4 → 3; domain-bad fixes are pulled out (Classification.domainOutliers) before the cluster median, and are excluded from robustWorldOrigin() via the inlier set.
  • Summary/overlay. A domain outlier names the culprit first; outlierCount now totals both kinds; the render-view message stays generic ("looks wrong").
  • Inline on the FixStationPage (follow-up, additive). Because the domain check is pure per-fix (no neighbours), it also surfaces right on the row that owns the coordinate: a read-only DomainErrorRole on cwFixStationModel (computed from the row's own input CS via isWithinDomain, empty when in-range or when the CS is blank) drives a warning icon + tooltip in both the wide and narrow row delegates. A blank input CS defers to the region-level 596/597 path; the cave banner and world-origin exclusion are unchanged (kept per the "both altitudes" decision).

Commits 1–5 flag an outlier only when a majority of the pooled fix stations form one tight cluster and a minority stray from it. The realistic data shape is the opposite: 2–3 caves, one with a typo, each cave carrying only one or two fixes. The pooled-cluster rule catches almost none of it, because the component-wise median center only sits on the real data when a majority is clustered there.

Key insight. "Outlier relative to a cluster of other fixes" is the wrong question when there are only 2–3 caves. A fix-station coordinate is wrong in ways that need no neighbors to prove. So make a per-fix check the primary signal (Part A), and demote the cluster rule to a complementary secondary signal (Part B).

Part A — Per-fix CS-domain check primary signal

  • For each gathered fix, independent of clustering, test whether its coordinate is plausible for its declared input CS. A transposed-digit UTM easting (1478000 in UTM 13N) falls outside the projection's valid domain; a fix that inverse-projects to a geographic location outside the CRS's area-of-use — or that makes PROJ error outright — is almost certainly a typo. This catches the single-cave, single-fix case, which is the whole point.
  • Open decision — how to bound the domain. (a) PROJ area-of-use via proj_get_area_of_use() (needs a small accessor on cwCoordinateTransform), then bounds-check the reprojected lon/lat against it; or (b) round-trip inverse-project to EPSG:4326 and flag NaN / |lat|>90 / |lon|>180 / gross out-of-zone. Prefer (a) if the accessor is cheap; (b) is the fallback. Both are CS-agnostic — no hardcoded UTM ranges.
  • Attribution. Same per-cave errorModel Warning as Commit 3, but a distinct message, e.g. "Fix station "X" has a coordinate outside the valid range for its coordinate system — check for a transposed digit or the wrong CS/zone." Open decision: a distinct errorTypeId vs. reusing 596 (affects independent suppression of the two warning kinds — lean toward a distinct id, which also motivates the §11 errorTypeId registry).
  • Origin coupling. A domain-bad fix must also be excluded from robustWorldOrigin() — fold it into Classification.outliers so the inlier centroid ignores it, otherwise the typo still blows up the world origin even though it's now flagged.

Part B — Relax the cluster rule secondary signal

  • Lower kMinFixesForDetection (4 → 3, possibly 2). With an odd count the component-wise median lands on the majority, so "2 good + 1 bad" is caught; the pathological case is the even balanced split (2 vs 2), which Part A's domain check covers instead.
  • Keep the ~84 km float-precision floor (kOutlierFloorMeters) and kMadMultiplier. Document in the code that the cluster rule is best-effort for small N — the domain check is the reliable path; the cluster check adds the wrong-CS-but-in-domain typo (declared the wrong zone, numbers are in-range) when a majority reference exists.
  • Ordering. Run Part A first and drop provably-bad fixes before computing the cluster's median center, so a wild typo doesn't pull the center off the real data and mask a second, subtler outlier.

Tests (extend test_cwFixStationValidator.cpp)

  • 2 caves, 1 fix each, one out-of-domain → flagged (Part A; the cluster rule alone can't, N<min and no majority).
  • 3 caves, 1 fix each, one in-domain-but-wrong-CS → flagged via the relaxed cluster rule (Part B; odd count lands the median on the majority).
  • 2 caves, 2 fixes each, one cave out-of-domain → flagged (Part A); assert the balanced split alone would not.
  • Two caves legitimately ~300 km apart, all in-domain → not flagged (no false positive).
  • A domain-bad fix is excluded from robustWorldOrigin() (origin unmoved by the typo).
Net. Part A makes the feature work for the common 2–3-cave typo with no cluster required; Part B keeps the original cross-cave signal as a bonus where a majority exists. The two together replace the "few fixes → acceptable" concession in §10.

13.8 — Free-form coordinate entry (U11, #621) and the popup's missing errors (U12) next

Added 2026-07-26, after Commit 10. Three separate numeric fields make the common case — paste a coordinate you got from somewhere else — into a manual split-and-retype. Issue #621 asks for one field that takes the whole thing:

Lat / long        46.12113, -115.59902, 304m
                  46.12113, -115.59902, 304ft
                  46.12113, -115.59902, 304        (project units)

UTM               610016.792, 5615117.075, 2545.340m
                  610016.792, 5615117.075, 2545.340 feet

Where it lands

There are now two coordinate-entry surfaces, and they must not each grow their own parser:

  • FixStationPage.qml — the wide RowLayout and narrow Flow delegates, three ValueFields bound to EastingRole / NorthingRole / ElevationRole.
  • FixStationPopup.qml — the Commit 10 inline editor, same three roles, filled imperatively through data() rather than by binding (see the §13.3 callout).

So the parser belongs in C++, called from both — one function, one set of accepted formats, one place a new format gets added. The natural shape is a small free function or value class returning the monad submodule's Result<T>: a struct of three doubles on success, a human-readable reason on failure (the message U12 then has to display).

Three design questions worth settling before writing it

  • The elevation unit is the real trap. cwFixStation::elevation() is a bare, unitless double (cwFixStation.h:63) fed straight into cwGeoPoint(easting, northing, elevation) (cwFixStationValidator.cpp:243, cwGridConvergence.cpp:141, cwTripCalibration.cpp:266) and serialized as-is (cwProtoUtils.cpp:821) — nothing downstream carries a unit, and cwGeoPoint has none either. A 304ft suffix therefore has to be converted at parse time into whatever the fix's effectiveCS() expresses its vertical axis in; the suffix cannot be stored. Reuse targets already exist: cwUnits::toLengthUnit(QString) for the suffix and cwUnits::convert(value, from, to) for the conversion.
  • "Use the project's units" needs a source. A fix belongs to a cave, not a trip, so the per-trip cwTripCalibration distance unit is the wrong well — it would make the same pasted string mean different things depending on which trip was last open. Most likely the settings unit system via cwUnits::surveyUnit(UnitSystem); decide once and write it down, because a silent wrong answer here moves a cave by a factor of 3.28.
  • Lat/long vs. UTM is not decidable from the numbers alone. 46.12113, -115.59902 is a legal (if absurd) UTM pair. The row already declares an Input CS, so the honest rule is: parse under the CS the row currently has, and let the existing per-fix CS-domain check (§12 Part A) say when the result is outside it — rather than inventing a second magnitude-based inference that can disagree with the domain check. Inferring the CS from the paste is a possible nicety, but it should propose a CS, never silently switch one.

Validation

#621 asks for a validator, but not a QValidator: a free-form field must accept partial text while the user is still typing, so blocking keystrokes is the wrong mechanism. Validate on commit and show the reason. Note this replaces, and must not simply sit beside, the per-field DoubleValidator Commit 10 put on the popup's coordinate fields (§13.3) — that guard exists so editingFinished can't push a NaN into the line plot, and the free-form path needs its own equivalent guarantee.

U12 — the inline popup has no error surface at all. Commit 9 gave FixStationPage rows a full set: red field text via error: on the station name and on whichever coordinate component is out of domain (eastingDomainError / northingDomainError, U4), plus message bars for stationError (U10) and domainError. FixStationPopup got none of it — a coordinate typed there can be outside its CS's domain, or anchored to a station that doesn't exist, and the popup looks exactly the same either way. The user only learns about it by navigating to the Fix Stations page or the CavePage badge, which defeats the point of editing inline.

Recommendation: fold U12 into the U11 commit rather than scheduling it separately. Free-form parsing creates a new error class ("couldn't make sense of that") that has nowhere to go today, so U11 has to build a message line in the popup regardless. Once that line exists, wiring the two error roles the model already exposes into it is a few bindings — strictly less work than a second pass, and it avoids shipping a parse-error line that conspicuously ignores the errors sitting right next to it.

Also in #621, not planned here: "a fixed station tool, for moving the station" — the issue itself is ambivalent about it ("might pollute the tool bar with a tool that won't be used that much"). Left open; it is a 3D-view interaction, not a coordinate-entry one, and shares nothing with U11 beyond the subject.
