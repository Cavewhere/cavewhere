# MP.11 — Attaching and opening a large sourced project within the main-thread budget

Written 2026-10-23 from the read-only investigation of the owner's CKKC.wpj (Walls, 51 books, 1,305 surveys, 1,293 .srv files, 385 `#FIX`; after attach 35 nodes, 1,228 trips, 31,809 stations). The full report with sample stacks is in the session scratch dir (`scratchpad/mp11/investigation-2026-10-22.md`); the facts an implementer needs are repeated here. CKKC and wulong_north are the owner's PRIVATE data: never a fixture, never quoted beyond counts. Every fixture is synthetic.

The rule this plan serves is now in CLAUDE.md (commit 4b999b0d): one frame (16 ms) per event-loop turn; cut, then move, then interleave; tests pin growth and signal counts, not milliseconds.

## 1. Owner decisions (2026-10-23, binding)

1. An attached tree fills in over several frames, reported as a row in the task list (`cwFutureManagerModel` through `cwFutureManagerToken`), with progress.
2. Before the first solve, a sourced row's station count shows a placeholder; the expensive pre-solve `knownStations` walk goes.
3. Labels and keyword-filter rows may appear a few frames after the line plot.
4. Save As skips the re-harvest when the copied files' contents are unchanged. The key is CONTENT, never "the dirs moved": an in-memory, per-owner cache in the manager keyed by a hash of the entry file plus its scanned dependency set, valid only within the running process (no persistence, so a CaveWhere or cavern upgrade can never serve a stale harvest). The solve still reruns, because the driver's include paths changed.
5. The 16 ms rule is a target gated in tests by growth ratios and signal counts; absolute timing is the owner's, in the app.
6. Queued passes are scheduled with `QMetaObject::invokeMethod(this, &Class::slot, Qt::QueuedConnection)` behind a pending flag; never a `QTimer` (it allocates a QObject for the same job).

### MT.1 — The survey tree refreshes its aggregates once per event-loop turn, and shows a placeholder count before the first solve
`cwSurveyTreeModel`: `emitAggregateChanged` sets a pending flag and queues one pass; the pass drops only the affected ancestors' cache entries and emits one `dataChanged` per ancestor; `refreshStationCounts` goes through the same queued pass. `sourcedStationCount` stops calling `knownStations()` before the first solve: a sourced row whose node has no solved positions yet shows the placeholder (decision 2; the implementer chooses the glyph and keeps it consistent with how the page shows an unknown value elsewhere, and says what it chose). Tests: `writeFlatSurvex` M=200 attached with the Data page shown: `dataChanged` on the model at most two per ancestor row per event-loop turn (spy + `QCoreApplication::processEvents` steps); the placeholder shows before the solve and the real count after; the MP.5 count tests in test_cwSurveyTreeModel_StationCounts.cpp and tst_DataMainPageTree.qml stay green. Gate: `[SurveyTreeModel]`, `[Attach]`; tst_DataMainPageTree.qml, tst_NodePage.qml.

### MT.2 — The reconcile builds each derived subtree detached and installs it one parent per event-loop turn under a task-list row
`cwExternalCenterlineAttach::reconcileSubtree`: a new derived node's whole subtree is built while detached (trips appended before the node is attached, as `cwCavingRegion::setData` does); new nodes are attached per parent with one `addNodes`; new trips under an existing node go through a new `cwSurveyNode::addTrips(QList<cwTrip*>)`, one ranged `InsertTripCommand` mirroring `addNodes`. The per-parent installs run one per event-loop turn (queued continuation, decision 6), under a `cwFutureManagerToken` job named after the entry file (for example "Attaching CKKC.wpj") whose `QPromise` the main-thread driver advances per parent (numberOfSteps = parents) and finishes after the last one; tst_TaskListView.qml shows the shape the row takes. Matching and removal for Reload stay as they are. Atomicity the investigation stage must settle with file:line evidence: the attach stays one undo step and one save state (what macro or command groups it today); a save trigger, a second attach, Reload/Replace, or Close Project arriving mid-fill either waits for the last batch or cancels cleanly through the same restarter that cancels the worker phases; the region solve keeps waiting (CP.2b's pending-scan deferral) until the last batch lands. Tests: `writeWallsProject` B=10, S=100: root `subtreeChanged` at most B+2 per attach; the tree shape equals today's (the MP.2 shape assertions in test_cwExternalCenterlineAttachSubtree.cpp); the job appears in `cwFutureManagerModel` with a non-zero range and finishes; a Close Project mid-fill leaves no dangling pointer under ASAN; growth ratio S=100 → S=400 secondary. Gate: `[Attach]`, `[LinePlotManager]`, `[cwFutureManagerModel]`, `[SurveyNode]`; tst_DataMainPageTree.qml, tst_TaskListView.qml, tst_ActiveTasks.qml, tst_SourceRootPage.qml.

### MT.3 — Tree-wide consumers of per-item signals run once per event-loop turn
`cwLocalProjectionManager`: subtreeChanged, attachedFixesChanged and the fix-model row signals set a pending flag and queue one `syncNodeConnections` + `evaluate`. `cwSurveyExportManager::rewireExternalCenterlineTracking`, `cwLinePlotManager::connectNodeInputs` and `cwNodePageModel::rewireTrips` become queued the same way. `refreshSenderAttachedFixes` collects pending nodes and refreshes them once, queued; `refreshAttachedFixes` buckets the owner's fixes by trip path / node path once per apply instead of filtering all fixes per trip. Watch for order dependencies: anything that read the projection synchronously right after an attach (tests included) now reads it after the queued pass; `cwFixStationValidator::revalidate` stays on its signal (cheap) or joins the queued pass, the implementer decides and says. Tests: `writeWallsProject` with `#FIX` in 50 surveys: `cwGeoReference::localProjectionChanged` exactly once across the attach; `cwSurveyExportManager` and the line plot manager each rewire once per attach (spy on an existing signal they emit, or on the number of region solves); growth ratio 50 → 200 fix-bearing surveys secondary. Gate: `[cwLocalProjectionManager]`, `[cwLocalProjection]`, `[cwFixStationValidator]`, `[Attach]`, `[LinePlotManager]`; tst_FixStationPage.qml, tst_NodePage.qml.

### MT.4 — Keyword items register in bulk, and the filter pipeline resets instead of replaying
`cwKeywordItemModel::addItems(QList<cwKeywordItem*>)` (append order, one `beginInsertRows` over the range) and `cwKeywordItemRegistry::ensureAll`; the downstream models take a multi-row insert in one pass (`cwKeywordGroupByKeyModel` OtherRow indexes become a QSet or sorted list; `cwUniqueValueFilterModel` and `cwKeywordFilterModel` do range inserts); `reconcileTripKeywordItems` collects all trips first; `cwLinePlotLabelView` registers its items once per region pulse (`positionsChanged`/`memberViewsChanged`), not once per relayed node signal; `cwKeywordFilterPipelineModel::clear` resets instead of removing and re-adding source models. Decision 3 allows the keyword-filter rows to land a frame after the plot. Tests: `writeFlatSurvex` M=200 solved: `cwKeywordItemModel::rowsInserted` at most two per solve; the pipeline model's row set after a Save As (filename change) equals the set before; the existing keyword suites stay green; growth ratio M=200 → M=800 on the publish gap secondary. Gate: `[cwKeywordItemModel]`, `[cwKeywordGroupByKeyModel]`, `[cwKeywordFilterModel]`, `[cwKeywordFilterPipelineModel]`, `[cwUniqueValueFilterModel]`, `[cwLinePlotLabelView]`, `[LinePlotManager]`; tst_KeywordTab.qml.

### MT.5 — Label lists and per-node member positions are computed on the solve worker and installed in bounded batches
`LinePlotResultData` carries the per-trip label lists (name + position, keyed by trip id) and each node's member-position lookup, computed in `cwLinePlotTask`; `updateLinePlot` installs them at most N trips per event-loop turn through `AsyncFuture::observe(future).context(this, ...)` plus a queued drain (decision 6), and the "Line plot" job ends after the last batch; `cwLinePlotLabelView` consumes the installed lists instead of walking `solvedStations` per node. Decision 3 allows labels to trail the plot by a few frames. Tests: on `writeFlatSurvex` M=800 the label set per trip equals today's `labels(trip)` output; the "Line plot" job's progress advances through the batches and the model shows it finished after the last; the solve-once invariant holds (`[SolveOnce]`); the batch size is a named constant. Gate: `[cwLinePlotLabelView]`, `[LinePlotManager]`, `[NodeTree]`, `[cwCavingRegion]`, `[cwFutureManagerModel]`; tst_KeywordTab.qml plus any QML view test the investigation finds bound to label timing.

### MT.6 — A superseded harvest stops before cavern, an unchanged copy is never re-harvested, and the scan reports per-owner progress
`cwExternalStationHarvest::harvestWithFixes` takes a cancel check (the scan promise's `isCanceled`) and tests it right before `cwCavernRunner::run`, so a scan superseded while waiting on the cavern mutex skips its run. The manager keeps an in-memory per-owner harvest cache keyed by the content hash of the entry file plus its scanned dependency set (decision 4; the hash is computed on the worker during the scan; the cache lives in the manager and dies with it); a scan whose key matches reuses the harvest result and still requests the solve when `m_solveOnScanApply` says so. The scan job's `QPromise` gets a range of owners and advances per owner, so the "External centerline scan" row shows n of m; the solve job gets step names where the existing API allows (harvest / solve / geometry) without a new job type. Tests: extend `[SolveOnce]`: a restart while a harvest waits on the mutex leaves one harvest result applied and one region solve; a Save As of an attached synthetic project runs zero harvests and one solve (spy on `cavernOutputChanged` / the future manager jobs); editing one copied file changes its key and re-harvests only that owner; the scan job appears in `cwFutureManagerModel` with a non-zero range. Gate: `[LinePlotManager]`, `[ExternalStationHarvest]`, `[Attach]`, `[cwFutureManagerModel]`; tst_TaskListView.qml, tst_SourceRootPage.qml.
