Settled with the owner (2026-09-13)

  • A source root is a row. OMEGA2 is one top-level node whose page lists its 18 files. The "promote" mode stays in the sim bar for comparison only.
  • The region's direct children can be any kind. A Compass project, a Walls book, a Survex file, a Cave, or a Folder can all sit at the top level.
  • Native nodes have exactly two labels: Cave and Folder. One node class; the label is display only and the backend never branches on it. Position picks the label and the verbs, and the user is never asked: at the region top level and inside a Folder, Add ▾ is Add Cave (caret: Add Folder, Attach survey file…); inside a Cave, and inside a Folder that sits inside a Cave, Add ▾ is Add Trip (caret: Add Section, Attach survey file…). "Add Section" creates a Folder node; it is only the in-cave wording, and the chip says Folder everywhere. A Cave is never offered inside a Cave. To relabel, click the Kind chip on a native node (tree row or page header) and pick Cave or Folder; only the label and icon change. Sourced chips are not interactive. Cave rows carry a cave icon, Folder rows a folder icon, and a Folder's aggregated Trips/Length/Depth render muted.
  • There is no Detach verb. Users delete nodes. Deleting a sourced root removes the whole subtree, native trips included, and the copied file; the confirm says so with counts. Deleting a sourced child or a derived trip hides it from the project, and the exclusion is project state that survives Reload; the root's page shows "N hidden · Restore…" so the consequence is visible.
  • Solve state is one region-wide lookup. "Connected" means connected to any survey in the project, so the floating-trip line reads "This chunk isn't connected to any survey."
  • The Kind column is always shown. It is never auto-hidden, even when every row is a native Cave.
  • Trip rows stay in the tree. Trips are the leaves of the main tree (muted rows, one click to open); the node page keeps its trip table as well.
  • A sourced root starts expanded one level on every load. Native caves and folders start collapsed, so a native-only project still reads as today's list; a project with sources opens showing each source's first level.
  • Names are unique per sibling set, like a file system. A › B and C › B are both fine. The mixed scenario has "Entrance survey" under three caves and a "Side Cave" folder (inside the "Kentucky field seasons" folder) beside the top-level "Side Cave" cave. Only siblings get disambiguated ("New Cave 2").

    • Decisions this prototype makes (all PROPOSED, all cheap to flip)

  • The region is the invisible root. Top-level rows are the region's direct children. There is no "Region" row to collapse; the breadcrumb and the project header above the tree already stand for it.
  • Native nodes start collapsed; sourced roots start open one level (settled). A native-only project renders as exactly today's cave list plus a caret per row. Expanding native caves by default would show every trip of every cave on open, which today's page never does.
  • Trip rows are muted (settled that they stay). A trip row has no kind chip (a gray "trip" tag), no trip count, and opens the trip page on Enter. That keeps the leaf level visually lighter than the node level.
  • Kind chip + lock. One chip per node row carries the kind ("Cave", "Compass file", "Walls book"…). Native kinds use the muted chip; sourced kinds use the blue chip and a 🔒 whose tooltip names the owning file. In promote mode a second, outlined provenance chip names the source and opens its page.
  • Columns. Name, Kind, Trips, Length, Depth, Last survey. Today's list renders a cave as "Name is L long and D deep" in a Flow; the tree needs aligned columns, so that sentence becomes two numeric columns. Trips and Last survey are new and cheap (they are folds over allTrips()).
  • One Add ▾ split button, everywhere. On the Data page its main action is Add Cave and the caret offers Add Cave / Add Folder / Attach survey file…. On a node page the main action and caret follow position (see the settled rule above) with "Place under" fixed to that node. Row ⋯ menus mirror the node's Add ▾ plus Open, Rename (native), and Reload/Replace (sourced root).
  • Delete is right-click only, as in the current app. No Delete button or ⋯ item anywhere; the right-click context menu on a tree row (and on a child-node or trip row of a node page) holds Open, Rename (native only), and Delete…, matching today's DataRightClickMouseMenu. Shift+F10 or the context-menu key opens it on the selected tree row.
  • Add Trip on a sourced node adds a native trip beside the derived ones. Deleting that node later hides it and its native trip together (the confirm counts both).
  • The ≡ sources menu is shown only in promote mode. When roots are rows, the row and its page hold the verbs and the menu would be a third copy.
  • Non-survey Walls books stay in the tree, gray. "SVG Sources" and "Fixed Points" hold no shots. Hiding them would make the tree differ from the .wpj the user knows; graying them says "nothing to survey here" without lying about the file.

    • Tree vs. list for the native-only case

    QuestionFlat list (today)Tree (this prototype)
    What a two-cave project looks likeTwo rowsTwo rows with carets. Same height, same click target on the name.
    Getting to a tripClick cave, then trip: two pagesExpand, click trip: one page. Or the cave page, as before.
    Where "Add Trip" livesCave page onlyCave page, plus the row menu. The page stays the primary place.
    Cost of the tree—One caret column, one Kind column (always shown; for native-only it reads "Cave" all the way down and doubles as the Cave/Folder picker).
    Risk—A user who expands everything on a 40-trip cave gets a long page; Collapse all and the filter box are the escape hatches.

    Verdict: the tree does not hurt the simple case as long as native nodes start collapsed. The only visible delta on a native project is the caret and the always-shown Kind column.
