What is new in Phase 6 (everything marked PROPOSED)

  • Region sources. A survey project file (Compass .mak, Walls .wpj, Survex master) is attached once, at the region, and derives one cave per top-level unit: a .dat file, a Walls book, a Survex top-level block. The region holds a list of sources; each source is one include block in the driver.
  • Same entry point. "Add cave from survey file…" stays the only menu item. The scan decides whether the file is one cave or a project; a project shows the caves it will create and the button reads "Attach N caves". The Phase 3 "this looks like a whole project" warning is gone because the case now has a real action.
  • Source column. The cave list gets a Source column with a chip per cave. Click a chip to filter to that source, click the header to group. There is no region-level page or panel.
  • Mixed caves. Any externally backed cave (derived or cave-level) accepts native trips and trip-level attachments. The driver emits the source include first, then native trips as their own blocks. A derived cave's equates are emitted at region scope, fully qualified. Native trips tie in through the shipped floating banner and tie-in suggester.
  • Trips per survey unit. Scope trips are windows over a station set the scanner records per unit (Compass survey, Walls .srv, Survex block) instead of a name prefix, so Compass surveys become trips even though cavern discards survey names. A station in two surveys belongs to both trips, as native trips already allow.
  • Source verbs live in the ≡ menu on All Caves. One submenu per region source with Reload, Replace…, Detach…. A derived cave's page shows a read-only source card, because any of those verbs acts on every cave the file backs. Detach removes every derived cave's Scope trips and the copied files; derived caves that gained native trips survive as native caves, the rest are removed.
  • Attach-as choice for Walls and Survex. A .wpj always has one root book, and its child books are as often sections or fixed-point folders as caves (Kaua North Maze: "SVG Sources", "Fixed Points", "North Maze Surveys"). A Survex master may be one cave in area files or a region. So the dialog asks: one cave (cave-level attach) or one cave per top-level book/block (region source). Walls defaults to one cave; Survex defaults from the shipped heuristic. Compass has no choice: a .dat is a cave.
  • Fix stations. Externally backed caves hide the fix-station editor. The source carries its coordinate system; native trips get their position through the equate.

    Open questions this prototype should help settle

  • Settled 2026-09-13: the Source chip is enough on the cave row; source verbs live in the ≡ menu and never on a cave page; derived cave names are the .dat stem title-cased; a lone .dat stays a cave-level attach.
  • Is the ≡ button beside Add Cave the right home, or should the source list be a section at the top of All Caves when at least one source exists?
  • Walls per-book mode on a project whose caves are second-level books (root → "Caves" → one book per cave): out of scope for v1, the user attaches as one cave. Worth a depth picker later?
