1. Goal and scope

Goal: a user attaches a native survey project (Compass .mak, Walls .wpj, Survex master file) once, sees it as the caves and trips the native format already defines, carpets on those trips, and adds native CaveWhere trips (digital survey, new leads) or trip-level attachments beside them in the same cave. Nothing is imported; cavern solves the author's files unchanged.

Why this phase exists (the audit that triggered it, 2026-09-13)

  • A cave-level attach is defined as "a cave with zero native trips" (src/cwSurvexExporterCaveTask.cpp:146-153 skips the trip loop for an attached cave; src/cwExternalCenterlineAttach.cpp:676-679 refuses a cave that has trips). A user cannot bolt a native trip onto an attached cave.
  • Scope trips are station-name-prefix windows. cavern discards the Compass survey name (survex/src/datain.c:881-886), and the scanner emits no Compass blocks (src/cwExternalCenterlineScanner.cpp:812-848), so a Compass attach gets one whole-cave trip while the importer gives one trip per survey (src/cwCompassImporter.cpp:267-286).
  • A project file that covers many caves lands in one cave; the multi-cave heuristic (qml/AddCaveSurveyFileDialog.qml:191-219) can only warn.
  • The survex port now gives each .mak #FILE its own survey level named by the lower-cased file stem (survex/src/datain.c:1052-1070, commit 805dc4f2), so per-.dat scopes exist in the .3d. The "cavern flattens Compass" fact in Phase 3 §P3.15 is stale.

Ships in Phase 6

  • Region sources. cwCavingRegion owns a list of external sources. Each source is one include block in the driver and derives one cave per top-level unit of its format (§3.3).
  • Mixed caves. Any externally backed cave (derived or cave-level) accepts native trips and trip-level attachments. Driver: source include first, then native and attached trips as their own blocks, then equates (§3.1).
  • Unit trips. A second Scope-trip kind whose window is the station set of one native survey unit (Compass survey, Walls .srv) recorded by the scanner, instead of a name prefix (§3.4). Survex blocks keep prefix windows.
  • UI: Source column on the cave list; project preview and "Attach N caves" in the existing Add Cave dialog; source card on a derived cave's page with Reload / Replace / Detach source; Add Trip enabled on externally backed caves; fix station editor hidden there; region rows on the cavern page (§3.5).
  • Multiple sources per region, from the first commit (§3.2).

Non-goals (deferred)

  • A Structure view with manual node-to-cave mapping. The cave split is a per-format rule (§3.3); a mapping UI can replace the rule later without a model change.
  • Converting a native cave to external, or an external cave to native.
  • Per-survey trips inside a Survex block that shares station names across blocks (prefix windows already cover Survex).
  • Bulk note-folder import (master plan §9 Phase 6 item) — unchanged, still deferred.
  • Compass export of a mixed cave. The export gate stays closed for any external owner (src/cwSurveyExportManager.cpp:361-381).

3. Settled design decisions (conversation of 2026-09-13)

3.1 Mixed caves

The invariant changes from "an attached cave has no native trips" to "an externally backed cave owns at most one source include plus any number of native trips and trip-level attachments."

  • Driver (writeCave): *begin cave, the cave-level include when present, then the ordinary trip loop (native blocks and trip-level includes, unchanged), then *end. The return at src/cwSurvexExporterCaveTask.cpp:153 goes away; the data gate at :108 stays skipped for externally backed caves (their trips may all be windows).
  • Equates of a cave that has a region-derived source scope are emitted at region level with fully qualified operands (through writeRegionEquates, src/cwSurvexExporterRegion.cpp:83-91), because Survex resolves an operand inside *begin cave relative to that block and the derived scope omega2.blowing3 lives outside it. A cave-level attach's equates keep emitting inside the block as today.
  • Fix stations of an externally backed cave are not emitted and the fix editor is hidden on its page. The source carries its own *cs and fixes; native trips get position through the equate.
  • Attach guard stays "fresh caves only" for the cave-level verb (src/cwExternalCenterlineAttach.cpp:676-679). Bolting on always means attach first, then add trips. Trip-level attach on an externally backed cave is allowed and gains a test.
  • Floating and tie-in need no change: a native trip inside a mixed cave shows the floating banner, and the suggester lists the cave's solved external stations, since knownStations() unions chunks, harvest, and solve.
  • Detach removes Scope trips and the copied files; native trips and trip-level attachments survive (removeEmptyScopeTrips, src/cwExternalCenterlineAttach.cpp:350-357, already removes only chunk-less trips — a trip-level attached trip has no chunks either, so the predicate becomes "chunk-less and not itself attached").

3.2 Region sources are a list

  • cwCavingRegion owns QList<cwExternalSource>. A source has an id (QUuid), an entry file (project-relative, like ExternalCenterline.entry_file), and a display label (the entry file's base name; the driver label is its sanitized, sibling-unique form).
  • Each source is one driver block emitted before the caves: *begin <srclabel> / *include / *end. Two sources are two blocks; the source label keeps them apart even when both hold a molly.dat.
  • Cross-source ties are region equates (cwCavingRegion::tieStations, src/cwCavingRegion.h:106), already emitted with qualified operands.
  • Each source's *cs and fixes scope to its own block, the same way a cave-level attach beside native caves works today. Different datums are cavern's job; P6.3 carries a fixture proving two sources with different *cs solve together.
  • A cave-level attach on a fresh cave and trip-level attaches remain allowed beside region sources. Three ownership levels, one rule each: a region source derives caves, a cave source defines one cave, a trip source defines one trip. The master plan's "region-level attach disables per-cave attach" is withdrawn.

3.3 Derivation rule: unit → cave, unit → trip, per format

Only Compass has an unambiguous cave unit. A Walls .wpj always wraps everything in one root book, and its top-level books are as often sections, fixed-point folders, or drawing sources as they are caves (dewalls/test/Kaua North Maze.wpj: root book = the cave; children "SVG Sources", "Fixed Points", "North Maze Surveys"). A Survex master that only includes files may be one cave split into area files or a region of caves. So the dialog asks, with the scan's structure shown, and the answer is stored on the source.

A single .dat, a single .srv, a .wpj attached as one cave, or a one-cave .svx is a cave-level attach (one cave, no region source). New there: a Compass .dat gets one unit trip per survey and a Walls .wpj gets one unit trip per .srv, replacing the whole-cave window for those two formats. Station names in a cave-level attach are relative to the cave's own label.

Derived cave names: the cave unit's name with the extension dropped and title-cased (BLOWING3.DAT → Blowing3; a Walls book keeps its title; a Survex block keeps its name), passed through uniqueCaveName. Derived trip names: the Compass survey name, the Walls .SURVEY title, or the Survex block name, through uniqueTripName. Both editable afterward; identity is the unit path, never the display name.

Deeper cuts (a second-level book, a nested block) are out of scope; the Structure view is where that would live, and the source stores the chosen split so a mapping UI can replace it without a model change.

3.4 Unit trips: windows by station set

  • A unit trip carries sourceUnit (the unit path relative to its cave's source scope, e.g. OF50-87 for a Compass survey or UPPER/LEAD.SRV for a Walls file) and owns exactly the stations the scanner recorded for that unit. A station in two surveys belongs to both trips — the same rule native trips already live by.
  • The station sets are not stored in the protobuf. The scanner writes one manifest per source, units.json, into the attachment directory beside the copied files (attach, replace, and reload rewrite it), mapping unit path → sorted station list (names canonicalized as cwExternalStationHarvest does, relative to the cave unit). The manager reads it on load and after every reload and pushes each trip's set through the existing cwTrip::setExternalStations channel (src/cwExternalCenterlineManager.cpp:788-806). The project copy is the source of truth, and git tracks the manifest with the files.
  • solvedStations() for a unit trip: the cave's position lookup entries whose key is <cave source scope>.<name> for each name in the set (case-insensitive, like the prefix path). No sibling-claim logic — sets do not nest.
  • Line-plot geometry (src/cwLinePlotGeometry.cpp:181-193) gets the per-trip sets in its thread-safe snapshot and emits a unit trip's legs by membership of both endpoints.
  • Derived caves are windows too. A derived cave's stations are its source scope plus the union of its unit sets from the manifest. Walls needs this (book ≠ prefix); Compass and Survex use the same path so there is one mechanism. A station whose name appears in two caves' sets (a Walls station shared across books) is assigned to the first cave in source order; a leg belongs to the cave that owns its from-station.
  • Prefix windows stay only for the cave-level Survex attach (Phase 3, unchanged). A trip has either a stationPrefix or a sourceUnit, never both; isScoped() is true for either.

3.5 UI surface (the whole of it)

  • Add Cave ▾ → "Add cave from survey file…" is the only entry point, unchanged. A .mak shows "Caves CaveWhere will create — one per .dat file". A .wpj or a multi-block .svx shows an Attach as choice, "one cave" or "one cave per top-level book/block", with the preview switching between the trip list and the cave list (§3.3 defaults). The button reads Attach or Attach N caves. The multi-cave heuristic panel and its alternate-target list are removed; the case now has a real choice.
  • Cave list Source column on DataMainPage: a chip with the source label for derived and cave-level attached caves, a muted "native" chip otherwise. Clicking a chip filters the list to that source; clicking the header groups by source. No region-level page or panel.
  • Source verbs live in a hamburger menu on DataMainPage, beside the Add Cave button: ≡ → "Survey sources" → one submenu per region source with Reload, Replace…, Detach…. The detach confirm (the §3.5 cascade text) opens inline on DataMainPage. A source with a source-change pending shows a dot on the menu item.
  • CavePage source card for a derived cave is read-only: file name, format, "shared with N other caves", provenance, "this cave is BLOWING3.DAT in the project", solve status, and a "Manage sources on All Caves" link. No Reload, Replace, or Detach on a page that shows one of many caves the source backs. A cave-level attach keeps today's card and verbs.
  • Trip table of an externally backed cave: 📎 unit and prefix trips with an em-dash declination, then native and trip-level rows. The Add Trip split button is enabled with both verbs. Native trips sort after Scope trips.
  • Fix station editor hidden on externally backed caves with the line "Fixed positions come from the cave's survey file."
  • Cavern page attached list: one row per source at every level; a region source row names its derived caves.
  • Detach source confirm lists: Scope-trip count removed with their notes and scraps, caves removed (those holding nothing else), caves kept as native (with their native-trip and trip-level counts), copied files deleted.
  • Source-change banner and Update/Reload rows: a region source is one more owner kind in the existing status model; its row says "(N caves)".

3.6 Naming and scope assignment in the .3d

A derived cave has two scopes in the solved network: its own block label (blowing., for native trips and trip-level includes) and its source scope (omega2. plus membership). cwScopeLabels gains sourceLabels(), and cwLinePlotTask::indexStations (src/cwLinePlotTask.cpp:395-447) assigns a station under a source label to the first derived cave, in source order, whose manifest set contains the remainder (upper-cased, like the existing lookups), before falling back to the cave-label head. updateCaveNetworks strips whichever scope matched. The survex port keeps '.' as the separator for Compass-only runs by the existing normalization in cwSurvex3DFileReader.
