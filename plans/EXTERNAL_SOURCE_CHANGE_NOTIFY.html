External Source Change Notification DRAFT

Filed 2026-08-20. Grows out of Phase 2 §16 B9 and the live-link retirement. Design settled in discussion with Philip; implementation unscheduled.

1. The user story, and what the retirement left unfinished

A user modifies several external source files (e.g. an evening of .svx edits in a text editor) and expects CaveWhere to pick them up. They will not visit every trip page to check whether each project copy is current — and the same holds for cave-level attachments. Today CaveWhere gives them nothing: the live-link retirement removed source watching entirely, so a diverged source is invisible until the user thinks to Reload by hand.

The 2026-07-16 direction, completed
The external-file direction change dropped auto-reconcile in favor of "notify + one-click update", with the project copy as the source of truth. The retirement shipped the "project copy is authoritative" half and deleted source watching; this plan builds the notify half properly — at project scope, not per-trip. The line that stays firm: no auto-update. Detection flips a status bit and shows UI; copying into the project only ever happens on an explicit user action.

2. Detection: fingerprint at copy time + notification-only watchers

The two mechanisms cover different windows and are both needed:

Copy-time fingerprintSession watcher
Covers Edits made while CaveWhere was closed — caught by a sweep at project open (one stat per source). Edits made while the app runs — the banner count ticks up live.
Mechanism At every copy into the project (Attach, Replace, Reload/Update), stamp the owner's breadcrumb entry in cwExternalSourceSettings with a fingerprint of the source. "Changed" = current fingerprint ≠ recorded one. QFileSystemWatcher on the breadcrumb source paths that exist on this machine. An event re-stats and updates the status model. Nothing else.

Fingerprint contents (decided)

  • All dependencies, not just the entry file. The scanner already produces the source's *include dependency list; fingerprint every file in it. A dependency edit is as real a change as an entry-file edit.
  • Size + mtime + content hash per file; stat is the fast path, the hash is the verdict. Sources are small text files (~100 KB max), so hashing (SHA-256 via QCryptographicHash) costs microseconds. A check compares size+mtime first: unchanged → UpToDate with no file read; changed → read and hash, and only a hash mismatch reports Changed — a hash match silently refreshes the stored mtime so the fast path goes quiet again. This kills the realistic false positives (a source directory under git rewrites identical files with fresh mtimes on checkout/pull; editors that rewrite unchanged content on save) while keeping the focus-regained re-sweep at pure stat cost when nothing changed. Accepted blind spot: a content change with deliberately preserved mtime and size. Stored in the breadcrumb's QSettings entry, which is per-user per-machine — exactly the scope the source path itself has.

Why watching sources is safe this time

The retired live link hurt because watcher events drove reconciliation: copies, solves, state merges. Here an event does one thing — recompute one owner's status enum. No file copying, no solve, no project mutation. The fiddly part is known scar tissue from the B8 project-copy watcher: editors save via atomic rename, which silently drops the path from the watcher, so every event re-adds the path, and the parent directory is watched to catch re-creation. Canonicalize paths before they enter the watch set (lesson from retirement commit 3).

Check triggers

  • Project open: full fingerprint sweep.
  • Watcher event: re-stat that owner's source set.
  • Main window regains focus: cheap re-sweep (the "edited in another app and came back" moment; also catches anything a platform watcher missed).

3. One status model, every surface reads it

A central per-owner status source — fed by cwExternalCenterlineManager, covering trip and cave owners through the existing owner-id scheme — exposing for each attachment: 

ownerId (QUuid)      trip or cave
sourcePath           breadcrumb path ("" when no breadcrumb)
status               UpToDate | Changed | SourceMissing | NoBreadcrumb

The app-level banner, the review list, and the trip panel's inline "changed since copied" state (Phase 2 B9's source line) all bind to this one model, so they can never disagree. Collaborator degradation is automatic and correct: a synced machine with no breadcrumb has no fingerprint, no watcher, no banner — there is no source there to compare against.

4. Presentation: a persistent banner, never a modal

┌────────────────────────────────────────────────────────────────────┐
│ 3 external sources have changed since they were copied into this   │
│ project.                     [Update all]   [Show]   [✕]           │
└────────────────────────────────────────────────────────────────────┘
  • Non-modal, persistent, dismissable — the browser "restore session?" pattern, hosted at the top of the main window via the per-window AppOverlay host. Appears when the open-time sweep finds changes; count updates live from watcher events. No project-open dialog, no popup.
  • [Update all] re-copies every Changed source through the shared Replace/Reload overwrite path and requests one coalesced solve at the end. Decided: Update-all skips SourceMissing rows — a gone source has nothing to copy; those keep the existing missing-source treatment and stay visible in the list.
  • [Show] opens a compact list: owner (cave/trip name), source path, status — with a per-row Update for the user who diverged one file on purpose.
  • Dismissal is per-fingerprint. Dismissing the banner records the dismissed fingerprints; the banner returns only when a source changes again. It never nags twice about the same edit.
  • Trip panel inline state: the "Copied from:" line gains a "— changed since copied" suffix bound to the model, with the source context menu's Reload (B9b/B9c) right there.

5. Commit breakdown

Prerequisite: Phase 2 B9b (Reload = re-copy from source through the Replace overwrite path) is the update verb everything here invokes.

  1. N1 — Fingerprint recording. Extend the breadcrumb entry with per-file size+mtime+SHA-256 for the source's full dependency set; stamp on Attach/Replace/Reload. C++ gate: fingerprints written on each copy path; older settings entries without fingerprints read back as "no fingerprint" (treated as UpToDate — never nag on data older than this feature).
  2. N2 — Status model + open-time sweep. The per-owner status source and the project-open fingerprint sweep. C++ gate: statuses for changed / missing / no-breadcrumb / stale sources; cave and trip owners.
  3. N3 — Session watchers, notification-only. Watch existing breadcrumb sources + parent dirs; atomic-rename re-add; window-focus re-sweep. C++ gate: an on-disk edit flips the status without touching the project copy, the solve, or cwProject::modified() (the B8 asymmetry: source-side events never dirty the project).
  4. N4 — Trip-panel inline state. The "changed since copied" suffix on the source line, bound to the model. QML gate.
  5. N5 — App banner + review list. Banner with live count, Update-all (coalesced single solve, skips missing), Show list with per-row Update, per-fingerprint dismissal. QML gates: banner appears from a seeded Changed status, Update-all invokes the shared overwrite path once per changed owner, dismiss suppresses until the fingerprint moves again.

6. Non-goals

  • No auto-update — explicit user action only, per the 2026-07-16 decision.
  • No modal or project-open dialog.
  • No cross-machine change detection — the breadcrumb and fingerprint are per-machine by design; a collaborator without the source sees nothing.
  • No hashing on the quiet path — a file whose size+mtime are unchanged is never read; hashing only confirms or refutes a stat-level change.
