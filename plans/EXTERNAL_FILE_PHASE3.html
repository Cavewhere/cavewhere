External File Integration — Phase 3: Cave-level attach

Full plan, written 2026-08-24 (supersedes the stub). Part of the External File Integration plan — the master plan holds the architecture and state model; its §9 Phase 3 block now points here. The settled UX is the clickable interactive prototype (Phase 3 lane), approved 2026-08-24. Phase 2's as-shipped surface is inventoried in the prototype's Phase 2 lane and in the Phase 2 plan.

How to execute this plan. Each commit below (P3.1 … P3.11) is one run of the 5-stage workflow pipeline (plan → implement → simplify → code-review → fix+commit), strictly in order — later commits assume earlier ones are in the tree. Every factual claim about existing code carries a file:line reference measured at externalFiles HEAD 8ee3ec30; re-verify line numbers before editing, trust the identifiers.

1. Goal and scope

Goal: a user can create a cave from an external survey file ("Add Cave ▾ → Add cave from survey file…" on DataMainPage), get one auto-created Scope trip per *begin block to anchor notes and scraps on, see solve errors on the cave and trip rows they navigate by, and detach the whole thing with one confirmed action.

Ships in Phase 3

  • Common-ancestor rebase of the attachment copy layout (prerequisite — see §4), with the absolute-include error and climb cap.
  • Scanner block tree (per-block station counts) + scan-preview exposure.
  • Cave-typed attach / detach / replace orchestration, Scope-trip auto-creation, owner-generic source verbs (Update/Reload for cave owners).
  • Scope semantics: a stationPrefix trip under an Attached cave is a window into the cave's resolved network; externallyBacked predicate.
  • UI: Add Cave menu + cave attach dialog (block preview, multi-cave heuristic), CavePage cave-summary card, 📎 trip rows with em-dash declination, TripPage Scope mode with ExternalCenterlineScopeHeader, cave-level Detach cascade.
  • Solve badges on DataMainPage cave rows and CavePage trip rows (the honest form of the master plan's "nav tree badging" — there is no nav tree; see §3.5).
  • Export gate extended to Scope (stationPrefix) entities.

Non-goals (deferred)

  • Region-level attach / Structure view (Phase 6).
  • The Replace diff dialog with per-trip Kept/Orphaned fates (v1.x — P3.4 ships a silent prefix-match reconcile instead).
  • "Convert Scope trip to native" escape hatch (v1.x).
  • Disconnected-component analysis for the multi-cave heuristic (block-structure signals only in v1 — see §5 Q1).
  • Carrying the raw *include directive into B7's containment message (nice-to-have noted in the old stub; only the absolute-include error is built here).
  • Converting an existing Native cave to cave-level external (per master §8.7 — fresh-cave entry point only).

3. Settled design decisions

3.1 UX (approved via the interactive prototype, 2026-08-24)

  • Naming: the menu item is "Add cave from survey file…" — same verb family as Phase 2's shipped "Add trip from survey file…", replacing the older prototype's "External cave…".
  • No Import box in the cave dialog. One primary verb: Attach. Whole-file native import is the existing Import Survex feature.
  • Scope-trip preview in the dialog: the scan shows the block tree and exactly which trips will be created. Auto-creation stays silent (no picker) — the preview is disclosure.
  • Multi-cave heuristic: when the entry looks like a project master (§5 Q1: ≥ 2 top-level blocks and no shot data of its own), warn, list the entry's direct includes as one-click alternate targets, and still allow the attach. Guidance, not refusal.
  • Cave-level detach cascade: RemoveAskBox-style confirm naming the Scope-trip count and the copied-file deletion; on confirm, Scope trips (and their notes/scraps) are removed and the attachment dir is deleted. Git history is the way back.
  • 📎 + em-dash: externally backed trips (Attached and Scope alike) get a 📎 prefix in the trip table and an em-dash declination cell.
  • Master §8.6 is superseded where it replaces the trip table with a notes list and hides native trips — the Scope-trip resolution keeps the trip table, showing the auto-created 📎 trips. The cave-level CavePage = summary card + normal trip table.

3.2 Scope semantics

A Scope trip under an Attached cave carries stationPrefix (dotted path of its *begin block relative to the file root, e.g. big-passage.east), owns no file and no chunks, and emits nothing into the driver (the attached cave's exporter path already skips the trip loop, cwSurvexExporterCaveTask.cpp:152-155). Its stations come from filtering the parent cave's solved network by scopePrefix() — which already returns stationPrefix + "." (cwTrip.cpp:43-51) and already feeds solvedStations() / knownStations(). P3.6 verifies and completes this path rather than inventing a new one.

3.3 Cave attach guard: fresh caves only

attach(cwCave*) refuses a cave that already has trips ("attach: cave already has trips — cave-level attach is for a new cave"). The only UI entry point creates the cave immediately before attaching (mirroring the trip flow's create-then-dialog, CavePage.qml:46-51), so the guard is a backstop, and it keeps the driver invariant that an attached cave has no native trips (cwSurvexExporterCaveTask.cpp:103-108). Replace is exempt — it runs on a cave whose trips are the Scope trips the previous attach created.

3.4 Scope-trip auto-creation lives in C++

Creation happens in the cave-attach success continuation (main thread, contextualized on saveLoad like the rest of the attach), not in QML: one trip per scan block with ≥ 1 station of its own, name = cave->uniqueTripName(block.name), stationPrefix = block.path, created in file order (parents before children — both big-passage and big-passage.east become trips when both have own stations). The report carries what was created so tests and QML observe it. Replace reconciles instead of recreating: keep trips whose prefix still names a block, create trips for new blocks, leave orphaned trips in place (their station list just goes empty). No diff dialog in v1.

3.5 "Nav badging" is row badging

The master plan assumed a nav tree; none exists — navigation is DataMainPage's cave list (DataMainPage.qml:256-341), CavePage's trip table, and the LinkBar breadcrumb. Phase 3 ships a small solve badge (dot, colors per ExternalCenterlineSolveStatus.qml:30-42) on cave delegates and trip rows for externally backed owners with a solve error or warnings; click navigates to the Cavern page. Anchoring to the owner's section on CavernOutputPage is satisfied by the attached-centerlines list already sitting at the top of that page.

4. Prerequisite design: rebase the attachment copy to the dependencies' common ancestor

Carried from the stub (2026-08-04), unchanged in substance; status updated. This is the difference between cave-level attach working and failing on roughly a quarter of real cave masters.

The defect

cwExternalCenterlineSync::computePlan mirrors every dependency relative to the entry file's own directory (cwExternalCenterlineSync.cpp:140-156). A dependency above the entry — the ordinary *include "../conventions.svx" — produces a relative path starting ../; relativeEscapesAttachmentDir (cwExternalCenterlineSync.cpp:27-41) omits it with a warning, and since B7 the attach fails outright on any omission warning (cwExternalCenterlineAttach.cpp:236-245).

Measured frequency (one 2111-file Survex corpus; don't over-fit)

Attach targetEntriesEscape their own directory
Trip (leaf file)1777 (84.2%)0 — 0.0%
Cave (master including trip files)242 (11.5%)56 — 23.1%
Area / region (master of masters)92 (4.4%)5 — 5.4%

97% of escaping entries escape via exactly one shared file exactly one level up (a shared BCRA error model feeding loop closure — losing it is not cosmetic). "Attach the parent instead" usually has no target: nothing includes the cave master and the shared file as siblings.

The mechanism

Choose the mirror base as the longest common ancestor directory of all (canonicalized) dependencies instead of the entry's directory. Every dependency then has a relative path that cannot begin with ../, by definition of "ancestor". No survey file is rewritten — a relative include is position-independent as long as the tree shape is preserved, and mirroring from the common ancestor preserves the shape. The persisted entryFile becomes a subpath (trips/trip1.svx) instead of a bare name; every consumer already joins it with the attachment dir or strips to a basename for display (ripple audit in P3.2).

Guards

  • Climb cap: refuse when the common ancestor sits more than kMaxRebaseClimb = 2 levels above the entry's directory (keeps a scattered project from dragging the base toward /; costs nothing on the measured corpus, where every climb is 1).
  • Absolute includes become an error (they are silently resolved today): rebasing preserves relative graphs only — a copied file that literally says /opt/shared/conventions.svx points outside the attachment on every machine. Built in P3.1 because ScanResult currently records only resolved paths, so nothing can tell an absolute directive from a relative one.
  • Canonicalize before computing the prefix — the scanner already canonicalizes dependencies; the helper must not re-introduce lexical comparison of uncleaned paths.
  • No common ancestor (different Windows volumes) — error.
Status of the stub's other prerequisite ("a cave-level owner has nowhere to show a file error"): RESOLVED by commit f63f465c — the reason lives on cwAttachedCenterlinesModel::Row::error (.h:62-67), exactly the preferred shape the stub described, surfaced on CavernOutputPage. P3.10's row badges reuse the same role.

P3.12 — Case-insensitive scope matching in line-plot geometry

Symptom (manual test, 2026-08-25): cave-level attach of 48H-H12-330-feng.svx solves, station labels render in the correct places, but no centerline lines appear and length/depth stay uncalculated.

Root cause (traced, confirmed): a Scope trip's stationPrefix is the block path as authored (cwExternalCenterlineAttach.cpp, trip->setStationPrefix(block.path)), which may carry uppercase (48H-H12-330-feng). Cavern lowercases every label in the .3d, so solved network keys are lowercase. The scope-membership filter in cwLinePlotGeometry::emitNetworkScopeGeometry is the codebase's one case-sensitive outlier — station.startsWith(scopePrefix) at cwLinePlotGeometry.cpp:82 (and the cavePrefix strip at :62) — so an uppercase prefix matches zero network stations: zero line vertices, and hasDepth stays false (feeding P3.13). Labels still render because cwTrip::solvedStations() (cwTrip.cpp:~574-578) matches case-insensitively, as do cwFindFloatingSurveys.cpp:243 (via cwStation::canonicalKey) and the position resolution inside emitNetworkScopeGeometry itself (cwLinePlotGeometry.cpp:65,160). Only the membership filter is wrong. Trip-level (Phase 2) attach never hits this because its prefix is the sanitized lowercase trip label.

  • cavewherelib/src/cwLinePlotGeometry.cpp — make the membership test and the cavePrefix strip case-insensitive: compare via cwStation::canonicalKey (or startsWith(scopePrefix, Qt::CaseInsensitive); sliced(size) stays correct because a case-insensitive match has the same length). This is the whole production change.
  • Do NOT "fix" this by lowercasing stationPrefix at attach time: block.path's authored spelling is also the reconcile/replace matching key (windowedPrefixes, cwExternalCenterlineAttach.cpp) against future scans that preserve authored case, and Survex station names are case-preserving for display.
  • Tests: cave-level analogue of "Trip-attached centerline emits renderable line geometry" (test_cwLinePlotTask_AttachInclude.cpp:393-455) using a mixed-case fixture — NEW survex_mixed_case.svx per §8 (uppercase-bearing block names, e.g. *begin 48H-Feng with a nested mixed-case child; solvable). Assert: attach at cave level, solve, the Scope trips' tripVertexRanges are non-empty and segment endpoints resolve. survex_blocks.svx is all-lowercase and would falsely pass — do not gate on it alone; keep it as the lowercase regression.
  • Trap (leave untouched): .3d legs name endpoints by coordinate and the reader fuses coincident stations ("first label wins"), so a cross-scope tie leg may attribute to whichever side is in scope — correct for rendering; do not tighten the neighbor side to in-scope-only.
Gate: cavewhere-test "[LinePlotTask]"-family tags covering test_cwLinePlotTask_AttachInclude.cpp and test_cwLinePlotGeometry.cpp (use the tags those files declare), then "[Attach][Cave]".

P3.13 — Length/depth robustness for external owners

Symptom: cave Length and Depth read zero / never calculated after a cave-level attach. P3.12's case fix is the primary cause; this commit hardens the rest of the chain, which today writes a (-1,-1) sentinel to the live cave and double-counts nested scopes.

Root cause (traced): cwLinePlotGeometry's per-cave result defaults to (-1,-1) (cwLinePlotGeometry.h:56) and is only set under if (hasDepth) (cwLinePlotGeometry.cpp:245-249); updateDepthLength (cwLinePlotTask.cpp:573-585) copies it unconditionally and cwLinePlotManager::updateLinePlot (cwLinePlotManager.cpp:698-705) writes it to cave->length()/depth() — the UI then renders -1.00 (SelectableCaveStat.qml has no clamp). Separately: on any solve error updateLinePlot is skipped entirely (cwLinePlotManager.cpp:544-548) so values silently go stale; and nested Scope trips double-emit — a parent block's prefix (doghill.) string-matches every descendant station and the emitted de-dup set is local per emitNetworkScopeGeometry call (cwLinePlotGeometry.cpp:75-78), so parent and child trips each emit the child's legs: duplicate render segments, per-trip visibility toggles disagreeing over the same leg, and cave length counting nested legs twice.

  • cavewherelib/src/cwLinePlotGeometry.cpp/.h — nested-scope de-dup: when emitting a trip's scope, skip a station whose canonical key also matches a longer scope prefix belonging to another trip of the same cave (compute the sibling-prefix list once per cave, before the trip loop). Each leg then belongs to exactly one Scope trip — the innermost. Cave totals stop double counting and per-trip visibility owns each leg exactly once.
  • cavewherelib/src/cwLinePlotGeometry.h/.cpp + cavewherelib/src/cwLinePlotTask.cpp — retire the (-1,-1) sentinel reaching the UI: keep "unset" internal (the hasDepth flag already exists) and have updateDepthLength write 0/0 for a cave that resolved nothing (an empty cave IS length 0) — the plan chooses 0-on-no-data over keep-last-good so a broken attach reads as "no centerline" instead of a stale number.
  • Solve-error staleness (cwLinePlotManager.cpp:544-548): leave the keep-on-error behavior (matches native trips' long-standing contract) but note it in a comment where updateLinePlot is gated, so the next reader stops rediscovering it.
  • Tests: extend test_cwLinePlotManager_AttachedCenterlines.cpp / test_cwLinePlotGeometry.cpp (today they assert nothing about external length/depth): cave-level attach of survex_mixed_case.svx yields positive length and depth matching hand-computed fixture values; nested fixture (survex_blocks.svx) cave length counts each leg once (regression for the double-count); a scope matching nothing yields 0/0, never -1.
Gate: the line-plot manager/geometry C++ tags (as declared in the two test files) + "[Attach][Cave]"; QML tst_CavePageExternalCave.qml (stat cells show numbers, not -1.00).
