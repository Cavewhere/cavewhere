Prerequisite: a cave-level owner has nowhere to show a file error

Carried over from the review of Phase 2 §16 B7 (2026-08-04). B7 drops an owner whose in-project *include reaches outside the data root from the survey solve, and solveInputs() excludes both owner kinds — but only a trip is ever told why. externalStationsError is a cwTrip property, cwCave has no equivalent, and cwAttachedCenterlinesModel::Row carries no error field. So a cave-level attachment that escapes is silently dropped: the cave's stations vanish from the plot and nothing anywhere says why.

It is harmless today only because cave-level attach arrives through a loaded project rather than the UI — and this phase is what changes that, so the surface has to exist before the attach flow is wired, not after.

Preferred shape: put the reason on the model row, which already serves both owner kinds, rather than mirroring an error property onto cwCave. That also folds into §15's per-owner status gadget instead of fighting it, and it gives the attachments list somewhere to show any per-owner failure — see the exportability-state item in §15, which generalizes containment, a missing entry file, an unreadable file, and a cyclic include into one reasoned state.

Rebase the attachment copy to the dependencies' common ancestor

Cave-level attach cannot ship with the copy layout Phase 2 uses. This section is a design decision made ahead of the rest of Phase 3's planning pass, because it is the difference between the feature working and the feature failing on roughly a quarter of real cave masters.

The defect in the current layout

cwExternalCenterlineSync::computePlan mirrors every scanned dependency into the attachment directory relative to the entry file's own directory (cwExternalCenterlineSync.cpp:93). A dependency that sits above the entry — the ordinary *include "../conventions.svx" — produces a relative path beginning with ../, which would land outside the attachment directory. relativeEscapesAttachmentDir catches that and the dependency is dropped with a warning (cwExternalCenterlineSync.cpp:102-107).

The copied entry file is byte-identical, so it still contains the literal *include "../conventions.svx" line, which now resolves to a path inside the project where nothing was written. The attachment is broken, and the only signal is a warningCount on the row.

How common this is — measured, not guessed

Measured against /Users/cave/Desktop/survex (2111 .svx files, 2287 *include directives), classifying each file by role: leaf (includes nothing), cave (includes only leaves), higher (includes other includers).

Attach targetEntriesEscape their own directory
Trip (leaf file)1777 (84.2%)0 — 0.0%
Cave (master including trip files)242 (11.5%)56 — 23.1%
Area / region (master of masters)92 (4.4%)5 — 5.4%

At trip level the case is structurally impossible, which is why Phase 2 can ship without it. At cave level it is not a corner case. The escapes are also strikingly uniform: 97% of escaping entries (59 of 61) escape because of exactly one shared file, and all 61 climb exactly one level. In this dataset that file is almost always <area>/caves/hmg-grade5.svx, a BCRA Grade 5 error model (*sd length, *sd bearing, *sd gradient, *sd position) shared by every cave master beneath it. It feeds loop closure, so losing it is not cosmetic.

Do not over-fit to this measurement. It is one project curated by one person. It establishes that the shared-error-model idiom is real and common; it does not establish that deep climbs never happen. The climb cap below exists precisely because the sample cannot rule them out.

What "attach the parent instead" would cost

The obvious workaround — refuse the attach and tell the user to attach the file that includes both — usually has no target in this dataset. Nothing includes a cave master and hmg-grade5.svx as siblings, and the region masters escape too (houping/wulong_north.svx reaches into ../sanqiao/, ../pengshui/). So the error would not redirect the user; it would mean the cave cannot be attached at all short of restructuring the source data or duplicating the error model into every cave directory.

The mechanism

Choose the mirror base as the longest common ancestor directory of all dependencies rather than the entry file's directory. Every dependency then has a relative path that cannot begin with ../, by definition of "ancestor". For an entry DuskButte/trips/trip1.svx that includes ../conventions.svx:

dependencyrel today (base = entry dir)rel rebased (base = common ancestor)
trips/trip1.svxtrip1.svxtrips/trip1.svx
conventions.svx../conventions.svx → droppedconventions.svx

The attachment directory then holds conventions.svx and trips/trip1.svx, and the unmodified ../conventions.svx inside the copied entry resolves correctly. No survey file is rewritten. A relative include is position-independent as long as the shape of the tree is preserved, and mirroring from the common ancestor preserves the shape.

The escape stops being a rule that is enforced and becomes a condition that cannot arise. relativeEscapesAttachmentDir survives only as a defensive assertion that should never fire.

Guards

  • Climb cap. Refuse when the common ancestor sits more than ~2 levels above the entry's directory. Scattered dependencies could otherwise drag the base to / or the home directory and mirror the author's directory names into a shared project. Costs nothing on the measured dataset (every climb is 1) and still refuses the genuine outliers — wulong_north.svx carries 894 dependencies and 23 outside references, which is "attach the entire project as one cave".
  • Absolute includes have to become an error — they are not one today, so this guard is work to build, not a status quo to preserve. Rebasing preserves relative graphs only. A copied file still literally says /opt/shared/conventions.svx, which points outside the attachment on every machine, and inside a bundled .cw it also breaks across re-extraction to a new temp directory. B7's fourth deviation records why it could not be built there: ScanResult::dependencies holds resolved canonical paths and drops the directive as written, so no consumer can currently tell an absolute *include from a relative one. Carrying the raw directive on ScanResult is the prerequisite, and it has two customers — this guard, and B7's containment message, which would rather name the directive the user typed than a long resolved path.
  • Canonicalize before computing the prefix — an uncleaned /a/b/../c/x.svx skews it, and a symlink can step out of the tree lexical comparison thinks it is in.
  • No common ancestor (different Windows volumes) — error.

Ripple

The geometric change is small: a commonAncestorDir() helper in cwExternalCenterlineSync.cpp's anonymous namespace, and computePlan swapping entryDir for it. What ripples is that entryFile stops being a bare filename — cwExternalCenterlineAttach.cpp:237-238 stores QFileInfo(…).fileName() today and would store trips/trip1.svx. Survey of the consumers says that ripple is small:

  • cwExternalCenterlineManager::scanOwners composes it as QDir(attachmentDir).filePath(entryFile), which already accepts a subpath.
  • ExternalCenterlineAttachedHeader.qml:28 already strips to a basename for display.
  • The GC already recurses (enumerateFilesRecursively plus full destination paths in expectedSet), so a nested layout needs nothing.
  • cwSurvexExporterCaveTask::driverIncludePathFor joins attachment dir and entry file, so it follows automatically.
  • CavernOutputPage.qml:128 would display a path where it displayed a name — cosmetic.

Corrected 2026-08-04, after B7 shipped. This note used to say B7 "deliberately leaves the attach-side warn-and-omit alone, because rebasing removes the condition rather than the check, and writing a strict attach-side error first would only be deleted here." B7 shipped the strict attach-side error anyway: computePlan's omission warnings now fail the attach outright (cwExternalCenterlineAttach.cpp:225). So the refusal this section deletes already exists, and relativeEscapesAttachmentDir is a live user-visible refusal until rebasing lands — not yet the "defensive assertion that should never fire" described above. The practical exposure is nil for what Phase 2 ships, since attach() is trip-level only and trip-level escapes measure 0.0%; it is precisely the cave- and area-level masters this section exists to serve (23.1% and 5.4%) that would hit the refusal, which strengthens rather than weakens the case for rebasing.
