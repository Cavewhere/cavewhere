Color By — research and proposed design

Implementation plan: plans/COLOR_BY_PLAN.md (that file is the authority). Color the 3D view (centerline, scraps, later point clouds) by depth, cave, trip, date, caver, or loop membership. Status: research only, nothing implemented. Branch colorBy.

2. The two "pipelines" collapse into one GPU mechanism

Categorical (cave, trip, caver) and numeric (depth, date, error) differ only in how the value is produced and how the ramp is built. On the GPU both are the same thing:

color = texture(ramp, (value - rangeMin) / (rangeMax - rangeMin))
  • Numeric: value = world z (or days since epoch, or error ratio); ramp = 256-texel sequential gradient, linear filter.
  • Categorical: value = palette slot index; range = [0, N); ramp = the fixed categorical palette baked into 256 texels in bands, nearest filter.

So every participating renderer needs exactly: one per-element float value, one shared 256×1 RGBA8 ramp texture, and a small UBO. That keeps shader branching to a single mode switch and gives categorical and numeric modes identical legends, identical plumbing and identical tests.

One state object feeds two renderers through the same ramp texture.

3. Centerline

  • New per-instance buffer (binding 3): float iValue, or two floats iValueFrom/iValueTo so a long shot grades smoothly in depth mode. Rebuilt exactly like the visibility mask: a copy-on-write QVector<float> on cwRenderLinePlot, uploaded on version change.
  • Depth mode: fill the value vector from vertex z in setGeometry; minZValue/maxZValue already exist and become the default range.
  • Categorical mode: cwLinePlotTripVisibility grows into a trip appearance proxy with setColorValue(float) calling setRangeValue(start,count,v). The range re-target after every solve (cwLinePlotManager.cpp:307-320) already handles geometry churn.
  • Fragment stage: new ColorByBlock UBO at binding 1 and the ramp sampler at binding 2. mode == 0 keeps today's constants so the default look is byte-identical. Splays: multiply the ramp color toward white the way the pink does today, so they stay visually secondary.
  • The pipeline key gains the texture/UBO bindings; the SRB rebuild path at cwRHILinePlot.cpp:293-324 already tolerates that.

4. Scraps: tint, shade, or glow?

Scraps are mostly white paper with dark ink, so the blend choice matters more than the palette.

OptionMathVerdict
Luminance recolor (recommended)lum = dot(tex.rgb, vec3(.299,.587,.114));
rgb = mix(tex.rgb, ramp * lum, strength)		Paper takes the color, ink stays dark and readable. Works for any strength. Same trick colorizes a gray LiDAR mesh. Default strength ≈ 0.6.
Multiplytex.rgb * rampSame as above at strength 1 but no dial; dark ramp steps crush detail.
Flat overlaymix(tex.rgb, ramp, k)Washes out ink at any useful k. Reject.
Glow / haloScreen-space pass: write value to an aux target, blur, composite behind sceneNeeds a post pass; the only one today (EDL) runs only when a cloud is visible, and tiles in capture would need it too. Halos pile up where plan scraps overlap. Defer; luminance recolor at strength 1 already reads as "painted".
  • Apply the tint after the transparent-texel-to-white step so the whole paper area recolors.
  • Set perDrawUniformBinding for the scrap material and give the item block { float value; }. In depth mode the shader ignores it and uses vVertex.z (pass world position to the fragment stage), because a single value per scrap is wrong for a scrap that spans tens of meters vertically.
  • Categorical: cwRenderTexturedItemVisibility grows setColorValue → setUniformBlock. One UBO write per scrap when the key changes; nothing per frame.
  • No pipeline or blend change: scraps stay opaque, so draw order and picking are untouched. Map export tiles pick the tint up for free; the 2D centerline overlay in export would need its own pen color later.

5. Sane color, by construction

Rule: sequential = one hue or an ordered perceptual ramp, light→dark. Categorical = a fixed palette in fixed order, color follows the entity. Diverging = two hues with a neutral middle, only for signed data. Rainbow exists as a named opt-in, never the default.

Ramp construction

Add cwColorRamp: a list of stops interpolated in OKLab (or OKLCH for hue sweeps), baked to 256 RGBA8 texels. Interpolating in OKLab is what makes two-stop gradients look even instead of muddy in the middle; it's a dozen lines of math. Ship presets as stop lists, plus viridis/cividis/turbo as 256-entry tables.

UseDefaultAlternates
DepthDiverging, white at the pivot (0 m by default). Depth runs +100 m to −500 m; the pivot is white and color steps are equal in meters on both sides (t = 0.5 + 0.5·(v−pivot)/max(max−pivot, pivot−min)), so +100 is a faint warm tint and −500 the full navy.

  • Stable assignment: slot = position of the value in the sorted set of all values in the unfiltered item model, so hiding trips in the Layers filter never repaints the survivors.
  • Dark mode: ramp endpoints that sit on white paper read differently on an inverted sketch. Keep light/dark endpoint pairs in Theme.qml-style tokens from day one (same lesson as the sketch stroke colors).
  • Centerline and scraps share the ramp so a legend entry means one thing.

6. Where the UI lives

Agreed: it is a view setting, not a tool. It never captures the mouse and it is always-on state, the same category as the keyword filter. Proposal:

  • Decided: everything in the 3D view. A "Color by: None" chip sits bottom-left (opposite scale bar and compass) when color-by is off and becomes the colorbar legend when on. A single click or right-click on it opens a popup with the controls: source ComboBox [None · Depth · Cave · Trip · Date · Year · Caver · Loop closure], ramp ComboBox, pivot, scrap tint slider. The key list is the same pipelineModel.possibleKeys the filter uses, with the numeric sources prepended. The Layers tab is untouched; no new tab.
  • Legend in the viewport: bottom-left overlay at zOverlay, mirroring the ScaleBar/Compass row at bottom-right. Numeric: a vertical colorbar with min/max labels and a drag-to-narrow range. Categorical: swatch + value list, scrollable past ~12 entries. Hidden when mode is None. The ramp bitmap comes through a QQuickImageProvider (image://colorRamp/<id>) so no Canvas/Shapes.
  • Optionally mirror the mode in FileMenu next to "Scraps Visible" for keyboard discoverability. Persist in QSettings as a view preference, not in the project file.

Per-shot sources (loop, error) need the value computed before trip ranges are flattened. The place is cwLinePlotGeometry::generate, which should emit a parallel QVector<float> of per-vertex values alongside points. Categorical keyword sources do not need this; they work on trip ranges after the fact.

8. Suggested phases

  1. Depth on the centerline + legend. cwColorRamp, cwColorBy state on cwRegionSceneManager, per-vertex value buffer, ColorByBlock + ramp texture in cwRHILinePlot, the Layers "Color by" row and the colorbar overlay. Offscreen PNG test for eyeballing. The default stays pixel-identical.
  2. Scrap tint. Per-draw UBO on the scrap material, luminance recolor in scrap.frag, strength slider. Depth works immediately because it reads vVertex.z.
  3. Categorical by keyword. Generalize the two visibility proxies to appearance proxies; a cwKeywordColorBy assigner (sibling of cwKeywordVisibility) that maps group-by rows to slots; swatch legend; Okabe–Ito palette.
  4. Date timeline, loop membership, loop error, point clouds. Each is just a new value producer.
