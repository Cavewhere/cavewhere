# Hand-rolled synchronization audit (2026-10-26, read-only)

Searched `cavewherelib/src`, `main.cpp`, `asyncfuture/`, `QQuickGit/src`, `dewalls/` for semaphores, wait conditions, atomics as completion counters, sleeps, `processEvents`/`QEventLoop`, `start`/`tryStart`, `QRunnable`, `std::thread`, direct `QtConcurrent::run`, `globalInstance`, `releaseThread`/`reserveThread`, `waitForFinished`/`waitToFinish`, and every `cwConcurrent::run`/`map` call site. `dewalls` is clean.

## A. Defects worth fixing

1. **`cwKtx2Codec.cpp:311-334` encodeLevelsOnPool.** One discarded `cwConcurrent::run` per 256-block chunk, counted on a `QSemaphore`. Fix: one `cwConcurrent::map` over a chunk list (plan: `plans/KTX2_MAP_PLAN.md`).
2. **`cwTripLinePlotTask.cpp:218-221` runLinePlot** runs `cwLinePlotTask::run` (`cwLinePlotTask.cpp:756`) and `waitForFinished()`s it from inside another pool task (`:252`), once per component. A blocked slot with no `releaseThread`, deadlock risk on a small pool; the outer run is the plain-lambda form so cancel never reaches cavern. Fix: make the outer run the `QPromise&` form and call `cwLinePlotTask::LinePlotWorker` inline with `[&promise]{ return promise.isCanceled(); }`; the nested future goes away.
3. **`cwKeywordItemFilterModel.cpp:50` destructor → `:224`** calls `AsyncFuture::waitForFinished(LastRun)`: a nested event loop in a production destructor, needed because `:276` uses `.subscribe([this, ...])` with no context. Fix: `AsyncFuture::observe(runFuture).context(this, ...)`; the destructor only cancels.
4. **Legacy `cwTask` family.** `cwTask.cpp:161` starts itself as a raw `QRunnable` (no `QFuture`, invisible to the task trace, `cwTaskTrace.h:104`). `cwTask::waitToFinish` (`cwTask.cpp:386-408`) spins `processEvents`/`QEventLoop::exec`, called from destructors at `cwUsedStationTaskManager.cpp:25-26`, `cwCavePageModel.cpp:17` (via `:188`, `cwUsedStationTaskManager.cpp:399`), `cwImportTreeDataDialog.cpp:75-76`, and a slot at `cwImportTreeDataDialog.cpp:344`. Subclasses: cwUsedStationsTask, cwTripLengthTask, cwProjectIOTask and children, cwExporterTask, cwTreeDataImporter (Survex, Walls), cwStationCSVTask, cwCompassExporterRegionTask. Fix: port each to `cwConcurrent::run` (QPromise form) + `AsyncFuture::Restarter` observed with `.context(this, ...)`, as the scrap and LiDAR managers do; destructors just cancel. First target: cwUsedStationsTask (torn down with every cave page).
5. **`cwTileStreamer.h:380`** discards its `cwConcurrent::run` future and captures raw `this`; `cancelAll()`/destructor join through a `QWaitCondition` (`waitForInFlight` `:461-466`, woken `:419`). Window is bounded (`kMaxConcurrentLoads = 4`, `:72`) and errors travel in `Result`, but an in-flight load is uncancelable (cancel only bumps the generation) and teardown blocks for up to 4 loads. Fix: store the `QFuture` in `Request`, give the loader a `QPromise&` that polls cancel, cancel that future from `cancel(itemId)`, join on the stored futures.
6. **`cwPointOctreeBuilder.cpp:1402-1496` pass B orchestrator** hand-rolls a byte-budget admission window: `cwConcurrent::run` per column into a list, reaped with `isFinished()` + `msleep(kMapPollMs = 30)` on a pool thread whose slot it released. Reimplements `AsyncFuture::limited` with a weight (`cwMemoryBudget::limitedOnPool`), adds up to 30 ms idle latency per round, parks a sleeping thread. Fix: drive the columns through `limitedOnPool` with `column.bytes` as the weight; the orchestration becomes a continuation chain on a context `QObject`. Related, tolerable: `awaitMapped` (`:548-570`) polls the same way only to forward cancel and progress; cleaner is `promise.isCanceled()` inside the mapped worker + progress from the worker + a `waitOnPool`-style release/wait/reserve.
7. **`QQuickGit/src/GitRepository.cpp:1351-1354` testRemoteConnection** starts a `QtConcurrent::run` that starts another (`testRemoteConnectionDetailed`) and waits with `AsyncFuture::waitForFinished(..., 20000)`: two global-pool slots and an event loop on a worker; the timeout is moot because `reportFuture.result()` blocks anyway. Fix: `return AsyncFuture::observe(testRemoteConnectionDetailed(url, false)).subscribe([](const RemoteConnectionReport& r){ ... }).future();`. `:1322` (event-loop wait on the LFS batch future inside the worker) is the same shape, tolerable if `LfsBatchClient` needs a worker event loop.
8. **QQuickGit bypasses its own pool seam.** `GitConcurrent` (`GitConcurrent.cpp:14-19`) has no callers. Every git job uses `QtConcurrent::run` on `QThreadPool::globalInstance()`: `GitRepository.cpp:1275, 1351, 1406, 1472, 1705, 1720, 2006, 3137, 3190, 3346, 3499`, `LfsHydrator.cpp:1199, 1400`. Futures are returned or observed, so errors reach callers; the cost is git I/O outside the task trace and outside the ideal − 2 sizing, so sync oversubscribes the cores. Fix: route through `GitConcurrent::run`, wire `GitConcurrent::setThreadPool(cwTask::threadPool())` in `main.cpp`; `:1705` should be `QtFuture::makeReadyValueFuture(false)`.
9. **Minor: `cwSketchManager.cpp:453`** (checked `:410`, `:462-473`, `:663`) keeps a `shared_ptr<atomic<bool>>` cancel token beside a Restarter future that already carries cancel. Fix: cancel `pipeline->restarter->future()` and let `promise.isCanceled()` do the job.

## B. Deliberate patterns to leave

- `cwKtx2Codec.cpp:178-197` runOnLane: single hand-off to the one-thread encode lane; the semaphore stops a waiting `QFuture` from stealing the runnable (its comment), slot released around the wait.
- `cwKtx2Codec.cpp:341-395` EncodeClaim: per-cache-key dedup across independent callers via `QWaitCondition`, slot released while waiting. A `QHash<QString, QFuture>` of in-flight encodes is an alternative with small gain.
- `cwGeometryItersecter.cpp:447-453` waitOnPool: nested `cwConcurrent::map` from a pool task with release/reserve; callers `:2313`, `:2354`, `:2643` are bounded maps that check cancel per item.
- `cwPointOctreeSampler.cpp:610-632` forEachIndexWithIdleThreads: helpers only through `tryStart`, at most `maxThreadCount`, never queued, caller works too; deadlock-free by construction. Uncancelable but bounded.
- Save pipeline (`cwSaveLoadPrivate.cpp:1449`, `cwSaveLoad.cpp:2331`, `:5577`): `QtConcurrent::run` on `m_saveThreadPool`, a dedicated one-thread serial lane (`cwSaveLoadPrivate.cpp:620`); futures observed. Direct only because `cwConcurrent::run` takes no pool argument.
- `cwSaveLoad.cpp:2088`: atomic `remaining` over save-job `onDone` callbacks; correct because the jobs are callbacks. Would become `AsyncFuture::combine` only if they returned futures.
- Cancel-then-join teardown with plain `QFuture::waitForFinished` (no event loop): `cwSurveyImportManager.cpp:77-82`, `cwCaptureViewport.cpp:685-686`, `GitRepository.cpp:991-994`.
- Shutdown joins: `main.cpp:370-371` (`waitForDone`), `cwRootData.cpp:526-527` (documented exception, arms `beginShutdown` first).
- `cwTaskTrace.cpp:136, 204-206`: diagnostic sampler on its own `std::thread`, compiled only with `CAVEWHERE_TASK_TRACE`.
- `cwRhiViewer.cpp:85`: `QRunnable::create` for `scheduleRenderJob`, the render-thread API.
- Progress counters (not completion counters): `cwLazClipOperation.cpp:494`, `cwProgressNode.h:93-107`, `cwProgressReporter.h:140`.
