Splay Shots — Implementation Plan

Issue #483 · branch dev_4 · plan written 2026-08-06

Add first-class splay shots to CaveWhere: import them from Survex .svx (TopoDroid exports in particular), store them on stations, solve their positions through the existing cavern pipeline, render them in the 3D line plot, and show them read-only in the SurveyEditor behind an expandable chip in a dedicated Splays column.

Decisions already made
  • Station-anchored. A splay is a cwShotMeasurement (distance, compass, clino) stored on a station occurrence — the same shape as LRUD, which is also per-occurrence. The chunk's alternating station/shot chain stays untouched.
  • Front-sight only. No backsighted splays in v1.
  • Read-only in the editor. Display behind the Splays-column chip (per plans/SPLAY_EDITOR_PROTOTYPES.html). Renaming/promoting a splay to a named station is a later feature, as is adding/editing splays by hand.
  • Positions come from cavern, not local math. Splays ride the existing export → cavern → .3d pipeline so declination/convergence are applied identically to centerline (measure, don't reason about frames).
  • Compass export deferred to the end (Phase 6).
Ground truth: the TopoDroid file. ~/Desktop/svx/a0-a34.svx shows what real input looks like — and it is not *flags splay: 
*begin                      ; anonymous begin (no survey name)
  *alias station - ..       ; "-" is an alias for the anonymous station ".."
  *flags not splay
  *data normal from to tape compass clino
  a3 - 1.14 275.1 83.3      ; splay: leg to an anonymous station
    a0 a4   24.07 95.9 -50.0  ; centerline leg
  ...
*end
Splay-ness here comes entirely from the anonymous endpoint. That matches Survex semantics: cavern implicitly marks any leg to an anonymous station as a splay. The importer must therefore recognize two independent signals — anonymous endpoints (- via alias, ., .., ...) and the *flags splay flag — and today it handles neither correctly. Also note the LRUD - ("no reading") in *data passage blocks, which must keep working.

Phase discipline. Each phase is one reviewable commit (or a small series) and ends with both test suites green. Stop at every phase boundary for review before starting the next.

Phase 1 — Data model, proto, save/load

Give splays a real home and make them survive a save/load cycle, before any importer can produce them.

cwStation

  • newRevive m_splays with accessors on cwStation: splays(), setSplays(), addSplay(), splayAt(), splayCount(). Value-type semantics like LRUD — the shared PrivateData already copy-on-writes.
  • newcwShotMeasurement gains operator==/!= comparing all three readings plus direction, so splay lists compare as values.
  • fixSplays stay out of cwStation::operator==. The original plan had them participate, but the operator turned out to be station.name().compare(station.name()) — comparing the argument to itself, so it was unconditionally true. Its real consumers are QSet<cwStation> in cwSurveyChunk/cwTrip's neighboringStations, where qHash hashes canonicalKey(name) alone. Equality is therefore fixed to case-insensitive name comparison, matching qHash's contract; folding LRUD or splays in would have changed neighbor-set dedup semantics for no benefit.
  • Only cwShotMeasurement::Direction::Front is produced anywhere in v1; the field exists but stays constant.

cwSurveyChunk

  • newA mutation + notification path so the editor model and save system observe splay changes: stationSplays(int) / setStationSplays(int, const QList<cwShotMeasurement>&) plus a dedicated stationSplaysChanged(int index) signal. setStation() emits it too, since it replaces the whole station.
  • fixA dedicated signal, not a new DataRole. The plan called for DataRole::StationSplays + dataChanged, but the roles are cell-oriented and QString-centric: setData gates on data.canConvert<QString>(), and the error-checking switches over DataRole are exhaustive, so a list-valued role would have to be stubbed into several of them for no gain. A typed accessor pair keeps the grid machinery clean.
  • cwSaveLoad connects the new signal next to dataChanged (cwSaveLoad.cpp:4107) so a splay edit marks the trip dirty.
  • No change to the alternating station/shot chain or canAddShot.

Proto (cavewhere.proto)

message SplayShot {
    optional string distance = 1;
    optional string compass = 2;
    optional string clino = 3;
}

message StationShot {
    ...
    repeated SplayShot splays = 105;   // station block (100s)
}
  • Readings are plain string, matching how StationShot already stores LRUD and shot readings. The DistanceReading/CompassReading/ ClinoReading messages the plan first named are marked legacy in the proto and are only read by the pre-v9 path.
  • Wire up in cwProtoUtils: saveStationShot and fromProtoStation, reusing the file's existing saveReading helper so an empty reading writes no field at all.
  • fixResolved: no protoVersion() bump. The field is purely additive, and cwSaveLoad parses JSON with ignore_unknown_fields = true (cwSaveLoad.cpp:973), so an older build loads a splay-bearing file cleanly. Bumping to 10 would instead make every older build show the "Upgrade CaveWhere… you will lose data if you save" error (cwRegionLoadTask.cpp:219) for all new files, splays or not. Existing practice agrees — GeoReference and auto_declination were added under version 9 without a bump.

Phase 2 — Survex .svx import

Make cwSurvexImporter produce splays from both real-world encodings, and fix the pre-existing flag and anonymous-station bugs. Acceptance bar: a0-a34.svx imports with every splay attached to its station and zero spurious warnings.

Flags (parseFlags, cwSurvexImporter.cpp:1032)

  • fixUntangle splay from duplicate: give cwTreeImportDataNode a separate splay flag alongside includeDistance (positive names, AND-combined through block nesting like the existing flag). *flags not splay stops canceling an active duplicate.

Anonymous stations and *alias (parseNormalData, cwSurvexImporter.cpp:554)

  • newParse *alias station - .. / *alias station - (the only alias form Survex defines). Alias state is per-block, inherited by child *begin blocks, restored on *end — same scoping as flags.
  • newRecognize anonymous to-stations: ., .., ..., and - when the alias is active (also keep accepting bare - for legacy files, since that's what the importer skipped before). A leg with a named from and an anonymous to becomes cwShotMeasurement{distance, compass, clino, Front} attached to the from station. Handle the reversed orientation (anonymous from, named to) by attaching to the named end as-is — do not invert the reading; Survex's own semantics anchor the splay at the named end and record the instrument reading unchanged.
  • Both ends anonymous → warning, skip (matches cavern's "no fixed point" reality).
  • fixLegs whose station fails cwStationValidator (e.g. an unhandled dotted name) become an import warning + skipped leg instead of today's silent empty-named station corruption.
  • *flags splay on a leg between two named stations: keep importing it as a regular shot with distanceIncluded = false (today's behavior, now under the correct flag) plus a warning that the station names were kept. Converting those to anchored splays would throw away the to-station name; revisit when splay promotion/naming lands.
  • Remove the "Skipping splay data" warning path.

Attaching splays to chunk stations

The importer accumulates legs into chunks as it parses; a station's splays can appear before or after the centerline leg that introduces the station (in a0-a34.svx, the a3 splays precede the a0 a4 leg). So: buffer splays per block keyed by resolved station name during parsing, and after the block's chunks are assembled, attach each buffered list to the station's first occurrence in that block's chunks. A buffered splay whose station never appears in a leg gets an import warning (an orphan splay has no anchor).

What came out different from the plan

  • fix*alias keeps no state. The plan gave it per-block scoping like flags, but the state would never be read: - is anonymous whether or not the alias was declared, because that's what legacy files rely on and *alias station - .. is the only alias survex defines. So parseAlias just accepts that one spelling quietly and warns about any other — enough to stop the "Unknown survex keyword:alias" the file used to produce.
  • fixThe LRUD pass now merges instead of replacing. updateStationLRUD used to write whole cwStation values built in parsePassageData, which would have dropped any splays already on those stations. Rather than leave that as an ordering rule for every later phase to remember, setLRUD copies only the four readings onto the chunk's own station, so the station keeps everything else it carries. A test checks a4 ends up with both left = 1.2 and its 3 splays. Both drains run from one finishBlock(), called at *end and again at the end of importSurvex for files that never open a *begin.
  • fixThe one warning on a0-a34.svx is real, not spurious. a3 is an orphan in the ground-truth file: the leg that names it lives in the previous survey file, so its 3 splays have nothing in this block to hang on. The trimmed dataset keeps that shape rather than inventing a leg for it.
  • fixDrive-by: *units compass degrees stopped warning. Getting to "zero spurious warnings" on the real file needed it — TopoDroid writes *units compass degrees and *units clino degrees on every export, and CaveWhere reads every angle in degrees already, so the line restates the default. All five angle types (compass, bearing, clino, gradient, declination) now stay quiet on degrees and name the unit they're ignoring otherwise.
  • The splay buffer lives in cwSurvexNodeData next to LRUDChunks, as a QMap<QString, cwStation> keyed by cwStation::canonicalKey so A4 and a4 collect together. Buffering into a cwStation reuses the name and splay accessors Phase 1 already added, and keeps the as-written spelling for the warning text.

Phase 3 — Survex export + cavern + .3d read-back

Two consumers share this code: the user-facing Survex export, and cwLinePlotTask's internal export that feeds cavern. Getting splays into the generated .svx is what makes cavern solve their positions; reading them back out of the .3d is what gives rendering its endpoints.

Export (cwSurvexExporterTripTask)

    *flags splay
a4 .. 5.88 124.1 4.6
a4 .. 5.42 118.8 2.9
*flags not splay
    Writing .. directly needs no *alias; *flags splay is redundant with the anonymous endpoint but makes the file self-describing.

Return them as a new output: QHash<QString stationName, QList<QVector3D> tipPositions> alongside the existing network + position lookup.
  • Keep skipping img_SFLAG_ANON labels in pass 1 (they still aren't stations), and keep dropping non-splay legs with unresolvable endpoints.
  • Positions flow through the same worldOrigin narrowing as stations — subtract in double before building QVector3Ds (the established rule from the worldOrigin work).

Phase 4 — Rendering

Geometry (cwLinePlotGeometry)

  • newAfter each trip's centerline segments, append splay segments: station position → tip, two de-shared vertices each — exactly the layout the per-shot visibility plan anticipated. Record each trip's splay vertex range next to its centerline range so the existing trip-UUID → range visibility mapping in cwLinePlotManager::reconcileTripKeywordItems extends naturally.
  • Splays never contribute to cave length/depth (they already can't — those accumulate from chunk shots, not geometry).

Render (cwRenderLinePlot / cwRHILinePlot) — instanced screen-space quads

This phase also upgrades the line rendering itself. The current pipeline draws a native Lines topology, which Metal (and D3D/Vulkan core) clamps to 1 px. Replace it with instanced screen-space quad expansion — the standard Metal-era thick-line approach (geometry shaders are unavailable on Metal):

  • newOne instance per shot segment. The per-instance buffer carries {vec3 from, vec3 to, uint flags} (flags = visibility bit + type bit: centerline vs splay). The pipeline draws a fixed 4-vertex TriangleStrip, corner selected by gl_VertexIndex — no corner vertex buffer. The current pair-per-shot vertex layout is already one instance per two points, so the geometry upload shape barely changes.
  • newVertex shader: project both endpoints to clip space, divide by w manually, compute the screen-space perpendicular from the two NDC points, extrude by halfWidthPx * 2.0 / viewportSize * devicePixelRatio, then multiply back by w so clipping and depth interpolation stay correct. devicePixelRatio is already in GlobalBlock; viewport size joins the line plot's own uniform block (per the global-uniform-scope rule, not GlobalBlock).
  • Widths and colors branch on the type bit to shader constants: centerline 2 px, existing red vec4(1,0,0,1); splays 1 px, opaque light red vec4(1.0, 0.6, 0.6, 1.0). No alpha blending — hard-edged quads plus the MSAA sample count already in the pipeline key give clean edges. One pipeline, one draw.
  • Caps/joins: extend each quad by halfWidth along its own direction (square caps) to fill pinhole gaps at shared stations; at 1–2 px no miter/round joins are needed.
  • Depth: keep the existing z -= 1e-4 bias; give splays a slightly larger bias so the centerline wins z-fights at stations.
  • newVisibility becomes per-segment (one flag per instance) instead of the duplicated per-vertex mask — the cwSceneVisibility ranges now address segments, which simplifies the mask upload in updateVisibilityBuffer.
  • newA showSplays toggle (default on) implemented through that per-segment visibility — masking each trip's splay range — exposed as a checkbox in the View page's line-plot settings. Visibility must go through cwSceneVisibility so picking agrees with rendering.
