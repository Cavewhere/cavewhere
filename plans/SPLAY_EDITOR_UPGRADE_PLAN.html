Splay editor upgrade — commit plan

Eight commits taking the survey table's splay display (phase 5 of plans/SPLAY_SHOTS_PLAN.html) to a full editor: a real Splays column, delete, move, in-place editing, and manual entry. Groundwork for digital survey on mobile, where splays arrive over Bluetooth from a DistoX/BRIC and the common failures are splays on the wrong station, bad shots to delete, and a dead connection forcing manual entry. Each commit builds, passes its tests, and is exercisable in the app on its own.

Approved look and feel: plans/SPLAY_ROW_DATABOX_PROTOTYPES.html (variant C — DataBox cells + accent rail) and the interactive plans/SPLAY_EDIT_INTERACTIONS_PROTOTYPE.html (chip-in-cell, menus, pick-a-target move, RemoveAskBox on delete-all, tab flow).

Decisions already made. Multi-select is deferred — operations are per-splay or whole-cluster. Off-by-one "move to prev/next" items are dropped — "Move to…" pick-a-target is the single move path. "Delete all N splays" goes through RemoveAskBox; single "Remove splay" is immediate. Undo integration is deferred — the challenge guards the only bulk-destructive action. Moves stay within the current trip (any chunk); cross-trip moves, swipe-to-delete, and live Bluetooth capture are later work.

Commit 1 Splays column becomes a real cell

Restyle from the floating chip to variant C, and give splays a home in the editor's focus model. This is the visual foundation the later commits hang menus and editing off of.

  • cwSurveyChunk::DataRole gains StationSplaysRole (appended; it is a UI navigation role, so no proto changes). cwSurveyChunk::isStationRole treats it as a station role.
  • cwSurveyEditorModel::nextCellIndex: Tab/arrow chain on station rows extends D → Splays cell → onward to the shot/next station exactly as D flows today. The cell is focusable on every station row, with or without splays.
  • SurveyEditorColumnTitles.qml: real column geometry — splaysX/splaysWidth — replacing the ad-hoc chip position, plus the header label (already present) moving onto the shared geometry.
  • New SplaysBox.qml: a lightweight cell (station-gradient background, 1 px Theme.borderSubtle border, focus ring wired to focusedRow/focusedRole like DataBox, but with no editor, error model, or remove preview). Contains the chip (count + triangle) when stationSplayCount > 0, empty otherwise. Click or Enter/Space toggles expansion via the existing toggleSplaysExpanded.
  • Splay row restyle in DrySurveyComponent.qml: the full-width tinted band becomes three bordered Theme.splaySurface cells under Distance/Compass/Clino (28 px, sharing the grid's 1 px borders), the 2 px Theme.splayBorder rail down the station column edge, and the A2 · s3 tag. Still read-only.
Tests. C++: nextCell cases for the extended chain (D → Splays → next row; skipped roles stay skipped) in test_cwSurveyEditorModelSplays.cpp. QML: tst_SplayRows.qml updated for the new cell (chip found inside SplaysBox, keyboard toggle). By hand: import a Survex file with splays, tab across a station row into the Splays cell, expand with Enter, check the variant-C look in light and dark.
Landed as dd3b288e. Review of the commit surfaced two refactors that must precede editable splay cells, inserted below as commits 2 and 3: SplaysBox copies DataBox's focus protocol and chrome wholesale (and misses DataBox's re-sync on view.onCurrentIndexChanged), and StationSplaysRole living in cwSurveyChunk::DataRole is a seam — the editor's cell vocabulary borrowing the chunk's data vocabulary, which the splay reading cells cannot fit at all.

Commit 2 Shared SurveyEditorCell base (QML refactor)

  • New SurveyEditorCell.qml: model, view, listViewIndex, dataRole, indexInChunk, calibration (→ frontSights/backSights), the focus protocol (shouldHaveFocus/syncFocusState/takeFocus/ moveFocus, tab handling, model Connections, sync hooks), and the chrome layers (station gradient, 1 px border, focus highlight).   • Absorbed fix: SplaysBox gains DataBox's re-sync on view.onCurrentIndexChanged (the ListView steals focus onto the row delegate; without the re-sync a focused Splays cell goes keyboard-dead when the current index moves).
  • Also here: split the station-rename branch out of the model's shared chunkDataChange lambda so errorsChanged on a station name stops redundantly re-emitting SplayStationNameRole for the rows under it.
Tests. Existing suites are the gate — tst_SplayRows, tst_SurveyDataEntry, tst_MarkStationFixed — plus an offscreen screenshot compare against the commit-1 render (pixel-identical expected). By hand: focus a Splays cell, scroll the table, confirm the keyboard toggle still works.

Commit 3 Editor-level CellRole (C++ refactor)

Give the editor its own cell vocabulary instead of borrowing the chunk's data vocabulary. The forcing function is commit 7: a splay reading cell can never be a cwSurveyChunk::DataRole because chunk->data(role, index) has no splay index.

  • cwSurveyEditorCellIndex gains enum CellRole (Q_ENUM, QML-exposed): reading enumerators mirroring the chunk roles at identical numeric values — so the ~100 existing cellIndex(...) call sites and QML int coercions keep working — plus editor-only cells, starting with StationSplaysCell.
  • Write boundary: toChunkRole(CellRole) returning an optional, used in setDataAt — editor-only cells answer empty, replacing the isReadingCell guard.
  • Retire StationSplaysRole from cwSurveyChunk::DataRole (with its checkForError case), and delete the wrong-if-ever-reached toModelRole(StationSplaysRole) → StationSplayCountRole mapping.
Tests. Existing [cwSurveyEditorModel] and [SplayShot] suites, with the splay-cell cases retargeted at CellRole. By hand: tab across a station row into the Splays cell and back — unchanged behavior is the proof.

Commit 4 Chunk mutation API (no UI) — done

All splay mutations in one C++-only commit, so every UI commit after this is thin wiring.

  • cwSurveyChunk: appendStationSplay(int stationIndex, const cwShotMeasurement&), removeStationSplay(int stationIndex, int splayIndex), clearStationSplays(int stationIndex), and setStationSplayData(DataRole, int stationIndex, int splayIndex, const QVariant&) for the three reading fields. Each emits stationSplaysChanged(stationIndex), which the phase-5 model reconciliation already turns into exact row inserts/removes.
  • Move as a static helper cwSurveyChunk::moveStationSplays(cwSurveyChunk* from, int fromStation, cwSurveyChunk* to, int toStation, const QList<int>& splayIndices) — remove from the source (descending), append to the target, one stationSplaysChanged per side. Cross-chunk works because both sides just re-emit; same-station moves are a no-op.
  • Dirty-project marking rides the existing chunk-change plumbing — verify a mutation marks the project modified.
Tests. [cwSurveyChunk] cases for each op (bounds, signals, empty results) and [cwSurveyEditorModel] reconciliation cases: remove-one, clear-while-expanded (cluster collapses), move between stations with both clusters open, move across chunks. By hand: nothing visible yet — this commit is proven by its tests.

Commit 5 Delete UI — done

Commit 6 Move UI — pick-a-target — done

  • Menu items: "Move to…" (row menu) and "Move all to…" (cluster menu) arm a pending move.
  • Pending-move state lives on cwSurveyEditorModel: startSplayMove(rowIndex, allSplays), cancelSplayMove(), commitSplayMove(targetRowIndex), and a splayMoveActive property. Putting it in the model keeps delegates stateless across ListView recycling — the same reason expansion state lives there.
  • QML: while active, StationBox shows a target outline (Theme.splayBorder) and the source station dims; clicking a station box commits instead of focusing; a banner above the table names the move ("Click a station to move 6 splays from A2 — Esc cancels"); Esc and clicking anything other than a station cancels. The target's cluster expands so the landing is visible.
  • Targets are any station in the trip, across chunks. The source station is excluded.
Tests. C++: startSplayMove/commitSplayMove across chunks, cancel restores nothing-pending. QML: full pick flow — arm, click target, tryVerify rows appear under the target; Esc cancels. By hand: the headline scenario — a cluster downloaded to the wrong station moved to its neighbor in three taps (⋯ → Move all to… → tap station).

Commit 7 Editable splay cells — done

The biggest commit: splay readings join the editing model, which is what makes correcting a mistyped DistoX value or finishing a partial manual entry possible.

  • cwSurveyEditorCellIndex::CellRole (from commit 3) gains SplayDistanceCell, SplayCompassCell, SplayClinoCell — editor-only cells; the chunk enum stays untouched. The model serves cwSurveyEditorBoxData for splay cells (reading populated from cwShotMeasurement; empty error model for now), so the QML can reuse the DataBox machinery: GlobalShadowTextInput editing, validators, focus sync, typing-starts-editing.
  • setDataAt routes splay cells to setStationSplayData from commit 4. The cell index stays (modelRow, CellRole) — the model row already pins chunk, station, and splay index through cwSurveyEditorRowIndex.
  • New SplayDataBox.qml layers on the SurveyEditorCell base from commit 2 — the editing machinery plus a splay-surface background, with no remove-preview or error UI. Validators: the existing distance/compass/clino validators.
  • nextCellIndex: Tab flows distance → compass → clino → next splay row; arrows move within the cluster and out of it vertically. Splays are single-reading, so front/back-sight branching stays off this path.
Tests. C++: setDataAt for each splay role (value lands in the chunk, dataChanged emitted), nextCell chains within and out of a cluster, validator rejection leaves the reading untouched. QML: click a reading, type a new value, Tab, tryCompare the committed text; arrow navigation across rows. By hand: correct a reading and watch the splay swing in the 3D plot.

Commit 8 Add splays — blank entry row and empty-cell entry — done

  • Blank entry row: every expanded cluster shows one trailing virtual splay row (dashed styling, IsVirtualRole true, splayIndex == count — the same virtual-row idiom as the chunk's trailing empty station). Committing a value in any of its cells calls appendStationSplay; reconciliation turns the virtual row into data and grows a fresh blank underneath, so focus keeps flowing during rapid entry.
  • Tab exits through an empty blank row: from the blank row's clino cell with the row still empty, Tab lands on the next station's StationNameRole — the cluster is a pass-through in nextCellIndex, matching how the table tabs today.
  • Empty-cell entry point: clicking (or pressing Enter on) a Splays cell with zero splays expands the station to just the blank row and focuses its distance cell — manual entry when the Bluetooth link dies is: tab to Splays, Enter, type. The chip appears when the first splay commits. The cell shows a subtle "+" hover hint.
Tests. C++: virtual row lifecycle (present when expanded, converts on commit, exactly one blank), tab-through-empty reaching the next station name, entry on a zero-splay station. QML: end-to-end manual entry — empty cell, Enter, type three readings with Tab, tryVerify the new data row plus fresh blank; tab through empty and tryCompare focus on the next station's box. By hand: enter a full station of splays without touching the mouse.

Watch-outs across all commits

  • ObjectFinder chains: new items may take objectNames, but existing intermediate items stay unnamed (tst_MarkStationFixed and tst_SplayRows share SurveyTableTestHelper.qml).
  • Delegate recycling: any new state (pending move, expansion, focus) lives in the model, never in delegates.
  • Splay construction in QML tests goes through TestHelper.addStationSplay (cwShotMeasurement is a value struct outside QML).
  • Shot-box shift: commit 8's always-present blank row changes an open cluster's height; shotBoxShift and clusterHeight math stay driven by the model's row count, never by a parallel formula in QML.
  • Chip loader: keep the count-gated Loader economy from phase 5 — most stations have zero splays and should keep instantiating nothing beyond the bare cell.
  • Run [SplayShot], [cwSurveyChunk], [cwSurveyEditorModel] plus tst_SplayRows, tst_SurveyDataEntry, tst_MarkStationFixed before each push.

Commit 16 Entry cues on every real station — done

Bug found by hand after commit 15 (follow-up 11, 2026-08-12): the "+" button and the "Press Enter to add" hint only appear on stations 0 and 1 of a chunk — station 2 and higher never show either cue, and Enter does nothing for them.

  • Failing test first — prove the bug before touching production code. QML: build a chunk, type through the virtual rows to create a third station, keyboard-focus (and hover) its zero-splay Splays cell, and assert the hint and "+" appear — this must fail against the current code. Add the C++ half at the model layer: when typing a name turns the virtual trailing station real, the model must emit dataChanged covering IsVirtualRole for that row (assert via the fixture's signal tally).
  • Prime suspect: stations 0 and 1 exist from chunk birth; every later station begins life as the virtual trailing row. IsVirtualRole (cwSurveyEditorModel.cpp:407) computes the right answer on a fresh read, but if no dataChanged announces the virtual→real transition, the delegate's required property bool isVirtual keeps its stale true and offersEntry (which requires !isVirtual) never turns on. Fix at the model's emission site, not by re-deriving state in QML.
  • Audit the same transition for the other isVirtual consumers (DrySurveyComponent's blankRow, shot rows) — a missing emission there has the same stale-delegate shape.
Tests. The two failing-first tests above, then green. Keep commit 15's cue tests passing unchanged. By hand: enter a fresh trip, add stations until the chunk has four, and check every real zero-splay station shows both cues.
