1. Goal and scope

Goal: the survey model becomes a tree — cwCavingRegion owns a root node, every inner node is one class (cwSurveyNode) with a kind, and every leaf is a cwTrip. A native project reads exactly as today (Region → Cave → Trip); a user can add Folders and Sections; an attached Compass .mak, Walls .wpj, or Survex master appears as one sourced root row whose subtree mirrors the file's own structure; native trips can be added under any node, sourced ones included. The Data page is a tree table. Solve state is one region-wide lookup with per-node views. Names are unique per sibling set.

Ships in this plan

  • cwSurveyNode with kinds Cave, Folder, CompassProject, CompassFile, WallsBook, SurvexFile, SurvexBlock; cwCave retired through a shim (W1 → W8).
  • Nested directory persistence (sub/ beside trips/), proto fields, loaded-path index by node path, node Move as a save op, sync handlers at depth N, conditional file-version bump (W3).
  • Driver: one *begin per native node, one *include per sourced root, one global equate list emitted fully qualified at region scope; line plot assigns stations by walking the label path (W4).
  • Tree Data page (W2), Folders/Sections and node pages with variable-depth links (W5).
  • Solve-state relocation: one region lookup + scoped views, region-wide connectivity (W6).
  • Sourced subtrees: scanner node tree + units.json station sets, attach under any node, reconcile by source_path, exclusions (hide/Restore), Reload/Replace on the root, delete cascades, dialog tree preview (W7).
  • Importers build the same node tree as attach; shim deletion; docs (W8).

Non-goals (deferred)

  • A persisted order field or drag-to-reorder (settled: order stays derived).
  • Renaming a sourced (derived) node; converting a sourced subtree to native.
  • Compass export of a mixed node; the export gate stays closed for any external owner (src/cwSurveyExportManager.cpp:355-380).
  • Struck-through hidden rows in the tree (prototype open question 1; v1 is the root page's "N hidden · Restore…" line, §13).
  • Bulk note-folder import; the LFS policy patterns beyond confirming they match at any depth (§6.9).

3. Settled decisions (binding; do not reopen)

  1. Node tree. Region → node … → cwTrip leaves. One node class with a kind; cwCave retires into it gradually (empty subclass shim during migration, deleted at the end). Native and sourced nodes are the same class; sourced nodes carry read_only + source_id + source_path. Native mode still looks like Region → Cave → Trip.
  2. Native labels: exactly two, "Cave" and "Folder". Label comes from position: Add Cave / Add Folder / Attach at the top level and inside a Folder; inside a Cave (or a Section, or a sourced node) the verbs are Add Trip / Add Section (creates a Folder) / Attach. A Cave is never offered inside a Cave. Relabel via the kind chip (Cave/Folder), which changes label and icon only. The backend never branches on the label; behavior keys off isReadOnly/isSourced and structural facts.
  3. Data page is a tree table: Name, Kind, Trips, Length, Depth, Last survey, ⋯. Kind column always shown. Trip rows are in the tree. Everything starts collapsed except sourced roots, which are expanded one level on every load. Filter box auto-expands to matches; expand/collapse all; breadcrumb; keyboard (arrows, Enter, Space, Home/End, Shift+F10 context menu).
  4. A source root is a row, never transparent. Kind chips: Compass project, Compass file, Walls book, Survex file, Survex block. The region's direct children may be any kind. Non-survey Walls books (SVG Sources, Fixed Points) appear gray.
  5. One "Add ▾" split button everywhere with "Attach survey file…" inside it; Attach places under the node it was opened on (region root from the Data page); the dialog shows the scanned tree preview.
  6. No Detach verb, no Delete buttons. Deletion is right-click context menu only (Open / Rename (native) / Delete…). Deleting a sourced root removes the whole subtree including native trips under it (confirm with counts; the copied file is removed). Deleting a derived sub-node or derived trip hides it; the exclusion is persisted per source, survives Reload, and the root's page shows "N hidden" with Restore….
  7. Reload / Replace live on the sourced root (row ⋯ menu + source card on its page).
  8. Solve state = one region-wide station lookup / network with per-node scoped views; per-cave copies retired. Unconnected-chunk wording: "This chunk isn't connected to any survey."
  9. Names unique per sibling set only; region-wide uniqueness goes away; cavern needs only sibling-unique labels (cwCavernNaming::scopeLabels is already per sibling set).
  10. No order field; order stays derived (alphabetical for native nodes; scan order inside a sourced subtree).
  11. Old builds: the existing file-version gate (saveWillCauseDataLoss/canSaveDirectly) is the forward-compat mechanism; bump the proto version when the first nested node is written.
  12. Persistence: nested directories mirroring the tree; child nodes under <nodeDir>/sub/<name>/ beside trips/; keep the Cave message and .cwcave extension; optional fields kind, read_only, source_id, source_path (absent = today); Project gains repeated ExternalSource with per-source exclusions; derived nodes/trips are ordinary records reconciled against the scan by source_path on reload; a native trip under a derived node has no source_path and reconcile never touches it. Node move is a first-class save op that keeps the same QObject*.
  13. Equates: one global list on the region (operands are handles: container uuid + tail), emitted at region scope fully qualified; LCA placement is optional tidiness, never a rule. Cave-held equates migrate into the global list on load.
  14. Importers (Walls/Survex/Compass import) build the same node tree as attach.
  15. Mixed nodes: native trips (incl. a future digital-survey trip) may be added under any node incl. sourced ones. Trip-level attachment stays as it is. Unit trips inside a sourced subtree use station-set membership windows from units.json (Compass survey names and Walls books get no cavern naming level; Survex blocks and Compass .dat files do, so prefix windows and membership compose). Equate operands into a sourced subtree use cavern-relative names from the manifest.

6.2 Load algorithm (C3.1, replaces the append loop at cwSaveLoad.cpp:2766-2830)

  1. Scan *.cwcave recursively as today (:2751-2760), but prune trips/, notes/, and external-centerline/ subtrees from the node scan (a copied Compass project has hundreds of files; today's scan enters them all).
  2. Sort by absolute path (:2765). A parent's directory is a prefix of its children's, so parents come first.
  3. Keep QHash<QString dirPath, cwCaveData*> nodeByDir. For each descriptor at directory D: walk D's parents upward until a directory in nodeByDir (→ that node's nodes list) or the data root (→ region.caves). Any other placement (a descriptor directly under trips/, or two descriptors in one directory) is a load error naming the path; the descriptor is skipped, never guessed.
  4. Per node, the trip scan is unchanged (:2807-2824, <nodeDir>/trips, recursive — it never enters sub/ because that is a sibling directory).
  5. Orphan trip directories (a .cwtrip whose nearest descriptor ancestor is not its trips/ parent — the add/move race in §6.10) attach to that nearest node and are reported in the load report.
  6. The resulting cwCaveData tree is set on live nodes by cwSurveyNode::setData recursively (children before signals, as cwCave::setData does for trips).

Existing projects: every descriptor sits at depth one, kind is absent, no sub/ exists → Region → Cave → Trip with zero visible change and no rewrite.

10.0 Ordering rationale
